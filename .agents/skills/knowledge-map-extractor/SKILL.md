# Knowledge Map Extractor

IRON LAW: 大模型只做语义理解与关系判断；编号、组装、环检测、校验和 HTML 渲染必须交给脚本。

红旗信号（出现任一项，退回对应步骤）：
- 一次性让模型生成最终 JSON 或 HTML
- 节点摘要复制案例、修辞或大段原文
- 为了得到 DAG 而删除真实反馈回路
- 静态树和动态流程并列展示，却没有关系映射

## 参数

| 参数 | 作用 | 默认 |
|---|---|---|
| 输入 | URL、Markdown 路径或正文 | 必填 |
| `--model-only` | 只输出规范 JSON，不渲染 HTML | false |
| `--no-confirm` | Skill 对话层跳过结构预览确认；不是脚本参数 | false |
| `--output DIR` | 输出目录 | 当前目录下的 `knowledge-map/` |

## 工作流

复制并逐项完成：

```text
Knowledge Map Progress:
- [ ] 1. 获取并通读全文 ⛔ BLOCKING
- [ ] 2. 提炼主旨与文章倾向 ⚠️ REQUIRED
- [ ] 3. 抽取静态树和动态轨道 ⚠️ REQUIRED
- [ ] 4. 建立映射并识别反馈 ⚠️ REQUIRED
- [ ] 5. 预览结构并确认（除非 --no-confirm）
- [ ] 6. 写入语义草稿并运行组装脚本
- [ ] 7. 验证 JSON 与 HTML ⚠️ REQUIRED
```

## 1. 获取全文 ⛔ BLOCKING

- URL：使用当前环境合适的网页抓取 Skill；不要仅凭摘要或搜索片段萃取。
- 文件：读取完整正文；超长时分段读取，但在抽取前必须覆盖全文。
- 正文：直接使用用户输入。

先回答：文章的主要命题是什么？它偏静态知识、偏动态方法，还是二者兼有？

## 2. 提炼主旨

用 30–50 个中文字符概括总主旨。只保留作者要读者理解或执行的核心命题。

## 3. 抽取两条线

需要精确字段和约束时加载 `references/extraction-contract.md`。

### 静态线：知识树

问：文章有哪些概念即使脱离叙述顺序仍然成立？

- 仅一个 `root`，2–6 个 `branch`，必要时添加 `leaf`；最多三层。
- 每个摘要 30–50 字，删除背景、修辞、例子和个案数字。
- 父节点必须先出现，名称必须唯一。

### 动态线：方法轨道

问：文章要求读者按什么顺序行动？哪些步骤属于同一套完整方法？

- 每套独立方法是一条轨道；活动按执行顺序排列。
- 活动摘要写成“动作 + 目的 + 产出”，30–50 字。
- 没有显性方法时保留空轨道数组，不编造流程。

## 4. 缝合关系网

先为静态节点与动态活动生成少量可信候选对，再逐对判断：

1. **跨线映射**：该静态概念是否直接支撑或约束该活动？方向固定为静态 → 动态，说明不超过 15 字。
2. **反馈回路**：该活动的产出是否会更新某个静态概念？方向固定为动态 → 静态，说明不超过 15 字。

宁缺毋滥。关系必须能用原文语义解释，不能因为节点“看起来相关”就连线。

## 5. 确认结构

除非 Skill 调用参数包含 `--no-confirm`，先展示：主旨、静态分支、轨道名称、映射数、反馈数。询问用户是否继续生成文件。用户确认后再写产物。不要把 `--no-confirm` 传给 `build_map.py`。

## 6. 组装与渲染

按 `references/extraction-contract.md` 写入语义草稿 `draft.json`，不要手工分配 ID。

```bash
python3 scripts/build_map.py draft.json --output knowledge-map
```

脚本会：分配稳定 ID、校验父子关系、构图并检测环、写入 `model.json`，再把模型注入 `assets/map-template.html` 生成 `index.html`。

若使用 `--model-only`：

```bash
python3 scripts/build_map.py draft.json --output knowledge-map --model-only
```

## 7. 交付前检查

- [ ] 全文已覆盖，不是基于摘要猜测
- [ ] 一个 root、2–6 个 branch、树深不超过三层
- [ ] 所有摘要 30–50 字；关系说明不超过 15 字
- [ ] 动态摘要都包含动作、目的和产出
- [ ] 每条映射都是静态 → 动态，每条反馈都是动态 → 静态
- [ ] 真实反馈没有为了“严格 DAG”被删除
- [ ] `build_map.py` 退出码为 0，且没有未替换的模板占位内容
- [ ] `model.json` 可解析；非 `--model-only` 时 `index.html` 可在浏览器打开

## 禁止做法

- 不要把普通摘要、思维导图或单张流程图冒充知识地图。
- 不要把一套方法的步骤拆成多条伪轨道。
- 不要用模型猜 ID、父子引用、环路结论或 HTML 转义。
- 不要过度连线；没有明确支撑或回流语义就不连。
- 不要因原文没有流程而虚构动态活动。
