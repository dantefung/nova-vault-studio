产品的类型与方向

产品方法论只有一套，但套在不同类型的产品上，结论经常是相反的。分不清类型，学再多方法也会用错地方。

读完你能回答

  • 为什么 C 端讲的「减少一步」，到了 B 端反而要加一步

  • 平台、工具、内容这三种形态，各自最难的地方在哪

  • 你自己想做的东西属于哪一类，该照哪套标准判断

最常见的误用是把 C 端的经验直接搬到 B 端。C 端的用户可以随时走人，所以每多一步都是流失；B 端的用户走不了，但他的每一步操作背后有一条真实的业务流程和一份责任，少一步反而出事。

C 端和 B 端

差别不在界面，在「谁决定用不用」和「用错了谁承担」。

看的是 C 端 B 端

谁做决定用的人自己，一秒钟决定老板买、员工用，两拨人 能不能走随时能走，所以每一步都算流失走不了，所以怕的是出错不是麻烦 判断依据数据。留存、转化、时长流程。跑不跑得通，对不对得上账 功能怎么加能砍就砍，简单是竞争力该有的必须有，缺一个环节就没法交付 最难的地方让人第一次愿意打开把一个组织的现实流程搞清楚 出错的代价用户下次不来了财务对不上账，有人要担责

还有一类 G 端，服务对象是政府，形态接近 B 端，但可靠性和安全性的权重更高，定制内容也更多。

同一个功能，两边的做法能差出一个「确认」按钮。

四种形态

除了服务对象，还有一层是产品的形态。它决定了你的增长从哪来，也决定了最难啃的是哪一块。

形态怎么赚钱最难的地方例子

工具 订阅、买断、增值功能 做完一件事就走，很难留住人 剪辑软件、笔记、设计工具

内容 广告、会员、带货 内容供给要持续，断一天就掉 视频、播客、资讯

平台 抽佣、流量分发 两边都要有人，先有鸡还是先有蛋 电商、外卖、招聘

社区 广告、电商、会员 氛围一旦垮掉基本救不回来 论坛、兴趣社区

工具产品用完即走，所以要么做成高频刚需，要么想办法沉淀数据把人留住；平台的冷启动几乎全是靠一边补贴另一边硬撑出来的。

你该做哪种

一个人用 AI 做产品，这四种形态的难度差距很大。

一个人能扛 需要一支团队和很多钱

工具 做出来就能用

内容 要持续生产

社区 要有人气才成立

平台 两边都要冷启动

独立开发者绝大多数落在工具这一档，原因不是野心小，是只有工具形态能靠「做出来」本身成立。平台和社区做出来只是开始，真正的成本在后面。

选方向的时候，把这三个问题连起来问一遍：服务的是个人还是组织、形态是工具内容平台还是社区、以及你能不能一个人撑到有第一批用户。三个答案自洽，方向就基本对了。
