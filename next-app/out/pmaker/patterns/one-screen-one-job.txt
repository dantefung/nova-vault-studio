<h1>一屏一件事</h1>
<p>功能都做出来了，用起来却很累。因为页面上每样东西都一样重，用户每进一个页面都要先做一道选择题。</p>
<p>你会遇到的现象</p>
<ul>
<li>
<p>让 AI 做工作台，它把你提到的五个功能做成五张一模一样的卡片</p>
</li>
<li>
<p>自己看着还行，别人打开第一句话是「我该点哪个」</p>
</li>
<li>
<p>想突出某个功能，只能靠加粗、加框、加底色，越加越乱</p>
</li>
</ul>
<p>一个页面应该有一个明确的主任务。用户走到这里是来干这件事的，页面上的其他东西全都为它让位：尺寸更小、位置更靠后、或者干脆收进导航里。</p>
<p>让 AI 生成页面时，它倾向于把你提到的所有功能平铺展开，因为它没有理由认为哪个比哪个重要。你说&quot;做一个工作台，要有项目列表、数据看板、团队管理、消息、设置&quot;，它就给你五块等大的卡片。每一块都存在，每一块都不突出，用户进来要先做一道选择题。</p>
<p>这就是功能都在、用起来却很累的来源。<strong>功能齐全和主次分明是两回事，前者 AI 帮你做到了，后者只能你来定。</strong></p>
<p>判断一个页面是否合格，问一句：如果用户在这个页面上只能点一个东西，应该是哪个？如果答不上来，说明这个页面还没设计完。</p>
<h3>怎么找出那一件事</h3>
<ul>
<li>
<p>看用户是从哪来的。从搜索结果进来的详情页，主任务是确认这是不是他要找的；从推送进来的，主任务是看那条更新。</p>
</li>
<li>
<p>看统计。如果已经上线，八成的点击集中在一两个位置，那就是主任务，页面应该照着它重排。</p>
</li>
<li>
<p>看频率。每天做的事放最外面，每月做一次的收进设置，一次性的（比如初始化配置）做完就该消失。</p>
</li>
</ul>
<h2>低频功能放哪</h2>
<p>从首屏赶走的东西不会消失，它们要落到导航里。导航形式基本就四种，选哪种取决于系统有多少个一级模块。</p>
<p>仅左侧一级
功能单一的系统
文档、笔记类</p>
<p>仅顶部一级
内容型站点
官网、电商</p>
<p>左一级 顶二级
模块多的后台
管理系统</p>
<p>顶一级 左二级
多个系统并列
门户 + 子系统</p>
<p>一级菜单项控制在五到九个之间，这是短期记忆一次能处理的量。超过九个就该分组，同时导航别藏超过两级，第三级往下用户基本走不到。</p>
<h2>设计考量</h2>
<ul>
<li></li>
</ul>
<p><strong>主任务只配一个主按钮，同屏不出现第二个同等份量的按钮。</strong>
两个一样醒目的按钮等于没有主按钮。次要操作降级成文字链接或幽灵按钮，视觉重量拉开三倍以上，用户的眼睛才会自动落到该落的地方。</p>
<ul>
<li></li>
</ul>
<p><strong>低频功能收进导航，不占首屏面积。</strong>
账单、成员管理、集成配置这类一个月碰一次的东西，放进顶部菜单或设置页即可。它们出现在首屏的唯一效果是稀释主任务。</p>
<ul>
<li></li>
</ul>
<p><strong>宁可多一个页面，不要一页塞两件事。</strong>
页面是廉价的，注意力是昂贵的。两个任务硬塞进一屏，用户每次都要先分辨自己在哪一半；拆成两个页面加一个清晰的入口，反而更快。</p>
<ul>
<li></li>
</ul>
<p><strong>用位置和尺寸做层级，别用边框和底色。</strong>
给次要模块加个灰底想让它退后，通常效果相反——多一块颜色就是多一个视觉重心。真正让它退后的方式是缩小、下移、去掉图标。</p>
<ul>
<li></li>
</ul>
<p><strong>首屏不滚动的区域，留给主任务和它的上下文。</strong>
用户不滚动就能看到的那部分是最贵的地方。它应该回答用户在哪、能干什么，而不是塞公告栏和推广位。</p>
<ul>
<li></li>
</ul>
<p><strong>同一个页面在不同角色下主任务可能不同。</strong>
管理员进来是审批，成员进来是提交。与其做一个兼容两者的折中页面，不如按角色渲染不同的主区域，导航保持一致。</p>
<h2>给 AI 的话</h2>
<p>AI 不会自己判断主次，你得把主次写进需求。这段模板适用于任何一个新页面。</p>
<p>复制
PROMPT · 页面需求
页面：[页面名]
用户从哪来：[入口，比如&quot;从侧边栏点进来&quot; / &quot;从邮件通知点进来&quot;]</p>
<p>主任务（这个页面只服务这一件事）：
[一句话，比如&quot;快速回到最近在做的项目&quot;]</p>
<p>页面上还需要出现，但都属于次要的：</p>
<ul>
<li>[次要项 1]</li>
<li>[次要项 2]</li>
</ul>
<p>低频功能，收进顶部导航或设置页，不要出现在首屏：</p>
<ul>
<li>[低频项...]</li>
</ul>
<p>布局约束：</p>
<ul>
<li>整页只有一个主按钮，对应主任务。次要操作用文字链接或
幽灵按钮，视觉重量必须明显低于主按钮。</li>
<li>不滚动就能看到的区域，只放主任务和它必要的上下文。</li>
<li>次要模块靠缩小字号、下移位置来降级，不要用灰底或加边框。</li>
</ul>
<p>先用一段文字描述你打算的布局顺序和每块的视觉权重，
我确认之后你再写代码。</p>
<p>如果 AI 给回来的布局描述里出现了三个以上&quot;重要的&quot;模块，说明主任务还没定清楚，回到需求那一步改，别在代码上调。</p>
<h2>相关模式</h2>
<p>入口密度
一屏一件事管的是单个页面内部的主次，入口密度管的是首页该放几个入口。当用户来意确实有好几种时，正确解法是把首页做成分流页，而不是硬选一个主任务。</p>
<p>层级对比
定下主次之后，靠层级对比来落实。大小和位置的差距不够大，主次就只存在于你的文档里，不存在于用户眼里。</p>
<p>唯一主线
这是同一条判断在两个尺度上的应用：唯一主线定的是整个产品的主任务，一屏一件事定的是单个页面的。产品主线不清楚，每个页面都会摇摆。</p>
<p>五秒测试
验证这个模式最快的方式。给陌生人看五秒，问他这页最想让你干什么，答不出来就是没做到。</p>
<h2>真实案例</h2>
<p>Google</p>
<p>Google 首页是这个模式最极端的版本：整页只有一个输入框。其余几十个产品全部收进右上角一个九宫格图标里。</p>
<p>收件箱 · 12</p>
<p>写邮件</p>
<p>Gmail 的主任务是&quot;处理收件箱&quot;，所以整个中区都是邮件列表，唯一的主按钮是写邮件。标签、过滤器、设置全部在侧边和角落。</p>
