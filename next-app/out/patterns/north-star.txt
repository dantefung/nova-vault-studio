12:T15ee,<h1>一个北极星 | 验证与迭代 | 做产品</h1>
<h1>一个北极星</h1>
<p>选一个指标代表产品在变好，其余都是参考。指标越多，越容易在每一份周报里找到一个正在上涨的数，然后说服自己一切顺利。</p>
<p>你会遇到的现象</p>
<ul>
<li>
<p>周报上十个指标有涨有跌，看完还是不知道这个月到底做得怎么样</p>
</li>
<li>
<p>两个方案争不出高下，因为一个能提日活，另一个能提留存，谁也说不服谁</p>
</li>
<li>
<p>指标涨了，但没人说得清是产品变好了，还是刚好做了一轮投放</p>
</li>
<li>
<p>年底复盘，大家各自挑对自己有利的那个数来讲</p>
</li>
</ul>
<h2>四个条件</h2>
<p>一个数能当北极星，要同时满足四条。少一条都会在某个时刻把团队带偏。</p>
<ul>
<li>
<p>**它代表用户真的拿到了价值。**不是「来了」，是「拿到了」。注册、访问、点开都只是路过；完成一次真实任务才算数。</p>
</li>
<li>
<p>**你这个季度改得动它。**做一件事，两周内能在这个数上看到变化。改不动的数只能当背景，不能当方向盘。</p>
</li>
<li>
<p>**它领先于收入，而不是跟随收入。**收入是结果，反应慢，还会被促销和季节盖住。北极星要能提前告诉你收入将来会怎么走。</p>
</li>
<li>
<p>**它刷不出来，而且全员看得懂。**一句话能讲清、任何人都无法靠拆页面或改口径把它做上去。看不懂的指标没人会拿它做日常决策。</p>
</li>
</ul>
<p>看起来很像北极星问题出在哪换成这个</p>
<p>注册用户数
注册完再没回来的人也计入，投放一开就涨
完成首个核心任务的人数</p>
<p>页面浏览量
把一页拆成三页就能翻倍，跟价值无关
有效使用时长或完成率</p>
<p>日活
推送能短期拉起来，掩盖真实流失
每周使用 3 天以上的用户数</p>
<p>GMV
大促和补贴的影响远大于产品改动
复购用户数 / 下单转化率</p>
<p>右边那一列的共同点：都带着「人」，而且这个人做完了一件对他有用的事。凡是能靠改口径做上去的数，都不适合当北极星。</p>
<h2>不同产品怎么选</h2>
<p>产品类型常见的北极星它在赌什么
内容社区每周产生有效互动的用户数互动带来关系，关系带来留存
工具类每周完成 N 次核心动作的用户数形成习惯的人不会走
电商复购用户数买第二次的人才是真用户
B 端 SaaS周活跃席位数真在用的人多，续约就稳
早期产品第二周还回来的人数先验证有没有人真的需要</p>
<p>「它在赌什么」这一列很重要。北极星本质上是一个假设：只要这个数涨了，生意就会好。假设有可能是错的，所以每年该重新审一次。</p>

<p>北极星只有一个，但不能只看它。得配两三个<strong>护栏指标</strong>：它们不用涨，只要不塌。<strong>北极星涨了、护栏塌了，这一轮不算赢。</strong></p>

<h2>一个人做产品</h2>
<p>一个人或者很小的团队，北极星要更狠一点：<strong>选一个你每天早上打开就能看一眼、看完知道今天该干什么的数。</strong></p>
<ul>
<li>
<p>**刚上线的阶段，选「这周第二次回来的人数」。**绝对值很小没关系，从 3 变成 8 也是信号。它能最快告诉你有没有人真的需要。</p>
</li>
<li>
<p>**不要选累计数。**累计注册、累计发布这类只会涨不会跌的数，看着舒服，但从来不会告诉你出问题了。</p>
</li>
<li>
<p>**写下来，贴在能看见的地方。**包括这个数今天是多少、你希望三个月后是多少。</p>
</li>
<li>
<p>**先埋点，再谈北极星。**没有数据来源的北极星只是一句口号，参见先埋点后上线。</p>
</li>
</ul>

<p>先埋点后上线
北极星要能被算出来。埋点方案跟着功能一起上线。</p>
<p>连到生意上
北极星和收入之间的那条链路，要能讲清楚。</p>
