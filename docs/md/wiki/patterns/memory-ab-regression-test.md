# 记忆有效性的三组对照实验

> 判断 Agent 记忆是否真的帮上忙，**不能靠"感觉它答得更好了"**，要靠固定问题 + 单一变量 + 观察工具调用。

## 实验设计

问题固定为一句：**"测试环境的夜间同步现在走哪个接口？"**

每次都另开会话，**前两次保持模型、配置和可用工具一致，只改变是否提供记忆**。

| 尝试 | 给 Agent 什么 | 主要观察什么 |
|------|--------------|-------------|
| 不带记忆 | 问题和相同的工具 | 能否找到正确任务，查了几次工具 |
| 带上记忆 | 再加索引和任务笔记 | 是否沿笔记找到配置，减少重复查找 |
| 修改配置后 | 保留旧笔记，把测试配置换个地址 | 是否重新查配置，回答新值并给出出处 |

## 观察顺序（关键）

**先对照实际配置检查答案和出处，再看工具调用中省掉了哪些重复查找。**

若还在报旧值，就顺着文件读取和配置查询记录定位原因。

先看答案对不对，再看省了多少调用——顺序反了会漏掉"答案错了但调用次数也少了"这种更糟的情况。

## 运行时埋点要求

要区分三种失败，运行时必须记录：

- 实际**读了哪个文件**
- 实际**查了哪个环境**

三种失败分别是：**没找到笔记**（路径/索引没命中）、**没读笔记**（读了但没用上）、**读完后用错了条件**（环境/版本对不上）。

## 回归化

三种情况走通后，把这道题留作**回归问题**，以后更新笔记或调整读取方式时再跑。

但回归题只保证"这一条没退化"，**是否持续省事，还得放到更多实际任务里观察**。
