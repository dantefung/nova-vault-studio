# 发布前合规预检

> 平台不会告诉你卡审的点是什么，只能自己反复推测。**解法是把审核规则显式写成带来源和核实日期的检查表，让 AI 代替你逐条比对。**

## 问题：黑盒审核 + 沉默失败

做自媒体的人都被「审核」困扰过——辛辛苦苦做的视频，最后却被卡审限流。

三个让这件事格外难受的特征：

| 特征 | 后果 |
|---|---|
| **平台不告诉你卡在哪** | 只能自己反复推测哪里出了问题，排查成本极高 |
| **沉默失败** | 没有报错、没有提示，只是流量突然消失 |
| **规则会变** | 同一份内容上个月过审，这个月被封 |

第三条最致命——**任何写死在代码里的规则集都会腐坏**。

## Pattern

```text
① 采集规则（带来源 + 核实日期）
        ↓
② 实战反馈回流（每次被卡审 → 补充检查项）
        ↓
③ 发布前预检（语音 + 字幕 + 画面一起检查）
        ↓
④ 输出可执行修改建议（原文 + 时间点 + 依据 + 改法）
        ↓
⑤ 确认后自动提交 PR（把真实案例回灌仓库）
        ↓ 回到 ②
```

关键在 **② → ⑤ 这个闭环**：每一次真实的卡审反馈都变成仓库里的一条 case，让下次审核更准。这不是「维护一份文档」，是**用社区反馈喂养规则集**。

## 三步搭起来

### 第一步：整理各平台公开的审核规定

- 把各平台公开的审核规定整理进去（小红书社区规范、抖音 / B 站 / 视频号的相关规定）
- **通用要求放在一起，平台差异分别保留**
- **记录来源和核实日期**，让判断有据可查

「记录核实日期」这一步是整个模式能抗住规则变化的前提——判断规则过期了，人能看出来。

### 第二步：根据实践经验不断迭代

每次发布遇到问题就把案例发给项目，这些经验会补充检查项、调整判断依据。

作者自己总结出的平台差异实例：

- 小红书和抖音**会卡一切疑似 URL 的地址**，但 B 站不会
- 小红书**会卡字节系的品牌 logo**

这类知识平台官方不会写明，只有大量实战才能积累出来。

### 第三步：一起提 PR

平台规则会变——作者举例：Codex 和 Claude Code 之前还是全网推，最近 2 个月 Codex 的安装教程就会被封杀。

**反馈回流机制**：

```text
被卡审 → 回到使用 skill 的对话里 → 把平台实际反馈发给助手
     → 「这是上次视频的实际平台反馈，请整理成案例，
        确认后提交到 guoshen 的 case 部分」
     → 助手整理记录 → 用户确认内容并授权公开 → 自动提交 PR
```

这个流程需要可用的 GitHub 登录与提交环境。复核合并后，案例就能帮助下一次审核。

## 用法

把 Skill 安装到 Codex / Claude Code，把**视频文案和成片一起**丢进对话，告诉它准备发到哪个平台：

> 用 /guoshen 检查这条视频在小红书、抖音、B 站、视频号的发布风险，标出原文、时间点、依据和改法。

它会**一起检查语音、字幕和画面**，给出修改建议表——每一行包含：风险点、原文位置（时间点）、判断依据、具体改法。

**关键点**：三个模态一起查。只查文案会漏掉画面里的 logo 和字幕里的外链，只查画面会漏掉口播里念出来的 URL。

## Failure Modes

| 失败模式 | 后果 | 对策 |
|---|---|---|
| **只查文案不查画面/语音** | 漏掉画面里的品牌 logo、字幕里的外链 | 三个模态一起送进去 |
| **规则集不记核实日期** | 规则变了却不知道哪条过期 | 每条规则带来源 + 日期 |
| **把平台差异合并成通用规则** | 误判（B 站允许 URL 却被抖音规则卡掉） | 通用 + 平台差异分开存 |
| **只靠公开文档不收实战反馈** | 官方不会写的隐性规则永远缺位 | 建立 case 回流机制 |
| **发布后才发现问题** | 已经消耗掉一次发布机会和流量 | 预检前置到发布前 |
| **把预检当免死金牌** | 平台审核不止规则，还有机审模型 | 预检降低概率，不消除风险 |

## Quality Gate

发布前逐条确认：

1. 语音、字幕、画面是否都送进检查了？
2. 报告里是否标明了原文位置、时间点和判断依据？
3. 修改建议是否具体到可执行（而不是「注意合规」）？
4. 本次涉及的平台差异规则，是否确认过来源与核实日期？
5. 被卡审过的内容，是否已回流为 case 并提 PR？

## 与既有内容的关系

[[patterns/wechat-image-post-account-sop]] 里的 15 条 Quality Gate 是**内容规范层**的自检（贴图规格、话题标签、非真人自动化创作等）；本模式是**规则驱动层**的预检——把散落的平台规则集中成一份带来源的检查表，由 AI 执行。

两者可叠加：前者告诉你「什么是对的」，后者帮你查「这次有没有踩线」。
