# Dreaming 离线记忆整理模式

> 把"回顾旧经历、纠错、重新组织记忆"从任务流程里拿出来，作为一轮**独立的离线计算**。

## 机制

任务做完之后，另跑一轮，让 Agent 翻旧记录、改掉写错的笔记、合并重复的内容。这轮整理叫 **Dreaming**（研究作者 Lance Martin 在 X 上称其为"一轮离线计算"）。

Dreaming 只做三件事：**回看经历、纠错、记笔记、重新组织记忆**。

## 典型场景

周二在测试环境跑通了新接口，顺手记了一句"同步任务已经迁完"。周三换会话查生产，发现还指着旧接口。

两次查到的东西都对，坏在周二笔记**漏了"测试环境"四个字**。

让 Dreaming 翻出两次会话的工具记录对照后，笔记可以改成两句：

- 周二，测试环境走通了新接口
- 周三查生产配置，夜间同步任务仍指向旧接口

## 关键约束

1. **旧记录只能核对"当时发生了什么"**。周三之后生产有没有切换，还得重新查。记忆提供的是"去哪儿查"，不是"现在是什么"。

2. **需要额外计算，且结果不一定马上进入正在进行的会话**。这是把回看和重组放到任务之外换来的代价。

3. **整理与采用必须分离**。Claude Platform 的 Dreams API 把整理结果写进一份新库，原来的库不动；运行中就可能出现新库，失败或取消也可能留下部分内容。判断整理有没有做完，要看任务是否到 `completed`。**完成整理不会自动替应用切换记忆库**——应用要先看改了哪些文件，再决定下次会话挂哪份库。

4. **纠错的前提是证据还在**。笔记能改回来，靠的是当时查过的东西还找得到。

## 自建 Agent 的采用步骤

任务笔记多起来后，需要纠错时：

1. 让整理过程**同时读旧笔记和原始记录**
2. **逐条列出冲突、依据与修改，先写成候选版**
3. 检查改动、**重跑刚才的问题**
4. 再让后续会话读取新版

这四步给 Dreaming 的整理结果补上了明确的"采用"环节——原生的 Dreams API 并不自动完成这一步。
