# 发布商 ID 反查站群

> 看到一个做得不错的站，顺藤摸瓜就能摸出站长手里还有哪些站——靠的是 **AdSense 发布商 ID**。这是 IAB 行业标准文件 `ads.txt` 里的公开信息，四步就能跑通。

## 原理

`ads.txt` 是广告投放侧的行业标准文件：**站长必须公开列出自己授权的 AdSense 发布商 ID**，因为它是收款账户的标识。里面每行长这样：

```text
google.com, pub-1234567890123456, DIRECT, f08c47fec0942fa0
```

- 第 1 段 = 广告平台域名
- 第 2 段 = **发布商 ID**（`pub-` + 16 位数字），这是我们要的
- 第 3 段 = 授权关系（DIRECT / RESELLER）
- 第 4 段 = 该平台的证书指纹

同一个发布商 ID 意味着**同一个 AdSense 收款账户**。而只要源码里引用了同一个发布商 ID，那个站就在用同一个账户。

## 四步操作

| 步骤 | 操作 | 工具 |
|---|---|---|
| **1. 取 ads.txt** | 在目标域名后面直接加 `/ads.txt` 打开 | 浏览器 |
| **2. 读发布商 ID** | 找 `google.com` 开头那一行，`pub-` 后面那串 16 位数字就是他的发布商 ID | 肉眼 |
| **3. 反查站群** | 拿这串 ID 去 [PublicWWW](https://publicwww.com/) 搜，源码里带这个 ID 的网站会全列出来 | PublicWWW（付费源码搜索引擎） |
| **4. 找真正吃的方向** | 把列出来的站丢进 [Similarweb](https://www.similarweb.com/)，看哪个流量最高，就知道他真正吃的是哪个方向 | Similarweb |

## 关键判断

> 有人一个账号挂了十几个站，你盯着的那个可能只是最不起眼的一个。

**第 4 步是这条技巧的价值所在**。反查出来的站群里，流量最高的那几个才代表这个站长的主攻方向；单个爆款站可能只是他矩阵里的小号，真正在赚钱的是同一账户下的另一个站。

所以用它做竞品分析时，结论不是「这个站做 X 方向」，而是「**这个站群在 X 方向上有规模**」——后者才是你真正要判断的事。

## 边界与风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **ID 相同 ≠ 同一个人** | 原文明确提醒：**ID 相同只能说明是同一个收款账号，也可能是代运营** | 结论只到「同一收款账户 / 同一运营主体」，不要断言同一人；可交叉核对站上的联系方式、政策页主体名 |
| **ads.txt 可能不公开** | 不用 AdSense、或刻意隐藏的站没有这行 | 这是**排除法**工具，查不到不代表没有站群 |
| **PublicWWW 是付费的** | 源码级搜索引擎，免费额度有限；大站的源码往往被压缩混淆，命中不全 | 先用免费额度验证思路，量大的再付费 |
| **Similarweb 只给估算** | 小站的流量估算误差极大 | 只用来看**量级排序**，不用看绝对数值 |
| **多平台多 ID** | 一个站长可能给不同站绑不同 AdSense 账号 | 单个 ID 反查出的是「一个收款账户的站」，不是「一个人的全部站」；要多个 ID 交叉 |
| **使用边界** | 这些是**设计上就公开**的信息，用途应是**理解竞争格局、找差异化方向、避开同质化赛道** | 不用于骚扰、举报打击、盗号或任何破坏行为；也不要把反查结果当成「对方的商业机密」传播 |

## 这条技巧在竞品调研里的位置

[[patterns/competitor-research-four-step]] 给出的四步法（AITDK 初筛 → SiteData 体检 → Similarweb 拆流量 → Wayback 追历史）解决的是**单个站**的解剖。

发布商 ID 反查解决的是**站群**维度——它回答的是「你以为在跟一个站竞争，其实你在跟一个矩阵竞争」。两者互补：

| 维度 | 方法 | 回答的问题 |
|---|---|---|
| **单站** | 竞品调研四步法 | 这个站做得怎么样？流量从哪来？历史怎么演化的？ |
| **站群** | 发布商 ID 反查 | 这个人手上还有哪些站？他真正的主攻方向是什么？ |

对做**新词站群 / 站群套利**的独立开发者，这一步尤其关键：站群里每一个起量的站，都是一个已被验证的关键词；而流量最高的那几个，就是当前最值钱的关键词方向。

## 落地清单

1. 挑 3–5 个你关注的对标站，逐一打开 `域名/ads.txt`；
2. 记录每个站的 `pub-` ID，**相同 ID 的合并成组**；
3. 每组去 PublicWWW 反查，拿到候选站全集；
4. 丢进 Similarweb 看量级排序，**排序最高的几个 = 这个站长的主攻方向**；
5. 反查结果与你的选题交叉：已在做的方向避开，同一收款账户下的其他站说明该方向已被占位。
