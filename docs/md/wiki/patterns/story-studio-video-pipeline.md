# Audio-First 短视频流水线

> 分镜不是按字数瞎猜，而是以**真实音频时间戳**为基准——先出声音，再切分镜。

## 核心倒置：为什么音频在分镜之前

常规流程是「先写分镜 → 再配音 → 再对齐」，代价是手动听录音、敲字、找时间戳，拆 20 个镜头要一条条对齐秒数。

Audio-First 把顺序倒过来：

```text
文案 → 配音（拿到真实时间戳）→ 分镜切镜 → 生图 → 剪辑草稿
                    ↑
            这一步改变了后面所有环节的基准
```

结果：**从这一步开始，分镜就有了完全真实的秒数基准。**

## 五步流水线

| 步骤 | 做什么 | 关键技术 |
|---|---|---|
| **1. 文案创作** | 拒绝 AI 味，370+ 篇爆款语料蒸馏 | Writing-DNA 双体系 + A/B/C/D/E 钩子库 + 事实核查表 |
| **2. 配音与时间戳** | 毫秒级字音对齐 | 豆包语音 V3 双向流式 WebSocket / 自备 MP3 |
| **2b. 本地转录** | 提取每句台词起止时间戳 | Coli（基于 sherpa-onnx），自动纠偏人名与专有名词 |
| **3. 分镜与配图** | 3 套画风 + 参考图锚定防穿帮 | Audio-First 切镜（约 8 秒/图）+ Reference Images |
| **4. 剪映草稿生成** | 一键生成可编辑剪映专业版工程 | pyJianYingDraft 底层能力 |
| **5. 剪映微调** | 字幕与特效，导出成片 | 剪映内置识别字幕 |

## Step 1：Writing-DNA 与钩子库

两大专业级 Writing-DNA 体系，基于 **370+ 篇顶级爆款逐字稿深度蒸馏**：

- **历史叙事风**：问题驱动，以具体历史行动与制度因果推进，结尾严密兑现承诺，拒绝空洞升华
- **真实人物故事风**：钩子先行 → 巅峰数字 → 可谁也没想到 → 磨难场景 → 金句收尾

### A/B/C/D/E 五类开头钩子库

Agent 会自动调取内置钩子库，让用户先选：

| 类型 | 特征 | 示例 |
|---|---|---|
| **A 型（数字连排）** | 用密集数字制造冲击 | 「5 岁丧母，18 岁拒绝婚姻，从医 60 年，亲手接生 5 万多个婴儿……」 |
| **B 型（宿命定格）** | 用反差命运定格画面 | 「她一辈子没有自己的孩子，却成了全中国几万个母亲心底最信任的依靠……」 |
| **C 型（反常画面）** | 用违反直觉的具体场景开场 | 「深夜 11 点的协和病房，一位满头银发的老人，手里紧紧握着一把被摩挲得发亮的产钳……」 |

**输出约束**：严格按照事实核查表与字数约束（误差控制在 ±5%），绝不凭空编造违背史实的引语或经历。

### 一个关键提醒：Skill 不等于文案质量

> 虽然每一个 agent 都可以帮你写文案，但是不同的 agent 哪怕遵循同一套 skill，写出来的文案也是不同的。

作者的实测结论：claude opus 4.6 与 gemini 3.8 flash 写出来的文案 AI 味最少、写作水平最好。

**方法论**：让 agent 每次给十版以上的开头钩子，自己测试对比，选出最好的那个。文案需要自己潜心打磨——不是给了 skill 生成一个东西、跑出来一条视频、随便发就能火的。

## Step 2：配音的两条路径

### 路径 A：接入豆包语音大模型（推荐）

- 火山引擎 **V3 双向流式 WebSocket** 协议，支持 `seed-tts-2.0` 与声音复刻音色
- Agent 自动调度合成，本地用 **ffprobe 校验完整性**，防止缺字漏字
- 对文本做**哈希防重复扣费**
- 敏感 Key 走系统底层 **DPAPI 加密存储**，绝不泄露在明文项目中

**音色准备流程**：自己找好一个流量好的对标账号 → 下载其音频 → 到豆包语音里克隆音色保存 → 交给 agent 配置好 → 后续发文案给 agent 即自动生成 mp3。

### 路径 B：自备配音 MP3（真人录音 / 剪映克隆）

把录好的 `voice.mp3` 丢进文件夹，对 Agent 说「配音我已放进文件夹，直接读取并做后续对齐」。

## Step 2b：本地离线转录（Coli）

无论哪种音频，Agent 都会自动调用本地离线语音识别工具 **Coli（基于 sherpa-onnx）**，毫秒级提取每一句台词的起止时间戳，并对照原文**自动纠偏人名、专有名词**。

## Step 3：分镜与配图

### Audio-First 切镜机制

1. **真实节奏切镜**：以转录出的音频时间戳为基准，默认按**约 8 秒/图**规划，确保从第 0 帧就有图，且每一镜画面与此时此刻正在口播的情节严丝合缝
2. **逐镜时代考据**：自动识别该镜头人物所处的年龄阶段（青年/中年/晚年）、时代服饰、发式与建筑形制

### 三大视觉画风

| 画风 | 标识 | 特征与适用 |
|---|---|---|
| **厚涂历史漫画风** | `historical-comic` | 强烈戏剧张力，赭金与焦褐块面，电影镜头感拉满（自带 3:4 与 4:3 金箔榜书标题封面） |
| **黑白纪实叙事风** | `monochrome-narrative` | 克制冷峻，细腻的胶片感与人物面部年龄质感，适合近现代与深度传记 |
| **历史写实风** | `historical-realism` | 柔和自然的光照与写实笔触 |

### 为什么不会画风突变

Skill 内置了**正文基准参考图库（Reference Images）**。实际生图时，Agent 会自动将同组的高水准参考图注入生成工具，**首张核验笔触与明暗对比后再批量出图**，把跨镜头画风漂移降到最低。

**降级路径**：习惯用 Midjourney、即梦或 ComfyUI 的，可以让它「只输出带时间戳的分镜表和每镜独立提示词」，不实际生图。

## Step 4：剪映草稿一键生成

不再手动剪辑，Agent 直接生成可编辑的剪映专业版（JianYing Pro）草稿箱工程。

- **底层能力**：pyJianYingDraft，全自动写入轨道
- **平滑慢推拉**（拒绝死板静帧）：每张图片根据停留时长智能计算缓入缓出推拉比例（默认约 16~20 秒走完 12% 幅度），画面始终处于流动呼吸状态
- **切点冲击缩放（Cut Punch）**：在镜头切换点自动写入出镜微推近（1.28x）与进镜拉回（1.50x）关键帧，既有电影硬切的视觉冲击，又彻底避免了剪映自带转场可能带来的闪黑帧问题
- **防丢保护**：图片与音频自动复制进剪映草稿目录，打开剪映即可直接播放、微调、导出 4K/1080P 成片

## Step 5：剪映微调

Skill 本身**没有配置字幕功能**——作者建议在剪映里识别字幕，理由是省心且可控。再根据习惯添加落叶、飘雪等特效即可。

## 与既有流水线的关系

[[concepts/ai-content-pipeline]] 描述的是**通用 12 步框架**（分阶段确认、用代码做视频 HTML/CSS/JS、HyperFrames 渲染）。本篇的 Story Studio 路线在三点上不同：

| 维度 | 通用 12 步（Bytec） | Story Studio |
|---|---|---|
| **输出目标** | 直接渲染 MP4 | 生成**可编辑剪映草稿**，人工微调后导出 |
| **分镜基准** | 视频脚本阶段规划 | **音频时间戳反推**，先出声音 |
| **画风一致性** | 统一风格背景图（3-4 张） | **Reference Images 注入 + 首张核验**，逐镜时代考据 |

两者不冲突：前者是「代码做视频」，后者是「代码写剪辑工程」——后者更贴近普通创作者的实际工作流（剪映是国内创作者的主力工具）。
