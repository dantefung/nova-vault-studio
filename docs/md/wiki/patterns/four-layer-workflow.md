# Four-Layer AI Workflow

AI 个人工作流的四层架构：

| 层级 | 解决的问题 | 我的做法 |
|------|-----------|---------|
| 数据底座 | AI 看不到我的全部上下文 | 把长期数据收回一个本地 Obsidian vault |
| 执行环境 | Agent 需要常驻进程和本地 IO | 家里一台 Mac 24h 跑 Codex、Hermes Agent 等进程 |
| 触达入口 | 不同场景需要不同摩擦的入口 | 微信、Codex Mobile、Obsidian Sync 分工 |
| 行动能力 | AI 不能只读笔记，还要能调用工具 | 用 Skill 接富途、外部 API 等 |

## 四层顺序的重要性

1. 如果没有统一数据，入口再多也只是多个聊天框
2. 如果没有常驻执行环境，agent 只能在你打开电脑时工作
3. 如果没有低摩擦入口，系统搭得再好也会被忘掉
4. 如果没有 Skill，AI 最多是个会翻笔记的问答机器人

## 链路

让 AI：读得到我 → 跑得起来 → 找得到我 → 也能替我做事
