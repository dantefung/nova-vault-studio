# 视频提示词反推模式

> 用多模态模型将参考视频转换为结构化视觉规格，再针对目标视频生成模型编译 Prompt，并通过生成结果与参考视频的差异持续校正。

## Pattern

```text
参考视频
  -> 预处理与镜头切分
  -> 客观视觉观察
  -> 结构化分镜规格
  -> 目标模型 Prompt 编译
  -> 候选视频生成
  -> 差异评估
  -> 单变量修订
  -> 再生成
```

## Five-Layer Specification

| 层级 | 要回答的问题 | 典型字段 |
|------|--------------|----------|
| 场景 | 画面发生在哪里 | 环境、时间、天气、背景 |
| 主体 | 谁或什么出现在画面中 | 外观、服装、道具、位置 |
| 动作 | 主体如何随时间变化 | 起点、终点、速度、方向 |
| 摄影 | 观众如何看见这一切 | 景别、机位、焦段、运镜 |
| 渲染 | 画面呈现什么质感 | 风格、光影、色彩、材质 |

分镜之间还需要单独记录一致性约束，例如人物身份、服装、道具、空间方向和光源连续性。

## Separation of Roles

反推流程应把三个角色分开：

1. **观察者**：只记录视频中可以看见的证据，不编写最终 Prompt。
2. **编译者**：把确认后的视觉规格转换为目标模型支持的指令。
3. **评估者**：比较生成结果与参考视频，定位最大差异并提出下一轮单变量修改。

角色分离可以降低模型一边观察、一边为自己生成的描述辩护的倾向。

## Evaluation Rubric

每轮生成可以按五项分别评分：

- 主体与构图
- 动作与时序
- 镜头语言
- 光影与材质
- 场景和角色一致性

优先修订最低分且影响最大的一个维度。多次生成仍不稳定时，应把问题从“措辞不够好”上移到模型能力、参考素材、时长、镜头复杂度或参数控制。

## When to Use

- 学习优秀视频的镜头、动作和视觉结构。
- 为现有创意快速生成可编辑的 Prompt 初稿。
- 把视频复刻流程沉淀为可复用的叙事组件。
- 为不同视频生成模型转换同一份视觉规格。

## Failure Modes

- 把反推结果误认为原始 Prompt。
- 不切分长视频，导致模型遗漏镜头或混淆时序。
- 只描述主体，不描述动作和摄影语言。
- 一轮同时修改多个变量，无法判断哪项有效。
- 忽略生成模型的语法、时长和参考素材能力差异。
- 把模型对视频的猜测当作确定事实。
