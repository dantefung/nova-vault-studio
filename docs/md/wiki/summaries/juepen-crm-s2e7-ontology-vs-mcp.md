# 【嘴喷CRM】S2E7：本体论 pk MCP一番战 — 精读摘要

## 核心结论

**接口是点，链接是边。预制接口，等于预制路径。** 短期看，语义封装决定你能不能用起来；长期看，本体决定你的天花板在哪儿。MCP（传输）→ 语义封装（可理解）→ 本体论（可组合），是三层递进关系，不是二选一。

## 两个真实反例

### 反例一：金额超五十万（字段未暴露）

问 agent："华南、金额超五十万、超过一个月没跟进、还没摸到决策人的单子，按体检分从低到高排给我"

agent 答得很流畅，但金额字段根本不在任何查询工具的返回值里。它用"必赢""大概率"等预测分类凑了一个看起来合理的答案，语气和真答对时一模一样——**不会报错，不会说"我看不到"**。

补救：把金额加进查询工具的返回值，一行代码即可。

### 反例二：王小明离职风险（路走不通）

问 agent："王小明要是离职了，他手上的单子交接出去，风险有多大？"

agent 停在第一跳："王小明名下有 12 单"——这是中间结果，不是答案。跟进记录的查询工具不支持按跟进人筛，这条路直接断了。

补救：**造不出**——因为在王小明提离职之前，没人知道会有人问这个问题。

## 核心论点

### 三层架构：MCP → 语义封装 → 本体论

| 层级 | 解决什么问题 | 性质 |
|------|-------------|------|
| 第一层 MCP | 怎么把东西递出去 | 传输协议，只管连通性 |
| 第二层 语义封装 | agent 看不看得懂 | 投入产出比最高，刚需 |
| 第三层 本体（对象+链接） | agent 能不能自己组合路径 | 决定天花板 |

### 链接的关键价值

Palantir 本体论的核心结构：对象（Object）、链接（Link）、动作（Action）。关键在链接：

> 链接在本体里被声明之后，对象集上会自动生成 search around 的接口，操作员可以走到关联对象，而不需要任何人写过这个查询。

**"不需要任何人写过这个查询"** 是整件事的关键。

一个系统里，对象之间的路径数量随对象数 × 关系数组合增长——三跳四跳的路径轻松上千条。你永远预制不完所有路径。这不是数据量问题，是组合数学问题。

## 失败的共同模式

agent 走不通的时候，两种失败方式相同：
- 不会报错
- 不会说"这条路断了"或"我看不到"
- 会用现有的东西拼一个说得通的答案
- 停在第一跳，把中间结果当答案
