## 核心观点

用 Git Worktree 为每个 AI Agent 分配独立代码现场，实现一个人同时管理几十个并行任务而不打架。分支管「路线」，Worktree 管「现场」。

## 关键概念

- **分支**：代码往哪个方向走（Bug 修/新功能）
- **Worktree**：同时打开几个代码现场（同一项目在硬盘上铺开成多个独立目录）
- **核心公式**：分支是排班的，Worktree 是发工位的

## 五种情况

| 情况 | 分支 | Worktree | 场景 |
|------|------|----------|------|
| 1 | ❌ | ❌ | 5分钟小活，main直改 |
| 2 | ✅ | ❌ | 大活/长周期/可能推倒重来 |
| 3 | ✅（同一） | ✅（多个） | 同分支下多个并行子任务 |
| 4 | ✅（多条） | ✅（每分支一个） | 多路线并行 |
| 5 | ✅（多条） | ✅（每分支多个） | 全矩阵，十几二十个现场 |

## 独立开发者三条建议

1. **拆任务能力是第一道分水岭**：从「怎么实现」变成「怎么拆成互不干扰的任务」
2. **基础设施先于功能**：测试/CI/代码规范 = 地基，地基稳才能多 Agent 并行
3. **当产品经理别当码农**：判断力稀缺，AI编程时代核心竞争力是产品感觉和决策质量
