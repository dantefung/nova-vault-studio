# 不建后台、不买服务器：三个 B2B 站怎么拿到询盘

## 核心结论

**B2B 站的成败不在技术选型，在「有没有搞清楚目标客户关心什么」。** 作者的三个站（两个外贸站 + 一个医旅站）陆续拿到询盘，技术上极简——纯 HTML + CSS 或 Astro，**没有管理后台，没有服务器（全部 Cloudflare），一年只花几十块域名费**。真正花时间的是前期：跟业务反复沟通产品细节、定采购商画像、研究竞品、分析搜索意图、规划整站关键词，**上线前至少两周，大部分精力不在敲代码上**。

## 关键洞察

1. **工具别纠结，核心是方法**。群里天天问用 Codex 还是 Claude Code——**这些全都是工具，真正的方法掌握了，用哪个写出来的代码都差不多**。作者的做法是把每次验证过的方法写成技能，攒成约 20 个技能、覆盖 4 类站的技能包，做什么站就调哪一套。
2. **自己做站，纯 HTML + CSS 就够，不必搭后台**。判断依据是场景：**自己用、不给别人外包建站 → 不搭**；别人要能自己发博客、加页面 → 这种才需要 Emdash（作者自己做了二改）。理由很实在：**搭后台费劲不说，开发完了平时根本不怎么打开看。**
3. **询盘怎么处理**：提交存到数据库，再在询盘邮件里塞 **visitor tracking（访问轨迹追踪）**——客户从哪个国家来、在网站上看过了哪些页面，一清二楚。**这是「不做后台」方案能成立的前提：你不需要内容管理，但你需要线索可见。**
4. **服务器成本可以压到零**：全部部署在 Cloudflare，除了一年几十块的域名费没有别的成本。
5. **500 块的建站为什么拿不到询盘**：那种做出来充其量是纯展示的空壳——**外观看着还行，但代码里根本没有 SEO、AEO 和 GEO 的结构，搜索引擎和 AI 不会抓取**。而且最主要的问题是**根本没调研目标客户关心的问题**。
6. **不懂产品就必须去问业务员**。产品自己不熟悉时，要跟业务员问相关问题、拿到相关信息才好做，**否则自己在一边摸索，理解不了目标客户群体和应用场景**——有些真需要跟业务员沟通才知道这个产品的目标客户还有这群人用在这个场景中。
7. **先搓 HTML 原型再动手写代码**。作者习惯在正式写代码前把网站结构和每个页面的排版布局做好，**原型定清楚了再动手，后面开发就会顺畅很多，不会反复返工**。
8. **技能包里定的一条规矩：第一版就先做英语的**，其他语言暂不做，等数据出来让数据决定要做哪些语言版本。（作者自己反而常常把几个语言一起开发，但他也承认现在很讨厌做多语言站——AI 总会出现翻译小问题，要审查好几遍；**有些语法问题不是小语种专业的根本审查不出来，这些放过吧，不要追求太完美**。）
9. **内容要完全站在目标客户角度写**。不管网站文案还是博客文章，**不要站在工厂自夸的角度写，要写买家采购时真正关心的问题**。再加两条：放大自己的优势（这一点跟做自媒体很像，都是拿自己擅长的来做）；盯紧这个网站的终始目标（**AI 有时候写的文案常常会偏离网站目标**）。
10. **上线不是撒手不管**：隔段时间翻 GSC（Google Search Console）和 GA4，看买家搜索哪些词进来的、在哪跳出的，再根据真实数据补内容。
11. **内容扎实了，不做外链也能拿到询盘**。作者的站到现在都没做任何外链，纯粹是因为懒散——外链这种繁琐事一般拖到最后才碰。细节上还要补齐 SEO / AEO 的结构化数据（Schema）、理顺内链结构。
12. **图片的 alt 属性是常被忽略的细节**：网站上的每张图片，alt 都要写清楚、图片内容信息要全。**现在的 AI 搜索引擎在引用答案时，会直接抓取网页里的图片和视频。** 另外可以放视频，但别把大视频文件塞进站里（太占存储），传到外部平台再嵌链接。

## 方法对照：什么场景用什么技术栈

| 场景 | 技术选型 | 原因 |
|---|---|---|
| 自用 / 不外包 | 纯 HTML + CSS（或 Astro），无后台 | 开发完基本不开后台，省下的时间投到前期调研 |
| 客户要自己改内容、加页面 | Emdash（二改版） | 需求明确要 CMS，但原版偏重，自己项目不用 |
| 部署 | Cloudflare | 服务器成本为零，只留域名费 |
| 线索 | 表单存库 + 邮件里放 visitor tracking | 不做后台也能知道客户从哪来、看过什么 |
