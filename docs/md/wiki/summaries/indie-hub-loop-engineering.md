## 核心观点

**有条件地赞成 Loop Engineering**：低风险、可验证、容易回滚的工作可以交给 Loop；目标、证据、权限和规则晋升不能由同一闭环自行决定。核心是区分"人在不在屏幕旁"和"人是否仍掌握系统"。

## 关键要点

1. **Cognitive Surrender（认知投降）**：73.2%的人在AI给出错误建议时会跟随，只有19.7%能独立推翻。保留人工确认按钮不足以保证独立思考。

2. **任务准入四条件**：目标清楚 + 结果可独立验证 + 可低成本撤回 + 团队长期维护需求。机械迁移适合Loop，支付/认证/权限等核心模块不适合。

3. **控制面写进运行协议**：目标/禁区/通过条件/停止条件/交接内容都要明确；检查/继续/触发/最终处置拆开，渐进放权。

4. **规则变更要慢**：执行Loop高频运行，规则变更要经证据+回归+版本管理；不能让Agent自己改规则再自己验证。

5. **四步上线**：人工复盘→影子模式→开放候选结果→开放低风险动作；关键看人接手成本，不是Agent产出量。

6. **Bun迁移案例**：100万行代码，测试全过后仍发现19个回归——机械验证只能覆盖团队已表达的预期。
