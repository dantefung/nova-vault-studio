# 冬青：闲鱼虚拟资料自动化——AI + MCP 把选品/制作/上架/发货变成一条流水线

## 核心结论

闲鱼虚拟资料这门生意的赚钱逻辑没变（找到付费需求 → 快速做成产品 → 持续上架 → 自动交付），**真正改变的是执行方式**——AI 负责选品 + 写资料 + 出上架素材，MCP 负责网盘上传 + 闲鱼批量上架，自动发货软件负责交付。**人只剩下三件事：定方向 + 检查质量 + 处理异常。** 「批量铺货」第一次从口号变成可落地的工程问题。

## 关键洞察

1. **赚钱的是「整理效率」不是「文件本身」**：网上到处能下载到的免费内容之所以还能卖，是因为买家不愿花时间搜索、筛选、下载、核对、整理。把分散信息做成结构清楚、拿来即用的产品，卖的就是这份节省下来的时间。
2. **虚拟产品的复利来自重复交付**：没有进货/仓储/快递环节，一份资料做完后可以无限卖。瓶颈不是产品本身，而是「持续制作 + 持续上架」的执行力——AI + MCP 把这个瓶颈压平了。
3. **AI + MCP 的分工是「内容生产 vs 平台执行」**：AI 负责「选什么 + 写什么 + 标题描述怎么写」（内容侧），MCP 负责「百度网盘上传 + 闲鱼上架」（平台侧）。两者解耦，每一步都有明确输入输出，前一步结果直接交下一步。
4. **SOP 化的「质量检查」不能省**：AI 写完必须人审事实正确性 / 链接可打开 / 步骤可走通 / 文件可在手机查看；自动上传解决重复操作，最终文件是否正确仍要确认。Cookie、Token、账号凭证绝不进截图。
5. **批量 ≠ 乱发**：每个商品都要独立内容、独立标题、独立交付链接；不要同一份文件换 80 个标题重复发，也不要让 AI 在没检查时连续操作账号。闲鱼 MCP 设了写操作限流与风控熔断，发布失败就停。
6. **闲鱼 MCP 解决批量上架，不解决自动成交**：是否出单仍取决于需求、标题、封面、价格、产品质量。商品发出去 ≠ 卖得掉。
7. **自动发货必须用真实小额订单端到端测一次**：后台显示「配置成功」≠ 真的发货成功。要验证买家是否收到消息、链接是否对应商品、提取码是否可用、文件是否完整、系统是否留有发货记录。
8. **放大方式是「持续增加有效商品 + 持续淘汰无效商品」**：不是指望单个商品突然爆单，而是利用 AI + 自动化持续增加能被搜索、能成交、能自动交付的商品数量。某方向开始出单后，再围绕相近需求继续做。

## 五步流水线

1. **AI 选品**：用 goofish-cli 闲鱼 MCP 搜索公开商品，分析商品名/售价/需求场景/卖点，不复制原文只分析市场；用淘宝 MCP 旁路看同类虚拟资料的玩家分布。每天挑几个自己能完成的方向即可，不需要 500 个。
2. **AI 写资料**：先生成完整目录（目标用户/使用场景/交付形式/每章解决的问题）→ 确认后逐章节写正文（教程/模板/资料合集各走不同 Prompt）。完成后让 AI **同时**生成闲鱼上架素材：标题、描述、5 卖点、适用人群、交付方式、售后说明、3 张商品图文字。
3. **百度网盘 MCP 上传**：用百度网盘官方 MCP 创建商品交付目录 → 上传最终文件 → 生成分享链接与提取码 → 返回链接 + 提取码。统一目录命名（`商品名称/最终交付文件/使用说明`），草稿与最终文件隔离。**本地上传只能用 stdio 模式，SSE 模式不提供本地上传工具**。
4. **闲鱼 MCP 批量上架**：用 goofish-cli 读取已完成的商品资料 + 标题/描述/价格/图片/类目/网盘链接 → 为每件商品匹配正确网盘链接 → 调用 MCP 逐件上架 → 保留商品 ID 与网盘链接的对应关系。控制发布节奏，发布失败即停止。
5. **自动发货**：把「商品 ID + 网盘链接 + 发货话术」配到易店自动发货管理系统（现成免费）或 xianyu-auto-reply 开源自建系统。买家付款后由系统自动发送正确资料。

## 每天的执行节奏

| 时段 | 动作 |
|------|------|
| 早上 | AI 搜索几个新虚拟产品方向，挑出可独立制作、可标准化交付的方向 |
| 上午 | AI 完成资料和上架素材；人审事实 / 链接 / 步骤 / 文件兼容性 |
| 中午 | 百度网盘 MCP 上传（一商品一目录，自动生成分享链接） |
| 下午 | 闲鱼 MCP 上架（每天稳定一批，持续增加店铺有效商品） |
| 晚上 | 把新商品加入自动发货规则，核对 ID/链接/话术，测试无误后销售 |
| 每日一次 | 处理上架失败 / 链接失效 / 账号掉线 / 无匹配发货规则的订单（异常订单人工处理） |

## 选品三准则

| 准则 | 含义 |
|------|------|
| 明确用途 | 买家看到后立刻知道这份东西能帮他完成什么，越具体越好写标题与详情 |
| 可标准化交付 | 付款后发一个 PDF / 表格 / 模板 / 网盘链接就能完成交付 |
| 可继续拆出相关产品 | 一个方向不只做一件商品；AI 可顺便拆不同人群/场景/版本，生成多个独立商品方向 |

## 适用边界与风险

- **平台规则可变**：百度网盘 MCP 个人用户开放能力 / 闲鱼平台风控策略可能变化，正式使用前必查最新官方说明。
- **自动发货 ≠ 自动成交**：MCP 解决批量上架与发货，不解决买家下单。质量决定出单。
- **AI 写出错的内容会一起铺出去**：自动铺货是把质量检查从「1 次」放大到「100 次」。质量门槛必须前置，不能省。
- **多账号风控**：Cookie、Token、账号凭证不进截图、不交第三方；同 IP/同设备多账号会被识别。
- **版权风险**：AI 生成的视觉/文字素材可能涉版权，发布前必自查。
- **依赖工具链齐全**：缺 MCP / Node / 网盘授权任何一个就跑不通。
