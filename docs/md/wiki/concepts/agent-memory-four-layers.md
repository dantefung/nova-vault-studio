# Agent 记忆四层架构

## 核心定义

**Agent 记忆四层架构** 是 Anthropic 在《The components of agent memory》（2026-11-06）中提出的记忆分层模型：把 Agent 留在会话外、供后续读取的上下文拆成**会话记录、笔记、Wiki、启动上下文**四层，每层承担不同的检索时机与留存义务。

这里的"记忆"特指**留在会话外、供以后读取的上下文，不动模型权重**。

## 四层职责

| 层 | 存什么 | 什么时候用 | 能否被删除 |
|---|---|---|---|
| **会话记录** | 原始经过：查了什么、工具回了什么 | 回溯核对当时事实 | 会话有保留期（Claude Code 按期限清理） |
| **笔记** | 值得再用的发现 | 下次省掉几个文件的翻查 | 随整理流程修订 |
| **Wiki** | 多次会话的线索互相链接的页面 | 沿关系链一路追查 | 长期维护 |
| **启动上下文** | 开工时先看到的几行提示 | 每次开工都读 | 每次都占上下文 |

## 关键洞察

1. **分层是"检索时机"的分层，不是"重要性"的分层**。同一份信息可以同时存在于多层——笔记是会话记录的蒸馏，Wiki 是多篇笔记的链接，启动上下文是 Wiki 的索引入口。

2. **只有会话记录是"证据"**。笔记和 Wiki 都是二手结论。要核对"当时查到的到底是什么"，必须回到会话记录。Claude Code 会按期限清理本地会话，但自动记忆文件不随之删除——所以笔记里必须写明日期、环境和配置位置，否则几个月后只剩一句"已经迁完"就无从追溯。

3. **Dreaming 是离线纠错机制，不是同步机制**。它把回看与重组放到任务之外，可以跨多次会话对照；代价是需要额外计算，且结果不一定马上进入正在进行的会话。当场记笔记能被后续步骤立刻读到，但会分走当前任务的注意力。

4. **"文件里存着、会话读到了、回答用对了"是三件事**。Dreaming 补上的是第一段（怎么把过去经历整理成下次要读的内容），后两段要靠启动上下文与工具能力分别保证。

5. **启动上下文必须用"用户平时提问会用的名字"**。索引上只写"同步迁移"，遇到"夜间同步怎么又报错了"未必能联想成同一件事；写成"夜间同步、用户中心 SDK，见 sync-migration.md"才可被召回。

6. **启动上下文有隐性成本**。它每次都占上下文，里面的错误也可能反复影响后续会话。把详细经过放进主题页、用到再读，新会话就不必携带整段旧记录。

## 边界与代价

- 笔记写错时（漏掉环境条件这类），跨会话传播后会持续误导——Dreaming 的价值在于把这类错误在离线阶段修掉。
- Wiki 的收益与"查这条链路的频率"正相关：跨多文件拼信息的题收益明显，答案主要在单份文件里的题没有优势。
- 建 Wiki 本身有成本（评测中用了 128 个会话），不能只算答题时省的 token。
