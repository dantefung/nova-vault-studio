# 本体平台总体架构 (Ontology-Driven Platform Architecture)

> 企业数字化建设中，以本体模型（Ontology）为统一业务语义中枢，连接从需求探索、模型驱动应用生成、到多源数据智能分析推理与 OLTP/OLAP 口径对齐的全链路工程架构。

<!-- more -->

## 核心洞察

- **解决“语义翻译损失”**：传统 IT 链路中，业务需求经分析师、架构师、开发、DBA、BI、AI 多层翻译，语义持续失真。本体平台通过统一的业务对象与规则语义层，使所有角色与系统在同一语义底座上协作。
- **好品味的数据结构优先**：模型不是画图工具，而是可运行、可校验、可执行的数据结构（M1 对象、M2 行为、M3 规则、ME 事件、M4 场景、M5 主体、M6 补偿、M7 质量约束）。
- **AI 落地的确定性上下文**：大模型不能裸查数据库；必须结合本体对象定义、校验规则、字段映射与受限事实数据集，输出可追溯、无幻觉的分析推理结论。
- **务实落地路径（小闭环先跑通）**：第一阶段做“本体建模 → 数据连接 → AI 分析推理 → 存储追溯”最小闭环，切忌一开始搞全自动生成微服务的庞大黑盒。

---

## 总体架构：四层三纵

| 维度 | 层级 / 链路 | 核心组件与职责 |
|------|-------------|----------------|
| **四层架构** | **用户与生态接入层** | 需求录入、分析问答、建模工作台、应用控制台、REST API / MCP 服务 / 事件订阅 |
| | **核心引擎层** | 需求引擎、本体模型引擎、应用生成引擎、数据分析引擎、数据连接引擎、AI分析推理引擎、场景编排引擎、能力网关、大模型网关 |
| | **存储与资产层** | 需求库、模型库、映射库、数据集市、代码库、报告库（强调全链路可追溯） |
| | **基础设施与连接层** | 关系数据库、数仓、对象存储、消息队列、文件系统、大模型服务网关 |
| **三纵能力** | **设计时链路** | 需求探索 → 本体建模校验 → 领域代码/接口/表结构生成 |
| | **运行时链路** | 业务提问 → 逻辑查询计划 → 映射物理取数 → 语义增强 AI 推理 → 报告回写 |
| | **编排能力** | 业务事件驱动 → 跨系统流程编排 → 异常补偿机制 |

## 十大核心引擎职责

```
┌─────────────────────────────────────────────────────────────┐
│                    用户 / Agent 接入层                      │
└───────────────┬─────────────────────────────┬───────────────┘
                │                             │
    [设计时] 需求探索与生成        [运行时] 语义分析与查询
                ▼                             ▼
┌───────────────────────────┐   ┌───────────────────────────┐
│ 1. 需求引擎 (结构化访谈)  │   │ 4. 数据分析引擎(逻辑计划) │
└───────────────┬───────────┘   └─────────────┬─────────────┘
                ▼                             ▼
┌───────────────────────────┐   ┌───────────────────────────┐
│ 2. 本体模型引擎(M1-M7/ME) │◄──┤ 5. 数据连接引擎(多源映射) │
└───────────────┬───────────┘   └─────────────┬─────────────┘
                ▼                             ▼
┌───────────────────────────┐   ┌───────────────────────────┐
│ 3. 应用生成引擎(表/接口)  │   │ 6. AI分析推理引擎(无幻觉) │
└───────────────────────────┘   └───────────────────────────┘
                │                             │
    ┌───────────┴─────────────────────────────┴───────────┐
    │ 7. 存储引擎 (需求/模型/映射/数据/代码/报告 六库追溯)│
    │ 8. 场景编排引擎 (M4 流程编排与补偿)                 │
    │ 9. 本体能力网关 (MCP / OpenAPI / 权限控制)          │
    │ 10. 大模型网关 (路由 / 脱敏 / 成本 / 审计)          │
    └─────────────────────────────────────────────────────┘
```

1. **需求引擎**：AI 结构化访谈，区分通用建议与特有规则确认，生成可溯源需求文档。
2. **本体模型引擎**：将需求转为 M1~M7/ME 核心模型，管理版本与变更影响分析（Impact Analysis）。
3. **应用生成引擎**：基于模型生成单体/微服务表结构、CRUD 接口、前端表单、权限与报表。
4. **数据分析引擎**：将自然语言问题解析为面向对象的逻辑查询计划（非直接硬编码 SQL）。
5. **数据连接引擎**：维护物理表/接口到本体对象的映射，处理方言转换、缓存、脱敏与数据质量。
6. **AI 分析推理引擎**：按需提取本体上下文 + 注入真实数据快照，结合大模型输出附带可查依据的分析报告。
7. **存储引擎**：沉淀需求、模型、映射、快照、代码、报告六大资产，实现全链路版本溯源。
8. **场景编排引擎**：将 M4 场景转化为顺序、分支、并行、超时与补偿的可执行流程。
9. **本体能力网关**：通过 OpenAPI / MCP 协议向外部 Agent 暴露业务对象与操作能力。
10. **大模型网关**：统一模型路由分发、密钥保护、敏感数据脱敏与成本控制。

---

## 落地演进四阶段

1. **Phase 1 智能分析最小闭环**：本体建模 + 数据映射 + 动态取数 + AI 归因推理 + 结果溯源（验证比直接丢表给大模型更准）。
2. **Phase 2 需求至应用生成**：接入需求引擎与应用生成引擎，生成稳定单体应用、CRUD、主从表单与简单状态机。
3. **Phase 3 场景编排与生态开放**：引入场景编排引擎、本体能力网关（MCP）与大模型统一网关。
4. **Phase 4 全局治理与规模化**：模型版本矩阵、字段/指标血缘、企业权限与团队协作。
