# AI 创业的逃逸速度

> 套壳有没有价值，取决于你能不能在下一代模型到来之前，比模型自己跑得更快地迭代。**这个速度差就是逃逸速度。**

## 一句话定义

逃逸速度 = 在下一代模型到来之前，通过数据积累与基建建设，比底层模型能力演进快的那一段**领先期**。

领先模型时，套壳有意义；落后模型且产品力不足时，只剩心智与营销的调度空间。

## 为什么「套壳」这个说法有争议但仍然成立

从 2023 年初 GPT 爆火起，围绕套壳的讨论从未停止——小狐狸 GPT 站生态、套 Midjourney 的生图站、AI 漫剧生产、GPTs 虚拟员工。人们争论的核心是：帮普通人降低门槛这件事，在大模型叙事面前成立吗？

结论是成立，但**有条件**。

关键在于把黑盒拆开看：

```text
解决方案 = 人的水平 + 工具能力
                ↑        ↑
              1 份    补 0 的杠杆
```

AI 时代的黑盒是模型本身。只要搞明白**输入端**和**输出端**，中间的模型怎么换代都不影响你——从底层往上做，盒子随便换，表现层也可以随便换，本质从没发生过改变。

## 能力公式：套壳优化的到底是哪三样

```text
Agent 能力 = 模型水平（大脑）
           + 指令（提示词）
           + 经验（记忆）
           + 外部能力（工具）
```

**套壳的意义在于**：在相同模型水平的前提下，通过优化后三者（指令、记忆、工具）来提高 Agent 能力的天花板。

Agent 能力提升后，配合高水平人类做人机协同，才能得到更优质的解决方案。于是问题转化成一个工程命题：

> 如何在有限的时间内，通过优化后三者，在下一代模型到来之前提供出优质服务来获得客户，并在这个时间内构建出一种「逃逸速度」——通过数据积累 + 基建建设，让套壳始终有一种超越模型能力的速度。

**这是 AI Startup 的产品力生死线。**

## 逃逸速度 = 有效迭代次数

那逃逸问题最终变成：**如何让 Agent 在有限的时间内做更多次有效迭代。**

```text
更多次 = 迭代周期短 × 每次都有有效反馈
          ↑                    ↑
     基建框架决定         数据质量决定
```

「更多次」有两个乘数，缺一不可：

| 乘数 | 由什么决定 | 失效后果 |
|---|---|---|
| **迭代周期短** | 基建框架（PDCA 循环有效性） | 每次迭代成本高，人就不愿意再投入 |
| **每次有有效反馈** | 数据质量 | Agent 一直重复垃圾任务，迭代不出智能判断 |

## 两类判断

### 方向判断（第一性）

第一性原理里夹杂着对未来方向的判断。这种判断有时异常简单：2025 年大家都在卷桌面智能体时，所有人都有一个基础判断——**人们不愿意坐在电脑前面**，移动就是第一性。

很多创业之所以会死，是因为 Pivot 不够。Claude Code 席卷桌面端时，如果你一上来就做移动端 Claude Code，自然产生优势心智；但你复刻一个 Claude Code，就得说出比它优秀的方面——这个课题本身极难，因为它不顺从人类的第一意识。你是后来者，还比前人厉害，这个信任基点难以构建。

**方向存在时空性。** 方向错了，就只能靠不断 Pivot 找答案。但战略与战术可以分离：有些产品知道未来是移动的，却优先做桌面，因为桌面能让移动更快更稳——这是战术，**但战略的远方从来都是移动**。

初心不一样，虽然同样在做「桌面优先」，侧重点完全不同，后面的逃逸速度也就截然不同。

### 迭代判断（专家知识）

当模型做得无效时，就需要输入人的智能来修正 Agent 的行为——这是通过外部人类输入给 Agent 的**专家知识**。Agent 获得的专家知识越多，它越发能变得智能。

专家知识有两个层面：

| 层面 | 做法 | 例子 |
|---|---|---|
| **一：给外部工具** | 让外部提供 Agent 工具，或走 Agent 自我构建工具的方向 | 2025 年让模型做 SEO，它压根不会调用 SEMrush / Ahrefs 拿关键词 KD 与搜索量，缺少有效上下文就做不出高质量决策建议 |
| **二：造上下文** | 通过优化「指令」与「记忆」构建上下文工程，触发模型注意力偏向专业部分 | 模型内部已训练了公开的专家知识，但缺少「上下文」来触发它 |

这两层是**初始化阶段**的事。Agent 从 0 到 1 开始执行后，就得从实践中自我获得反馈：

```text
反馈驱动三层优化
  模型层    ← RSI，多数模型厂商在做的事
  套壳层    ← 指令 + 记忆 + 工具，应用侧能优化的部分
  人类先验  ← 该沉淀什么、该丢弃什么（人的判断）
```

于是问题出现了：**如何让 Agent 沉淀经验、更新上下文与工具**——这是决定 Agent 迭代质量的关键环节。

这里不只需要后验的评估测量框架（迭代到底变差了还是变好了），更需要**先验**的部分：人的判断是什么，该沉淀什么，该丢弃什么。

> 当有了这两类判断，叫做我们在正确的做正确的事了。这是「道」的层面，接下来才是「术」。

## 关键区分：逃逸速度 ≠ 套壳耻感

技术圈常用「套壳」嘲讽上层产品，但[[patterns/ai-business-seven-layers]] 已指出：几乎所有现代软件都建立在底层第三方协议与硬件设施之上，最终付费客户只在乎业务痛点是否被优雅解决。

逃逸速度给这个讨论补上了**时间维度**：

- **七层金字塔**回答的是「你在价值链上交付什么标的物」（静态的空间选择）
- **逃逸速度**回答的是「你能不能抢在模型前面迭代完」（动态的时间竞赛）

两者不是替代关系。选定了交付层级，还要看自己有没有逃逸速度。
