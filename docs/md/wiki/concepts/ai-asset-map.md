# AI Asset Map

> 当企业 Agent 数量增长到上百个时，从 Agent 花名册走向可管理的数字资产关系图，回答"每个 Agent 与业务、数据、系统、权限和责任人是什么关系"。

## Key Points

- Agent 背后不只是模型，还包括提示词、知识库、MCP Server、API、数据库账号、工作流、审批规则和监控任务
- 五类管理盲区：资产盲区、责任盲区、权限盲区、依赖盲区、审计盲区
- AI 资产地图三层能力：资产注册表、关系地图、治理控制面
- 优先建设六条关系：Agent → 业务服务 / 责任人与团队 / 模型与知识库 / MCP 工具与 API / 数据对象与权限 / 工作流与审批审计
- 不是另建系统，而是扩展现有 CMDB 模型，让 Agent 成为配置项

## Details

### 八类必录信息

1. 身份：唯一标识、运行账号、认证方式、所属租户
2. 责任：业务负责人、技术负责人、维护团队、复审人
3. 目标：解决什么业务问题，服务哪个流程，如何判断成功
4. 能力：能够回答/判断/执行哪些动作，对外提供什么能力
5. 依赖：模型、提示词、知识库、MCP Server、API、应用、基础设施
6. 权限：可访问数据范围、可执行动作、环境、额度、有效期
7. 运行：版本、状态、调用量、成功率、成本、异常、人工接管率
8. 生命周期：申请、测试、上线、变更、复审、暂停、下线记录

### 与 CMDB 的关系

CMDB 保存稳定身份和关系，可观测平台保存轨迹和指标，IAM 保存认证授权，ITSM 承接流程。AI 资产地图让它们围绕同一个 Agent 身份和关系模型协同。

### 权限管理

Agent 权限不能只绑定部门角色。需要知道：代表谁、处理什么、执行什么、在什么条件下执行。OWASP 针对 Agentic AI 的风险清单包括工具滥用和身份与权限滥用。

### 四步建立最小可用地图

1. 统一身份：每个生产 Agent 分配唯一标识
2. 登记八类信息：先覆盖生产 Agent
3. 打通流程：Agent 上线自动创建配置项
4. 持续发现和复审：从多系统自动发现资产

## Context

本文来自"云与数字化"公众号，提出当企业 Agent 数量增长到 100+ 时，需要从"名字清单"升级为"资产地图"。核心观点是 Agent 治理问题不能靠更强的模型解决，而属于资产、配置、身份、流程和责任管理。
