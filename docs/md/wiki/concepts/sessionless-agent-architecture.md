# Sessionless Agent 架构与任务责任状（Quest）

> 会话不再代表身份和任务，只是一次执行的耗材；比会话活得更久的是业务事实与任务责任状（Quest）。

## 核心定义

**Sessionless Agent 架构** 是阿里在协同空间 Flock 实践中提出的一种 Agent 运行时范式：用户界面上不再提供“新建会话”按钮，系统也不把“一个会话”等同于“一个任务”或“一个助手”。会话降级为执行耗材，控制面（业务事实、进度、责任）与执行面（模型调用、工具执行、断点恢复）彻底分离。

## 核心机制

### 1. 会话作为耗材的切分规则

不同工作场景对会话的生命周期诉求不同：

- **对话会话（续接）**：人机沟通需要连续感，系统通过计算事实键（用户 + 业务空间 + 成员名单）自动决定是否续接。若群内成员发生变化，新对话自动切到新会话，防止新加入成员越权读取历史上下文。
- **任务执行（尽量新开）**：继承旧会话会让不可控上下文跨轮累积，导致模型注意力稀释或幻觉；因此每轮任务执行尽量从干净窗口启动，仅子任务收口回到父任务或人工断点重启时才续接。
- **验收会话（强制新建）**：验收者不能带着执行者的全部中间推导上下文，也不能拥有执行权，必须以独立的全新视角对比交付物与验收标准。

### 2. Quest（任务责任状）

在 Sessionless 体系中，比会话更稳定、跨越断点存活的实体是 **Quest**：

- **三要素**：明确目标、可量化的验收标准（Acceptance Criteria）、唯一的责任人（Owner）。
- **待验收（Pending Verification）状态**：Agent 工具跑成功、代码提了 PR，**不等于任务完成**。它只代表提交了一版候选交付物，必须由人或指定的验收 Agent 明确签收认可才算终结。如果不达标则打回重做，保留版本历史。

### 3. 任务链动态长出（Dynamic DAG）

复杂任务事先往往无法画出完整的流程图。DAG 不是前置规划出来的，而是在做事时自然“长出来”的：

1. Agent 在执行某个 Quest 过程中派生新任务，默认挂载为该任务的子任务；
2. 建任务时显式声明依赖项，上游完成前下游保持冻结；
3. 子任务全部结束后，平台自动唤醒父任务，并将已验收的产出汇总带回。
4. **防逃逸校验**：若 Agent 无法说清派生任务的归属，平台强制拒绝创建，避免游离任务导致父任务陷入无限等待。

### 4. 沿任务链的上下文召回（Chain of Recall）

任务链本身构成了一张结构化的引用图，边是真实的工作协同关系：

- 追溯两周前决策的线索在第二版批注里；
- 原始技术证据在上游子任务的失败日志里；
- 业务约束在最初发起人员的单句答复里。

Agent 不需要长程记忆全部细节，只需沿着 Quest 引用链“按图索骥”，逐跳展开相关节点。

### 5. MDC（Meta-Dance-Context）文件接口

彻底摒弃“每次唤醒把所有成员、历史、动态全量推入上下文”的推式思维，转向**从推到拉**：

- 每次唤醒只编译出一个极简干净的初始窗口；
- 历史会话、任务责任状、教训偏好、知识页统一归置在结构化文件接口（如 `session/`, `quest/`, `memory/`, `knowledge/`, `skills/`）之后；
- Agent 根据需要自主查阅，结果可审计、可引用、跨模型完全可迁移。
