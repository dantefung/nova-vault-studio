# 极简 B2B 询盘站技术栈

> **B2B 站的成败不在技术选型，在「有没有搞清楚目标客户关心什么」。** 极简技术栈（无后台、零服务器成本）是这个判断成立后的自然结果，而不是前提。

## 一句话定义

| 层 | 选择 | 理由 |
|---|---|---|
| **站点** | 纯 HTML + CSS（或 Astro），**不搭管理后台** | 自己做站自己用，后台开发完平时根本不开 |
| **内容管理** | 需要客户自己改内容时才上 CMS（Emdash 等） | 场景决定，不是「站都要有后台」 |
| **线索** | 表单提交存库 + 询盘邮件里放 **visitor tracking** | 不做后台也能知道客户从哪来、看过哪些页 |
| **部署** | Cloudflare Pages / Workers | **服务器成本为零**，一年只花几十块域名费 |
| **方法沉淀** | 把验证过的做法写成技能包 | 下次做同类站直接调用 |

## 为什么「不搭后台」多数时候是对的

**判断依据是场景，不是潮流：**

- 自己做站自己用、不给别人外包 → 不搭（搭后台费劲不说，开发完根本不开）
- 客户明确要自己发博客、加页面 → 这种才需要 CMS

**但不做后台有个前提：线索必须可见。** 表单存库解决「收到没有」，邮件里塞访问轨迹追踪解决「是谁、从哪来、看过什么」——**这两件事加起来，等价于一个最小可用的线索后台。**

## 真正花时间的部分（占 90%）

| 阶段 | 具体动作 |
|---|---|
| 前期调研 | 跟业务反复沟通产品细节、**定目标采购商画像**、挨个研究竞品网站、分析搜索意图、规划整站关键词 |
| 结构先行 | **先搓一套 HTML 原型**（结构 + 每个页面的排版布局），原型定清楚再动手写代码 |
| 上线前 | 补齐 SEO / AEO 的结构化数据（Schema）、理顺内链结构、**每张图写清 alt** |
| 上线后 | 定期翻 GSC 和 GA4：买家搜哪些词进来、在哪跳出，按真实数据补内容 |

**「不懂产品就必须去问业务员」**——有些事只有跟业务员沟通才知道目标客户还有这群人用在这个场景中。

## 两条容易被忽略的技术细节

1. **图片 alt 必须写全**。**现在的 AI 搜索引擎在引用答案时，会直接抓取网页里的图片和视频。** alt 是给 AI 读的索引信息，不是给盲人读的替代文本。
2. **视频别塞进站里**。可以放视频，但大文件太占存储容量——传到外部平台再在页面里嵌链接。

## 失效模式

| 失效 | 表现 | 修法 |
|---|---|---|
| 只抄结构不留结构化数据 | 搜索与 AI 抓不到，自然没询盘 | 补 Schema、补内链 |
| 没调研目标客户关心什么 | 页面看着不错但没人问 | 跟业务员聊 + 研究竞品 + 分析搜索意图 |
| 直接写代码不搓原型 | 反复返工 | 先出 HTML 原型 |
| 第一版就做多语言 | AI 翻译小问题审查几遍，还漏掉非专业语种的语法错误 | **第一版先做英语，等数据出来让数据决定语言版本** |
| 没做外链就焦虑 | 内容扎实时外链不是前置条件 | 先把内容做扎实，外链拖到最后 |
