# Agent 的本质：用 Token 换架构

> Agent 是用更多成本（多轮推理 + 多次工具调用 + 更高延迟/Token），换开发与维护成本的下降（分支更少、扩展更快、长尾更适配）。

## 核心定义

Agent 是一种工程架构层面的优化，核心不是"更聪明"，而是把工程师在开发期显式写死的控制流（if/else、编排、异常处理），迁移到运行时由模型来决定（路由、工具选择、多轮尝试、失败重试、补槽追问、结果校验）。

## 关键洞察

1. **Agent vs Workflow 的核心取舍**：Workflow 在复杂度上升时面临分支爆炸 + 维护爆炸（三类不可穷举：工具/系统、意图组合、异常与边界），Agent 用 Token 成本换架构简洁度。

2. **Agent 不是"更聪明"，而是控制流迁移**——把开发期写死的 if/else 迁移到运行时由模型决定。这是 Agent 解决的根本问题。

3. **三年技术脉络**：ReAct（推理+行动框架）→ Function Calling（工具调用标准化）→ MCP（缓解工具爆炸的集成维护成本）→ Skills（SOP 沉淀提升稳定性）。每一步都在解决前一步的问题。

4. **2025 年工具调用可用性大幅提升**，但记忆模块仍是老大难问题。2026 年模型可能在这块突破。

## 技术栈演进

| 阶段 | 技术 | 解决的问题 |
|------|------|-----------|
| 2022 | ReAct | 推理+行动的循环框架 |
| 2023.06 | Function Calling | 工具调用标准化 |
| 2025 | MCP | 工具爆炸的集成维护成本（N×M → N+M） |
| 2025.10 | Skills | 工具调用稳定性提升（SOP 沉淀） |
