# 本地模型网关

> 「订阅即供应商」——把你已经付费的账号挂成模型来源，用一个本地网关把它们的模型汇成一张清单，再反代给任意 Agent。**它转卖的不是 token，是「你本来就有的额度」的调度权。**

## 一句话定义

| 要素 | 含义 | 典型实现 |
|---|---|---|
| **来源层** | 把「订阅账号」抽象成供应商 | ChatGPT Plus / Claude Pro / Copilot / Gemini Code Assist / SuperGrok / Antigravity，每个订阅可挂多账号 |
| **汇聚层** | 所有来源的模型汇成一张清单 | 任意 Agent 的模型下拉框里看到的是同一份菜单 |
| **协议层** | 在本地做接口方言互转 | 一个 `127.0.0.1:3425` 同时说 OpenAI / Anthropic / Gemini 格式，流式、工具调用、推理模式都不缺 |
| **调度层** | 决定「这次调用派哪个账号」 | 路由组：smart / order / rotate / usage / pace |
| **观测层** | 把不可见的成本与上下文摊开 | 费用/额度倒计时、上下文构成、会话列表与跨 Agent 接力 |

**网关本身不产生模型，它的全部价值在调度层与观测层。**

## 为什么这个形态成立

1. **订阅经济已经让「额度」成为最稀缺的资源**：各家按订阅周期发放额度，而多账号可以并行使用。**网关把「额度池」这一层从 Agent 工具里抽出来做统一调度。**
2. **接口方言是纯粹的形式问题**：Claude Code 说 Anthropic 腔、Codex 说 OpenAI 腔、Cursor 又另一套。本地网关做翻译后，**换 Agent 不用改模型配置，只要改 `base_url`**。
3. **额度用尽是「时机问题」而非「总量问题」**：不同账号的额度重置时间不同、有些额度窗口不用就作废。**路由策略（smart / pace）本质上是在管理「额度的时间分布」。**

## 三个容易被忽略的设计

### 一、上下文缓存会「钉住」账号

换账号 = 缓存作废 = 钱白花。所以路由不能只看额度，还要看**当前会话的缓存命中在哪个账号上**。**缓存命中率是路由目标，不是副作用。**

### 二、预热（开窗）比抢跑更重要

订阅额度常常有「启动后 N 小时有效」的窗口。**定时自动为每个账号开窗，等于把额度从「用得上才生效」变成「随时可用」**，这是纯粹的时间管理收益，跟模型能力无关。

### 三、意图路由 + 派单理由可见

先读懂请求想干嘛，再决定派谁；**并且每次派单的理由摆在页面上**。前者是决策质量，后者是**可审计性**——多账号并行时，「为什么这次用了这个号」必须能查。

## 观测层：真正稀缺的那块

| 观测项 | 暴露了什么 | 典型发现 |
|---|---|---|
| 费用与用量（按官方价估算） | token / 缓存读写 / 推理 / 调用次数 | 哪类调用在烧钱 |
| 额度窗口卡片 + 倒计时 | 什么时候用完 | 该切哪个号 |
| **上下文构成** | 提示词里有多少是工具定义、系统提示词、真实会话 | 实测 83% 工具定义 / 13% 系统提示词 / **2% 真实会话** |
| 会话评分与标签 | 这条会话稳不稳 | 起步轻 / 会压缩 / 不稳定 |
| 资源库 | MCP 服务器与技能装了哪些 | 是否真的落到了各 Agent 的目录里（符号链接） |

**上下文构成那一项是网关最有价值的产出**：它把「为什么我的 AI 会话这么烧 token」从玄学变成了可测量的事实——**工具目录才是隐形吞 token 的大户。**

## 失效模式

- **只做汇聚不做观测**：变成一个「多 key 拼接器」，用户看不出省在哪，也无法判断哪天该换号。
- **忽略缓存粘性**：路由策略只看额度余量，频繁切号 → 缓存反复失效，账单反而更高。
- **把网关当成额度倒卖**：一旦开始转卖订阅，就从工具变成了合规问题。**正确的边界是驱动自己已登录的账号。**
