# 多机多 Agent 远程控制

> 当一个人同时跑 6 个 Agent、管 9 台电脑，「远程」就不再是「连回家里那台机器」，而是两层独立的问题：**人怎么随时控制任意机器**，以及**机器之间怎么互相调用**。用一套工具同时解决两件事，往往哪件都做不好。

## 一句话定义

| 层 | 回答的问题 | 代表方案 | 失效后果 |
|---|---|---|---|
| **人控机** | 我在外面，怎么稳定操控任意一台主机？ | Vibe42 / T3 Code / Paseo / UU 远程 | 看不到哪个 Agent 还在跑、切终端费劲、移动网络断连 |
| **机连机** | 分散在多地的机器之间怎么互访？ | Tailscale 私有局域网 | Agent 无法挑空闲机器承接任务，显卡/模型无法跨机调用 |

**两层正交，不互相替代**：Vibe42 不依赖 Tailscale，Tailscale 也不解决人的操控体验。

## 为什么多 Agent 会把「远程」问题放大

单机的远程桌面只要解决「连上去」；多机多 Agent 还多出三件麻烦：

1. **状态可见性**：必须一眼看到哪个 Agent 还在跑、哪个已经干完——传统远程桌面根本不提供这个视图。
2. **会话连续性**：在书桌前聊了一半，出门掏手机要能接着聊，**不用把上下文重讲一遍**。
3. **非终端操作**：看 App 模拟器、点网页、查产物，纯终端方案不够用，得带远程桌面和文件浏览。

## 四款方案的实测取舍

| 方案 | 强项 | 短板 | 适用 |
|---|---|---|---|
| **UU 远程** | 免费、国内直连极稳 | 传统远程桌面设计，9 台机切终端费劲；看不到 Agent 状态 | 偶尔使用、设备少（搭配 8 美元套餐的 Vibe42 够用） |
| **Paseo**（开源） | 局域网统一管多主机很轻快 | 出门移动网络不稳需自建中继；9 机 + 多手机两两配对十几次 | 桌前、局域网场景 |
| **T3 Code** | 交互体验上乘；同会话切不同 Agent 顺手；手机端直接审批；遥测可用两个环境变量关掉 | 无自带远程桌面，非终端操作要切别的软件 | 短期交互体验优先 |
| **Vibe42**（付费） | 移动网络稳、端到端加密、统一账号跨端续接、自带远程桌面与文件浏览；Pro 25 美元支持 10 台 | 当前以终端为主，对普通用户门槛偏高 | 多机重度用户的主力方案 |

**关掉 T3 Code 遥测的两个环境变量**：`T3CODE_TELEMETRY_ENABLED=false`、`T3CODE_OTEL_SDK_DISABLED=true`。

## 一个可复用的架构判断

> 每层只解决自己的问题，别指望一个工具通吃。

- **人控机层**按「出门稳定性 + 会话续接 + 状态可见」选型，必要时付费。
- **机连机层**用 Tailscale 把跨地域机器组进私有局域网，让机器之间直接互访。
- 典型调度：美国云主机专跑 Claude（隔离防封号）、本地 Mac 跑多个 Agent、Windows 显卡机做渲染；组完内网后 Mac 可直接调 Win 显卡渲染、本地可互调云端 Claude，**甚至让 Agent 自己挑空闲机器承接并发任务**。

## 失效模式

| 失效 | 表现 | 修法 |
|---|---|---|
| 用传统远程桌面管多 Agent | 看不到任务状态，切机费劲 | 换带 Agent 状态视图的面板 |
| 用局域网方案出门办公 | 移动网络断连、要自建中继 | 人控机层选全球加密直连方案 |
| 期望一个工具搞定所有 | 纯终端方案看不了模拟器/网页 | 配一个带远程桌面的方案，按场景切换 |
| 把机器各自孤立 | 显卡、模型、空闲算力无法跨机调用 | Tailscale 组网，机器间直连 |
