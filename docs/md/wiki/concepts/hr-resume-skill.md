# hr-resume-skill

> 智能招聘场景的**自定义 Skill 三层架构** —— 把整个 HR 简历筛选流程封装为可复用的 Skill 文件，配合连接器 + 自动化实现端到端自动化。

## 一句话定义

`hr-resume-skill` = **技能（Skill）+ 连接器（Connector）+ 自动化（Automation）** 三层组合的招聘场景实现模式——把邮箱采集、简历解析、飞书存储、AI 评分、业务推送这一整套流程封装到一个 Skill 里，由桌面端 Agent（WorkBuddy 等）执行。

## 三层架构

| 层 | 作用 | 在 HR 场景的实现 |
|----|------|------------------|
| **技能（Skill）** | 把"做某事的完整步骤"写成 Skill 文件 | 把整个 HR 流程写到 `hr-resume` Skill 文件里 |
| **连接器（Connector）** | 与外部系统交互（飞书、邮箱等） | 邮箱连接器采集简历 + 飞书连接器读写多维表 |
| **自动化（Automation）** | 定时触发整个流程 | 每天早上 9 点自动检查邮箱 |

**三者叠加**：技能定义"怎么做" + 连接器完成"外部交互" + 自动化决定"何时做"。

## Skill 的处理流程

```
1. 读取邮箱附件
2. 结构化提取（按 JSON 模板）
3. 根据岗位名从飞书多维表拿评分标准 + 岗位描述
4. 简历评分 + 总结 + 面试问题生成
5. 写入飞书多维表
6. 得分 ≥ 8 分 → 自动推送到业务负责人
```

## 适用场景

不仅限于 HR 招聘。任何**结构化信息处理 + 规则驱动决策**的场景都可以用这套模式：

- 客服工单自动分类
- 简历筛选
- 财务发票审核
- 法务合同初筛
- 销售线索评分

## 关键设计原则

### 1. 字段名一致性

Skill 中的 JSON 提取字段名必须与飞书多维表列名**完全一致**，否则数据写入会出错。

### 2. 客观规则优先

把"业务负责人觉得 OK 不 OK"这种主观判断，转化为"分数 ≥ 8 分推送"的客观规则。

### 3. 容错性高于严密性

相对 Coze/Dify 的"步步对、格式错则后续全错"，Agent 风格更关注**最终意图达成**。

### 4. 渐进式落地

不要一次覆盖全流程。从高频 + 痛点切入，跑通核心环节再扩展。

## 评分标准设计

6 维评分框架（每个维度满分 10 分）：

| 维度 | 权重 |
|------|------|
| 学历匹配度 | 10% |
| 经验相关性 | **30%** |
| 技能契合度 | 10% |
| 项目深度 | **30%** |
| 稳定性指标 | 10% |
| 综合潜力 | 10% |

按权重加权后总分满分 10 分。**得分 ≥ 8 分自动推送业务负责人**。

## 持续校准机制

- **每周/月**：根据实际推送效果，调整评分标准、字段定义、阈值
- **典型问题**：某岗位推 10 份高分简历给业务负责人，只有 2 份符合要求 → **说明这个岗位的评分标准不合理**，要重新校准
