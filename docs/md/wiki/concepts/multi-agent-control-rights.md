# 多 Agent 控制权归属：三次反转

> 多 Agent 架构按“下一步做什么”的**决策权归属**排成一条控制权下沉路径：Master Agent（中心节点决策）→ 任务看板（决策编码进共享状态）→ Advisor（决策交还执行者）。架构选型不是组件数量的选择，而是**控制权与问题是否匹配**的选择。

## Key Points

- **四个组织问题归一为一个**：谁拆解任务、谁分配任务、谁判断完成、Agent 之间共享什么信息——四问最终都指向“系统里的控制权究竟放在哪里”。
- **切分应按上下文边界，而非职业标签**：“代码分析 Agent”“数据探索 Agent”比“后端 Agent”“数据库 Agent”更实用——前者描述了上下文与产出的边界，后者只是容易被提示词放大的职业想象。
- **看板模式的可靠性来自协作协议，不来自持久化**：把任务写进数据库不会自动变可靠；真正的难点是并发领取、崩溃回收、下游依赖解除与幂等提交。
- **Advisor 不接管任务也不代调工具**：它只在局部决策上提供第二意见，采纳权始终在执行 Agent 手里；代价是“何时问、问什么、给多少上下文”必须成为 Agent 自身能力。
- **大小模型协作靠三件套保证可解释**：输出协议、证据引用、失败回退——否则“大小模型接力”只是一次不可解释的随机传递。
- **每个架构都有适用带**：控制流清晰的中心编排适合固定审核链路；共享状态适合多任务高并行长耗时；按需咨询适合高不确定性但不值得预先编排的任务。

## Details

### 三种协作方式与控制权位置

| 维度 | Master Agent | 任务看板 | Advisor |
|---|---|---|---|
| **决策权位置** | 中心节点 | 共享状态 | 当前执行者 |
| **组织哲学** | “我告诉你做什么” | “你看看现在什么任务可以做” | “你自己推进，需要时我给你建议” |
| **调用方向** | 中心节点 → Worker | Agent 主动读看板领取 | 执行节点 → 咨询者 |
| **上下文归属** | Master 持有全局 | 看板持有共享状态 | 执行 Agent 持有完整上下文 |
| **可靠性来源** | 集中编排的确定性 | 状态机 + 租约 + 幂等 | 证据充分性与不确定性标注 |
| **代价** | Master 易膨胀成“超级 Agent” | 牺牲直观性，压力转移到一致性 | 咨询成本与采纳判断 |
| **适用场景** | 流程固定、依赖明确、需统一权限 | 任务多、并行高、耗时长、需断点恢复 | 不确定性高、但不宜预先编排 |

### 两个前提边界

**上下文边界**——比职业标签更有价值的切分：每个 Agent 负责一段上下文与一种信息压缩，而不是一个“岗位名”。

**模型边界**——大小模型不是上下级替代关系，而是通过 Agent 边界把**速度**与**质量**组合起来：

- 小模型负责“快”：批量扫描、字段提取、异常发现 → 压缩成结构化线索
- 大模型负责“深”：基于线索补上下文、比较方案、处理冲突、对最终结果负责

### 看板模式的任务状态机

```
PENDING → CLAIMED → RUNNING → SUCCEEDED
                        ↓
                   FAILED / RETRYING
```

配套四件套：**锁或租约**（并发领取）、**历史记录**（状态变化可追溯）、**稳定引用**（产出物传递，不塞进下一次提示词）、**幂等提交**（重复执行不产生额外副作用）。

租约到期后由其他 Worker 接手，配合有限重试只补做未完成批次——这是“从局部中断恢复、避免整轮重跑”的机制基础。

### 落地：中间件巡检的三层组合

| 层 | 承担者 | 职责边界 |
|---|---|---|
| 入口 | Master Agent | 只做**组件级路由**：提取组件 / 时间窗口 / 关注点 |
| 组件内 | Inspector Agent + Worker（看板） | 指标目录、目标发现、任务拆分、证据汇总、完整性检查 |
| 疑难 | RCA Advisor（按需咨询） | 只在关联指标难解释、原因分歧、需领域知识时介入 |

两个关键设计细节：

1. **入口的职责收窄**——Master Agent 不逐个跟踪分析批次，下层指标、工具与分组策略的变化留在组件巡检单元内。
2. **三种状态必须分开**——“当前异常”“窗口内已恢复”“数据不足”是三件不同的事。**没有数据的目标必须明确标注**，否则会形成“没有发现异常，所以一切正常”的误判。

 Advisor 超时或失败时仍输出已有证据支持的基础结论，可自行解释的问题直接成稿——把咨询成本控制住。
