# AI Coding 方法论：从自然语言编程到代码搬运工

> AI 编程不会消灭程序员，而是进入「自然语言编程」时代——提示词即是代码，AI 消灭的是只会工具使用的「代码搬运工」。

## 核心定义

**AI Coding** 是以 AI 模型作为"结对编程者"的软件开发范式。开发者（产品经理/非技术角色）以自然语言向 AI 描述需求，AI 生成代码、修复 bug、迭代优化。核心变化是**控制流从显式编码迁移到自然语言提示**——"提示词的编写就是自然语言编程"。

## 关键洞察

1. **自然语言编程 ≠ 消灭程序员**：真实复杂 AI 项目里，核心代码约 1 万行，提示词大几十万行。提示词编写本身就是编程，只是换了一种语言。AI 消灭的是只会套用工具的"代码搬运工"。

2. **AI Coding 的六步方法论闭环**：需求拆解 → 架构设计 → 提示词编写 → 迭代开发 → 前后端集成 → 部署上线。每一步 AI 都参与，但每一步都需要人的判断和上下文。

3. **"推翻重来几乎零成本"**：AI 代码质量下降时，从头再生成往往比修补更好——因为你的需求描述能力提升了，第二遍更清晰。这是与传统开发最大的差异之一。

4. **AI 编程的边界来自训练数据**：AI 擅长 20% 常用的增删查改（覆盖 80% 市场问题），但对芯片编程、硬件编程、自研 DSL 等小众领域无力——因为训练数据极度匮乏，ROI 过低导致基模没兴趣投入。

## AI Coding 方法论全景

### 六步流程

| 阶段 | 核心任务 | 关键技巧 |
|------|---------|---------|
| 需求拆解 | 将业务梳理为功能模块 | 提供上下文+非功能需求（规模/数据量） |
| 架构设计 | 确定页面/服务/数据存储 | 让 AI 检查完整性、生成 API 设计 |
| 提示词编写 | 用自然语言描述功能 | 清晰明确、有示例、有数据格式 |
| 迭代开发 | 测试→发现问题→反馈 AI | 一次只改一处、勇于推翻重来 |
| 前后端集成 | 确保接口/数据格式一致 | 同一上下文生成、CORS 贴 AI 修 |
| 部署上线 | 云服务/静态托管 | 把平台地址给 AI，让它读文档 |

### 调试技巧

- 保持每次修改的单一性
- 勇于推翻重来（AI 推倒重来几乎零成本）
- 保存每个阶段的代码以便回退

## AI 编程工具选择

| 维度 | 说明 | 选择建议 |
|------|------|---------|
| 可用性 | 插件 vs 独立 IDE | 非专业用户选 Cursor（当智能体用）；专业用户选 Copilot |
| 代码质量 | 模型能力决定 | ChatGPT/Claude 最强，Gemini 强势追赶 |
| 本地化 | 中文支持 | Trae 对中文注释/变量名处理更好 |
| 稳定性 | 工具稳定性+代码一致性 | 无脑选大厂，不担心突然关门 |
| 集成能力 | 与工作流/工具链结合 | Copilot 集成最广，Cursor/Trae 内聚强 |

## 局限性

| 问题 | 原因 | 应对 |
|------|------|------|
| 小众领域无力 | 训练数据极少 | 专门微调（但 ROI 低） |
| 模型本质缺陷 | 概率堆积，CoT 效果有限 | 错误连锁，难自行纠正 |
| 长尾问题不覆盖 | 二八原则，20% 解决 80% | 基模没兴趣，需要领域微调 |
