## 多 Agent 协作冲突的教训

多 agent 同时改一份项目文件如何避免打架，这是困扰我很久的问题。虽然我也懂 worktree、branch、PR 什么的，也经常发给 AI 用，但由于长期跑三十多个终端任务，还真老是忘记完全遵循那些用法。

如果一个任务只针对一个项目还好，Codex 可以跑很久安全顺利完成。但是同一个项目多个任务分支有冲突，甚至可能 main 更新太慢，就老是出现多个 agent 任务窗口信息更新不及时老打架。

这对正规程序员来说当然是个很简单的常识，但是我却一直跑了很久歧途、搞了很多返工才知道：

- **浏览器锁**：这样不会一次性跑几十个测试把电脑干崩
- **多窗口权限分离**：分唯一主 main 管理者和多 worker 协作者，后者只允许做 branch/worktree 分任务，就相当于主管和员工的方法权限不同
- **AI 习惯分析**：多把自己日常的困扰和遇到问题发给 AI，让它结合电脑所有软件运行日志来分析你的习惯，多跑几次重复着看就记住最佳做法

> 注：这里的 AI/Agent 只指代 Codex CLI

我现在非常习惯终端里面跑任务，因为可以多个终端软件窗口同时打开，这样均分软件内存降低单一压力避免卡死崩溃，而且有任何想法都可以快速拉电脑文件和大量复制粘贴分析干活。
