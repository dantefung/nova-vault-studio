### 今天踩到的六个坑

1. **脚本会把带 `###` 小标题的文章压扁**——正文首行被拼成一整段超长行，后面又跟一份正常分段版本，等于内容重复。归档时应删掉被压扁的那行，保留分段版
2. **扁平表格需要手工重建**——脚本会把 Markdown 表格拆成一列一行的散行。判定信号是"表格首行内容在文中重复出现两次"。今天重建了 5 张：Skill 三形态能力边界、sub-agent 七维对比、三条路径选型、状态四文件、需求线八活动
3. **tmpfiles.org 的下载不是直链**——直接 `curl` 只会拿到 HTML 壳页面。真实下载地址需从页面上的 Download 链接取 `/dl/{token}/{id}/{name}` 形式，再 curl 才是文件本体
4. **fetch_weixin.py 偶发超时**——报 `Page.wait_for_selector: Timeout 15000ms exceeded`，等 `#js_content` 可见失败。这是网络抖动不是文章失效，**直接重试即可**（同一 URL 第二次跑就成功拿到 21KB 正文）。备用手段：带微信 UA 的 `curl` 拿原始 HTML（约 3.7MB，正文内嵌在 `#js_content`），再从 `var msg_title` 取标题
5. **批量验活时 000 不等于站点失效**——`curl` 返回 000 且 `getent hosts` 解析到 `198.18.0.x`，说明命中了沙箱代理的拦截段（RFC 2544 保留测试网段），不是域名挂了。判断依据：DNS 能正常解析 = 域名真实存在；政务站点另有反爬（412/521），浏览器正常访问不受影响
6. **内置 fetch_feishu.py 会丢掉飞书文档的表格和图片**——脚本只处理了 text/heading/bullet/ordered/code/quote/todo 几种 block_type，**table(31)、table_cell(32)、image(27)、callout(19) 全部渲染成空代码块或 `feishu-image://` 占位符**，正文看着完整但关键表格内容全部丢失。**正确做法是自己调 API**：
   - `GET /docx/v1/documents/{doc_id}/blocks` 拿原始 blocks（分页 page_size=500）
   - 表格：`table.property` 有 `column_size`/`row_size`/`cells`，`cells` 数组是**行优先**顺序，第 `r*cols+c` 个即第 r 行第 c 列；每个 cell 是 type 32，其 `children` 指向真正的文本块
   - 图片：`GET /drive/v1/medias/{image.token}/download` 直接下二进制
   - 有序列表：`ordered.style.sequence` 字段可能是字符串 `"auto"`，不能直接当序号用，要自己计数
   - 图片下载后建议改 ASCII 文件名——飞书 caption 常含中文标点和空格，URL 里要编码很容易出错

## 五、今天的观察

今天 17 篇里有 8 篇讲 Agent 架构，观点却互相拉扯：

- Anthropic 工程博客说「一个 Agent 往往就够」
