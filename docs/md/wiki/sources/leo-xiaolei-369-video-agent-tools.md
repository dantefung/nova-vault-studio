# 369 个开源仓库清单：AI Agent 视频生成、自动化剪辑与代码动效渲染

> 「我刻意打破了常规的 **GitHub 高星滤镜**——星数并不能完全代表真实的生产力。一些刚建库、甚至只有个位数 Star 的项目，往往正在解决极为刁钻、具体的行业痛点。」本文收录覆盖视频/动效产出、专供 Agent 调用、有完整 README 的 369 个仓库。

## 收录的三条底线

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **必须围绕视频或动效产出**。纯 3D 网页不收录；必须是代码渲染出画面，且能够交给 Agent 重做的成片或提示词 | 排除「看着炫但不可复用」的项目 |
| 2 | **必须是专供 Agent 调用的工具**。包含 Skill、插件、MCP，或明确为 Claude Code、Codex 等 Agent 打造的工具包 | 排除「人用工具」——本清单面向 Agent 工作流 |

## 一、四大现象级当红框架

> 得益于 Claude Opus 5.5、GPT-6 Astra 等底层大模型能力的跃升，有四个项目在近期脱颖而出。

### 1. lemo-opuscar：彻底抛弃视频大模型的风格引擎

**lemomo-ai/lemo-opuscar（8,322 星）**——不是 Awesome 资源清单，而是一套开箱即用的**视觉风格引擎**。

- 内置 **59 种**针对 Claude Opus 5.5 深度调优的代码影片风格，每种标配风格提示词与纯代码渲染样片；
- **全程无需调用任何昂贵的 AI 视频生成模型**；
- 代表作「OPUSCAR 98」是一支 **6 分 31 秒**的样片，一次性展现 **98 种**奥斯卡级别的 2D、2.5D 与 3D 视觉风格；
- 近期新增 8 种真实素材纪录片剪辑风格，支持「将现有风格改造为专属资产」，并打通 Claude 插件市场一键安装。

> 「如果你需要现成的高级视觉方向，又想保留代码级修改的自由度，这是目前的**绝对首选**。」

### 2. huashu-art-motion：艺术风格与解说语法的完美封装

**alchaincyf/huashu-art-motion（5,418 星）**——开发者「花叔」开源的艺术动画 Skill。

- 把 **36 种艺术风格 + 9 种解说语法 + 8 种参数化片段**整合进一套完整制作方法论；
- 仓库样片含 **65 秒**的马里奥关卡重现，以及 **98 秒**、纯代码合成配乐的 Clawd 博物馆夜巡动画。

> 「与 lemo-opuscar 偏向『提供素材与模板』不同，huashu-art-motion 解决了『**如何用特定的视觉语法去讲解一段内容**』的核心痛点。」

### 3. huashu-motion：商业发布片与「指哪打哪」的浏览器可视化修改

**alchaincyf/huashu-motion（1,766 星）**——切入商业产品发布片的自动化生产。

Agent 工作流：**读取产品信息 → 给出三个商业策划方向 → 确认后自动写出整片 → 使用 ABC 记谱法在本机完成合成音色或真实乐器采样的配乐**。

**杀手锏是浏览器内可视化修改**：

> 「在制作商业宣传片时，第一版往往只是草稿。通过这个工具，你在预览时**只需按下 C 键，点击画面中的任意一帧并输入修改意见**，Agent 就能像外科手术一样精准调整该处细节。」

### 4. sweety-handdraw-video：CodeX 友好的手绘口播全自动流水线

**threerocks/sweety-handdraw-video（903 星，v1.4.1）**。

与其他强依赖 Claude Opus 5.5 的工具不同，**它对 CodeX 极其友好**，同时兼容 Workbuddy 和 Opus 5.5，并已在 Workbuddy 技能市场上架。

**只需输入一个主题、文章或定稿**，Agent 自动包揽口播稿、分镜与插画设计；随后本地渲染引擎接手**精准描线、自动上色、按笔顺生成手写字**，并实现**画面与配音的帧级对齐**。

底层是拟人化绘制引擎 + 原生集成的 **VoxCPM 2** 语音合成。

> 「这是目前做**知识科普、文章可视化**最高效的可复用闭环流水线。」

## 二、场景深挖：垂直领域的硬核项目

> 「除了四大天王，我还从 **300 多个库**中筛选出了一批在垂直领域解决痛点的优秀方案。」

### 自动化剪辑与人机协同

| 项目 | 能力 |
|---|---|
| **browser-use/video-use** | 全自动转录剪辑：把原始素材扔进文件夹，Agent 依赖逐词转录自动下刀，剔除语气词和停顿，完成字幕与 FFmpeg 调色，动效交给 HyperFrames 或 Remotion（需自备 ElevenLabs API Key）。**注意：模型不直接看画面，完全基于文本逻辑剪辑** |
| **OpenChatCut / BaoCut** | 机器剪完后需要人类介入时间线微调时的最佳选择 |
| **fragua（11 星）** | 跑在本地，**无需 API Key** 即可用 FFmpeg 完成竖屏去静音和烧录字幕 |
| **cutloupe（0 星黑马）** | 提供 MCP 和可视化时间线，通过 `look` 命令把真实渲染帧送回给模型，尝试解决「**让模型看见自己剪的画面**」这一行业难题 |

### 代码直出成片与结构化镜头卡

| 项目 | 能力 |
|---|---|
| **awesome-opus5-5-videos** | 收录高达 **703 条** Opus 5.5 的代码成片提示词 |
| **video-shotcraft** | 专为 Remotion 商业片打造，含 **152 张**结构化镜头配方卡和 **209 个**动效预览 |
| **lovisdotio/motion2code** | 将现有动效视频**逆向重建**为内联 SVG 和 GSAP 时间线，支持精确定位到任意帧与原片对照 |

## 三、这份清单最值得学的一点：打破高星滤镜

> 「我刻意打破了常规的『GitHub 高星滤镜』——因为我发现，**星数并不能完全代表真实的生产力**。在这个日新月异的赛道里，一些刚刚建库、甚至只有个位数 Star 的项目，往往正在解决极为刁钻、具体的行业痛点。」

清单里的低星项目恰好验证了这一点：

| 项目 | 星数 | 解决的问题 |
|---|---|---|
| `cutloupe` | **0** | 让模型看见自己剪的画面 |
| `mondo-music-video` | **9** | 音乐视频工作室基础设施 |
| `fragua` | **11** | 本地无 API Key 的竖屏剪辑 |

而星数最高的那几个（lemo-opuscar 8,322 / huashu-art-motion 5,418），解决的是**已被验证的通用需求**。

> **两条路线的判据不同**：高星项目解决的是「已经被很多人验证过的通用需求」；低星项目解决的是「还没被验证但非常具体的地带」。做内容生产时，**通用需求用高星项目保底，垂直地带用低星项目卡位**。
