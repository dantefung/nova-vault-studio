# 南晚 Nanwan（@snwiki238337）：自己构建 Agent 至少要满足的 12 条——从确定性边界到沙箱隔离

> 生产级 Agent 的 12 条工程清单：确定性边界（能用代码/正则/状态机/硬规则解决的逻辑先写死）、轻量级路由（顶层只做意图分类与分发）、上下文隔离、主动获取上下文（信息不全先调工具查配置读文件检索历史再执行）、扁平少参的工具接口设计、结构化报错回传让模型自修正、显式状态管理（状态图或共享存储而非 Agent 之间聊天传话）、并发与过期状态拦截（版本号校验防旧结果覆盖）、循环上限与预算控制、人类审批节点（删除数据/改生产配置/发邮件/付款前暂停）、断点续跑与持久化、沙箱环境隔离。核心判据是：不要只衡量 Agent 能否完成任务，还要衡量它在工具报错、指令模糊和并发执行时能否以可接受的成本与延迟持续可靠地完成任务。

<!-- more -->

如果你正在去构建你自己的 Agent，至少需要完成这些：

1. 确定性边界：在调用大模型之前，先把能用代码、正则表达式、状态机和硬规则解决的逻辑写死。

2. 轻量级路由：让顶层路由只负责意图分类和任务分发。不要在路由层塞入具体的业务逻辑和长上下文。

3. 上下文隔离：把不同的子任务拆分到独立的上下文窗口中执行，防止多个数据源和指令混在一起互相干扰。

4. 主动获取上下文：不要在信息不全时直接让模型生成答案。让 Agent 先调用工具去查配置、读文件和检索历史状态，再开始执行任务。

5. 工具接口设计：为模型专门封装扁平、参数少、语义明确的工具，而不是直接把复杂的后端接口暴露给模型。

6. 结构化报错回传：捕获工具调用的异常、超时和参数错误，把具体的错误原因返回给模型，让它自己修正参数重试。

7. 显式状态管理：使用状态图或共享存储来记录任务进度，不要靠多个 Agent 在对话框里来回聊天传递信息。

8. 并发与过期状态拦截：当计划发生改变时，及时取消正在运行的旧任务，并校验返回数据的版本号，防止旧结果覆盖新状态。

9. 循环上限与预算控制：严格限制单次任务的最大推理步数、工具调用次数和 Token 消耗上限，防止死循环把账单跑穿。

10. 人类审批节点：在执行删除数据、修改生产配置、发邮件或付款等不可逆操作前，暂停任务并等待人工确认。

11. 断点续跑与持久化：在每一步执行后保存状态快照。当网络中断或服务重启时，从上一步恢复，而不是从头再跑一遍。

12. 沙箱环境隔离：在受限的容器或虚拟环境中运行模型生成的代码和命令，严格限制文件系统与网络访问权限。

一个 Agent 在演示 Demo 中看起来可以令人惊艳，但在生产环境中依然会惨败。

不要只去衡量你的 Agent 能不能完成任务。

还要衡量它在工具报错、指令模糊和并发执行时，能不能以可接受的成本和延迟，持续、可靠地完成任务。

你的模型会变，你的框架会变，你的系统基础设施也应该不断完善。
