# Huashu-Excel 正式发布

作者：花叔（alchaincyf），公众号，2026-08-24 发布

## 背景

花叔从美团离职后，基于做运营时攒下的数据处理经验，把对 agent 能力的理解做成了 `huashu-excel` skill，MIT 协议开源。

仓库：`https://github.com/alchaincyf/huashu-excel`

## 八步工作流程

体检 → 清洗 → 对齐 → 分析 → 对账 → 交付 → 验图 → 质控

按需走：查一个数就直接查，要报告才全走。

### 三步重点

1. **体检**：用 `openpyxl` 读原始单元格，保留合并单元格/格式/原始类型信息，先定位表头、混入的小计行、异常列。用 `pd.read_excel()` 直接读的表格，月度总额可能比真值高出 161%（零报错零警告）
2. **对账**：拿清洗后的明细自求和，去对表内自带的合计行。揪出过差 10 块的错（表内小计 6,490,430 vs 明细 6,490,420），相对误差 0.00%，肉眼发现不了
3. **质控**：另派一个未参与创作的 agent 从原始数据重算，专门拆台——分析窗口是否挑出来的、外部基准分母是否对齐、「已剔除某某偏差」是否真做了

## 压测结果（10 份真实数据，独立 agent 跑全流程）

| 数据集 | 规模 | 核心发现 |
|--------|------|---------|
| 纽约市 311 住房工单 | 159,275 条 | 辛普森悖论：处理时长涨是因为品类结构变了，同口径 13 品类中 12 个在变快；32.4% 工单以"没进门"结案，达成率 86.5% vs 49.5% |
| 英国电商交易明细 | 106 万行 | 表面营收增长是新品补出来的：3,145 个老 SKU 营收 -12.9%，651 个新品带来 £2.05M；一万多个脏发票号逐个查出取消单/坏账/Amazon 渠道上线时点 |
| 纽约市市政预算 | 21 万行 | 109 亿不是超支，是记账时点；内部校验全绿的数字整体错了一个财年——外部基准校验救回来 |
| 薪酬调查问卷 | 28,225 份 | 11 种货币混一列、1,228 种行业写法；最高年薪 1.02 亿当录入错误（Twyman's Law）；22,918 份美元样本入分析，结论自带证明边界 |

## 设计逻辑

1. **AI 算错不报错**：流程里的对账、验图、独立质控给不存在的报错机制补位
2. **角色激发**（灵感来自 Anthropic AI 心理学研究）：第一句话「如果世界上最好的数据分析能力可以被装进一个文件，那就是你」，依次成为领域专家→数据分析师→战略顾问→视觉设计师→前端工程师→质控
3. **Test-time scaling**：八步流程强制 agent 多思考多规划，每跑完脚本要回答「看到了什么、意味着什么、下一步查什么」才准往下走
4. **脚本是眼睛不是大脑**：内置体检/清洗/陷阱扫描/对账/验图/验 Word 脚本，但遇到脚本处理不了的结构，agent 该自己写代码
5. **统计讲究**：默认给中位数和五数概括（Tukey 抗差统计），类别超 3 个拒画饼图，柱形图数值轴强制从 0 开始，双轴图禁掉
6. **图表用内联 SVG 手画**：洛伦兹曲线、双峰分布、事件研究图、价量分解、哑铃图、小倍数图——离线单开即看

## 兼容

不挑 agent：Claude Code、Codex、WorkBuddy、豆包、DeepSeek Harness 等均可。环境探测后自适应：能跑 Python 就跑脚本，能派子任务就并行，连脚本都跑不了就告诉你在 Excel 里怎么点。核心依赖仅 `openpyxl`，处理 CSV 纯标准库，验图装 `playwright` 更全。

安装：clone 到 skill 目录，或直接丢仓库链接给 agent 说「读一下这个仓库的 SKILL.md，然后帮我分析这份表。」
