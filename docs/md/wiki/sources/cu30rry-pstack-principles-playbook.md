# cu30rry：pstack 的精髓——Principles 先行、Playbook 后行

> 引述 nogu 的分析：pstack 秀逸之处在于**把判断基准放在 Principles 里**，不在单一手步骤里定义所有判断；「Guard the Context window」原则一以贯之，/poteto-mode 只读目录与启动条件、不读全部步骤书，原则同理，所以 Agent 迷茫时也能被导向高质量方向；每个 Skill 小而严。启发：对 Agent 说「借鉴 pstack」这种粗略指令也能达到 90 分；剩下 10 分需要理解 pstack 思想与工程专业知识。作者提及自己持续更新的免费解说本已超 100 万字——**这句自我推广已按去广告规则删除**。

<!-- more -->

pstack が秀逸なのは、手順の中での判断の基準を Principles で持たせている点で、1つの手順で、判断をすべて定義・設計していない点だ

「Guard the Context window」という原則があるが、一貫してそれを守っていて、/poteto-mode でも手順書をすべて読み込むわけではなく、一覧と起動条件のみ定義しているし、原則も同じだ

だから、エージェントが判断に迷ったときも質の高い方向に誘導できる

それに、各 Skill はコンパクトながら厳格なのも忘れてはいけない

要するに、全体も詳細も作り込みが素晴らしいということで、「pstackの何かを取り入れて」と自分たちのエージェントに雑に依頼するだけでも、普通に洗練されて、90 点くらいまでは行ける

残りの10 点までいきたければ、pstackとその考え方を理解したり、エンジニアリングなど専門知識が必要になるので、ぜひ私の本を読んでみてほしい！

もちろん、最新のpstackに合わせて、いつも更新しているし、今では100 万字を超えた！

そして、日本、いや世界で有数の解説本だと思っているが、無料なのも忘れないでほしい！！！！

AI 駆動開発に関する違和感として、Playbookのような手順が先行している印象

でも、従来のエンジニアリングはPrinciplesが存在して、その上でPlaybookがあるような構造になっていた理解をしている

なので、pstackは、その２つをスキル化していることが重要なので真似すべきポイントはここだと感じた https://x.com/_nogu66/status/2125430781137055823
