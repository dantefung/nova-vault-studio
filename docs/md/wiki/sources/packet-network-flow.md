# 跟着一个数据包，看懂整个网络传输过程

> 数据从你的应用出发，经过 TCP/IP 四层，每经过一层就被套上一层「外壳」——这就是封装。每一层的「头部」只有那一层的设备才会读它。

![数据包传输过程](images/packet-network-flow/001.jpeg)

## 什么是数据包？

数据包（Packet），就是网络里传输数据的基本单位。但它不是把数据整块发出去，而是切成一块一块，每块单独打包传输，到达目的地再重新拼起来。

**为什么要切块？** 分包传输是互联网的基本设计哲学——共享线路、独立路径、局部重传，这三点让网络效率极大提升。

## 封装：数据是怎么被「套娃」的？

![封装过程](images/packet-network-flow/002.jpeg)

数据从应用（比如浏览器）出发，要经过 TCP/IP 四层，每经过一层，就被套上一层「外壳」（Header，头部）。

> 每一层的「头部」就像信封上的地址标签，只有那一层的设备才会读它。路由器只看 IP 头，不关心 TCP 头里写了什么。

## 数据包的「环球旅行」全程

![数据包旅程](images/packet-network-flow/003.jpeg)

以在北京用浏览器访问一个上海服务器为例：

1. **应用层**：浏览器生成 HTTP 请求（比如 GET /）
2. **传输层**：加 TCP 头（源端口、目的端口、序列号等），形成「段」
3. **网络层**：加 IP 头（源 IP、目的 IP），形成「包」
4. **链路层**：加以太网帧头（源 MAC、目的 MAC），形成「帧」
5. **物理层**：转换成比特流，通过网线/光纤传输

**关键细节**：路由器只拆到第 3 层（网络层），它读完 IP 头知道该往哪转发，然后重新封装一个新帧发出去。它根本不知道你在看什么网页，也不在乎 TCP 里写了什么——这也是互联网「各层各司其职」的体现。

## 数据包头部里到底有什么？

![数据包头部结构](images/packet-network-flow/004.jpeg)

每一层加的「头部」就像快递单，里面记录的信息各有侧重：
- **TCP 头**：源端口、目的端口、序列号、确认号、窗口大小、校验和
- **IP 头**：版本、TTL、源 IP、目的 IP、协议
- **以太网帧头**：源 MAC、目的 MAC、类型

## 终极总结：三句话记住全部

![总结图](images/packet-network-flow/005.jpeg)

1. 数据不是整块发的，是切成块、每块单独打包传输、到目的地重新拼起来的
2. 封装就是一层一层套外壳，解封就一层一层剥外壳
3. 每一层只看自己那一层的头部，路由器不看 TCP 头，网卡不看 IP 头
