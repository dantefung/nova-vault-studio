## 第 1 章：贴图号是什么，和文章号有什么区别

1. 1 贴图号是什么

贴图号用的是同一个微信公众号，但走的是订阅号后台里专门的**“贴图”创作方式**，不是平常写长文章的那种图文。

每条贴图很简单，只有两样东西：

| 组成部分 | 要求 |
|---|---|
| 图片 | 至少 4 张，3:4 竖屏 |
| 文案 | 1 段，250 字以内的中文 |

用户在手机上刷到贴图，第一眼看的是图，第二眼看的是那段短文案。所以贴图号的打法就是：图要好看、文案要短而准。

![](../images/ryan-muse-wechat-tietu-step-by-step-guide/002.webp)

1. 2 和文章号的区别

| 对比项 | 文章号（图文） | 贴图号 |
|---|---|---|
| 内容形态 | 长文章 + 多张配图 | 4 张竖屏图 + 1 段短文案 |
| 每条工作量 | 大，要排版全文 | 小，重点是选话题 + 做图 + 写短文案 |
| 更新频率 | 一天 1 篇就不少 | 一天 15 条，每小时 1 条 |
| 适合内容 | 教程、实操、长干货 | AI 热点快讯、轻量解读 |
| 发表方式 | 一样：Muse 备草稿，你手机发表 | 一样：Muse 备草稿，你手机发表 |

两套内容共用同一个公众号、同一个账号登录，但草稿类型不同，不要把贴图当成图文来存，也不要把图文当成贴图来存，后面第 7 章会讲怎么区分和核查。

1. 3 一句话全流程图

```
每小时选 1 条最热 AI 信息
↓
精选 + 润色重写 → 250 字以内中文文案
↓
按文案选风格 → 生成 4 张 9:16 竖屏图
↓
文案 + 图片 → 只存入“贴图草稿”（不发表）
↓
你在手机端公众号助手打开草稿 → 预览
↓
没问题 → 你自己点“发表”
```

记住：Muse 的活到“存入草稿”就停了，发表永远是你手动点的。

## 第 2 章：准备清单

开始之前，先把下面 5 样准备好，缺一样都先补齐，不要边做边找。

2. 1 一个微信公众号

- 和文章号是同一个公众号就行，不用新注册一个。
- 确保你能登录这个公众号后台，能在手机端公众号助手里看到草稿箱。
- 如果账号退出了，后面会给登录二维码，你扫码登录即可，不要让 Muse 帮你代扫、代验证。

2. 2 一个能用 Muse 的电脑

- Muse 负责每小时选话题、写文案、生成图片、存草稿。
- 电脑要能联网，能打开公众号后台。
- 教程里的本地文件都存在这台电脑上，换电脑要重新确认路径和登录状态。

2. 3 一个固定中国 SOCKS5 代理 + 本地转发

公众号后台登录必须走固定代理，不能直连。

你需要准备：

| 项目 | 填什么 |
|---|---|
| 代理类型 | SOCKS5 |
| 代理地址 | `<你的代理地址>` |
| 代理端口 | `<你的代理端口>` |
| 代理账号 | `<你的代理账号>` |
| 代理密码 | `<你的代理密码>` |
| 本地转发地址 | `127.0.0.1:1080`（固定不变） |

规则：

- 代理只用于 mp.weixin.qq.com（公众号后台），不用于其他网站。
- 本地转发跑起来后，所有公众号操作都走 127.0.0.1:1080，不直连。
- 凭据不要写进教程、不要写进聊天记录的截图里、不要发给别人。 教程里只用占位符。
- 如果转发掉了（后面第 11 章会讲怎么检查），先重启转发，再继续存草稿。

小白理解：代理就像一条固定通道，Muse 必须走这条通道去公众号后台，不能翻墙走别的路，也不能裸奔直连。

2. 4 AI 信息源：GitHub 开源汇总

每小时选话题的信息源，是用户提供的 GitHub 开源 AI 信息源汇总，主要包括：

- Horizon
- ai-news-brief
- AI-Search
- ai-news-radar
- Awesome-AISourceHub
- awesome-ai-sources
- ai-news-aggregator
- ai-rss-feeds
- RSSHub
- 以及汇总里的其他 AI 新闻聚合 / RSS 项目

用法很简单：每小时从这些信息源 + 实时新闻搜索里，选当时最热门的 1 条 AI 信息。 不要自己编话题，不要拿昨天的旧闻当今天的热点。

选话题的优先级：

1. 当天刚发布的大模型 / 大厂发布 / 重要开源；
2. 影响面广、大家都在讨论的 AI 事件；
3. 有明确来源、可核对的消息（官方发布、知名媒体报道）。

避坑：不要选来源不明的小道消息，不要编造价格、链接、发布时间。

2. 5 图片风格指南

图片风格指南是一份整理好的开源风格参考，核心是两个方向，每条贴图只选其中一种，不要混搭：

| 方向 | 什么时候用 | 感觉 |
|---|---|---|
| 1. 漂亮唯美精美梦幻（优先） | 绝大多数情况，尤其重大发布、技术突破 | 一眼就爱上，精美、梦幻、有高级感 |
| 2. 幽默俏皮搞笑 | 轻松话题、meme、卡通、搞笑梗 | 俏皮、可爱、让人笑出来 |

参考来源（只记名字，不用背链接，Muse 知道怎么用）：

- 漂亮方向：aesthetics、handraw-style、ComfyUI-Style-Prompts-Collection（Ethereal / Dreamy / Crystal Dreams / Nebula Dreams 等）、style-reference（dreamy / ethereal / soft focus 等）、awesome-ai-image-prompts、illustration-style-samples。
- 幽默方向：meme 生成类、卡通插画类、照片转卡通类项目。

第 6 章会讲具体怎么按文案选风格、怎么写提示词。

## 第 3 章：分工与边界（先读这章，别越界）

这是全教程最重要的一章。把边界记牢，后面就不会出事。

3. 1 Muse 负责什么

- 每小时选 1 条最热门 AI 信息；
- 精选 + 润色重写为 250 字以内中文文案；
- 按文案选风格，生成至少 4 张 9:16 竖屏图；
- 把文案 + 图片存入贴图草稿；
- 存完核查草稿箱，告诉你草稿 ID 和核查结果；
- 出问题时停下、说清原因、提醒你。

3. 2 你负责什么

- 在手机端公众号助手打开草稿，预览；
- 确认图片、文案、排版都没有问题后，自己点“发表”；
- 发表时如果要求扫码验证，你当场扫码；
- 手动处理测试草稿、重复草稿（见 3.4）；
- 代理转发掉了、账号退出了，按提示重启 / 扫码登录。

3. 3 绝对不做的事

| 禁止事项 | 为什么 |
|---|---|
| 自动化直接发表贴图 | 发表必须由你确认，Muse 只备草稿 |
| 自动化代扫验证二维码 | 验证必须你本人当场操作 |
| 把原稿 / 文案改写成编造内容 | 文案只能精选 + 润色重写，不编价格 / 链接 / 事实 |
| 把代理凭据写进教程 / 记忆 / 文件 | 凭据只用占位符，绝不明文保存 |
| 直连公众号后台 | 必须全程走固定代理经本地转发 |
| 动测试草稿 | 测试草稿绝不动、绝不删、绝不发布 |

3. 4 测试草稿和重复草稿怎么处理

草稿箱里可能有几篇不是你当天要发的草稿，处理原则是：自动化一律不碰，只由你自己核对。

- 测试草稿：标题类似“测试段落，仅用于探测保存接口，完成后删除”这类，是以前探测接口留下的。绝不发布， 由你在自己浏览器 / 手机端手动删除。
- 重复草稿：标题和某篇正式文章完全相同、但不是本次创建的那篇。自动化不删除， 由你在自己浏览器核对来源后再决定是否删除。
- 正式草稿：你当天要发的贴图和文章，正常预览发表即可。

一句话：分不清的草稿，先别动，先核对。

## 第 5 章：文案怎么写（250 字以内）

5. 1 文案标准

- 长度：250 字以内（含标点与空格，不含标题 / 来源行）。写完必须数一遍字数。
- 语言：中文，口语化，普通人能看懂。
- 结构：一句话说清“谁发布了什么” → 2–3 句说清“为什么值得看” → 1 句提醒 / 注意 → 1 句来源提示。
- 不编造：不要编价格、链接、发布时间、数据。不知道的就写“请以官方口径为准”或不写。
- 来源提示：文案末尾要有一句来源提示，例如“来源提示：XX 官方发布与当日多家媒体报道。”

5. 2 文案模板（直接套用）

```
XX 在 X 月 X 日公开了 XXX：。
最值得看的点是，；。
注意区分，。
来源提示：。
```

注意：模板里的 `` 只是帮你分段，正式文案里不要保留这些括号标记，要写成自然连贯的一段话。

5. 3 避坑清单

| 坑 | 正确做法 |
|---|---|
| 文案超过 250 字 | 删废话，保留核心 + 提醒 + 来源 |
| 把“开放权重”写成“开源” | 这两个概念不一样，分不清就按官方原话写，或加一句“商用前请先读许可条款” |
| 编一个不存在的链接 | 没有核实的链接就不写 |
| 编一个价格 | 没有官方价格就不写价格 |
| 话题太旧 | 只选当时最热门的，不要拿几天前的旧闻充数 |
| 文案里夹带广告 | 贴图文案不加文章号那种文末广告，保持干净 |

5. 4 字数怎么数

- 标点、空格都算字。
- 标题、来源行、图片说明不算进文案字数。
- 存草稿前必须在本地文件里写清“文案字数：XXX 字，≤250 字 ✅”，不要凭感觉。

## 第 6 章：图片怎么生成（每条 4 张）

6. 1 图片规格（硬性要求）

| 项目 | 要求 |
|---|---|
| 数量 | 至少 4 张 |
| 比例 | 3:4 竖屏 |
| 尺寸 | 1536×2048 |
| 文字 | 越少越好，画面要清晰 |
| 角度 | 同话题不同角度，不要 4 张重复 |

6. 2 4 张图的分工（固定套路，小白照抄）

| 第几张 | 作用 | 画什么 |
|---|---|---|
| 第 1 张：主图 | 第一眼吸引人 | 话题核心场景 + 梦幻光感 / 俏皮主体 |
| 第 2 张：参数对比 | 把关键数字可视化 | 两个关键数字的对比（大 vs 小、多 vs 少） |
| 第 3 张：长上下文 / 核心能力 | 把抽象能力画出来 | 延伸、扩散、长链条的画面 |
| 第 4 张：落地场景 | 告诉用户“这东西能在哪用” | 真实使用场景（桌面、手机、办公室等） |

这个分工不是死板的，如果当天话题没有“参数对比”，可以换成“对比 / 原理 / 场景”等同类角度，但要保持 4 张角度不同。

6. 3 风格怎么选（关键：每条只选一种）

选风格只看文案的调性：

```
文案是重大发布 / 技术突破 / 严肃话题 → 选“漂亮唯美精美梦幻”
文案是轻松话题 / 梗 / meme / 卡通 → 选“幽默俏皮搞笑”
拿不准 → 默认选“漂亮唯美精美梦幻”
```

## 第 7 章：存草稿怎么存（后端接口要点）

这一章是给 Muse 看的技术要点，小白不用背，但要知道“存成功长什么样、存失败长什么样”，方便核对。

7. 1 本地文件结构（每条贴图固定这样存）

```
stickers/
└── YYYY-MM-DD/ # 比如 2026-10-16
├── HHMM.md # 比如 2100.md：话题 + 来源 + 文案 + 图片说明 + 字数统计
├── HHMM.jpg # 第 1 张：主图
├── HHMM-2.jpg # 第 2 张：参数对比
├── HHMM-3.jpg # 第 3 张：长上下文 / 核心能力
└── HHMM-4.jpg # 第 4 张：落地场景
```

示例（2026-10-16 21:00）：

```
stickers/2026-10-16/2100.md
stickers/2026-10-16/2100.jpg
stickers/2026-10-16/2100-2.jpg
stickers/2026-10-16/2100-3.jpg
stickers/2026-10-16/2100-4.jpg
```

本地文件是底稿，公众号草稿是发布用的副本，两边都要有，丢一边都不行。

7. 2 存草稿前的准备

1. 确认本地转发 127.0.0.1:1080 在监听（第 11 章有检查方法）；
2. 确认公众号会话有效（如果过期，Muse 会给你登录二维码，你扫码）；
3. 确认本地 4 张图 + 文案都齐了，文案字数 ≤250 字；
4. 确认这条贴图不是测试草稿、不是重复草稿。

7. 3 后端接口要点（已验证，小白看结论即可）

| 要点 | 结论 |
|---|---|
| 保存方式 | 必须用 **表单编码** `application/x-www-form-urlencoded` |
| 错误示范 | 用 JSON 传参会被后端判为参数错误 `200002`，存不上 |
| 保存参数 | `sub=create`，`type=77` |
| 图片上传 | 贴图图片必须先经 **素材库上传**，参数 `scene=1`、`writetype=doublewrite`、`groupid=1`，才能拿到一致的 `file_id` / `cdn_url` |
| 临时 file_id 的坑 | 普通上传只给临时 `file_id`、无 `cdn_url`，素材库里也查不到，**不能用这种方式存贴图** |
| 关键字段 | `share_page_type0=8`、`share_imageinfo0`、`guide_words0=文案`、`content0=文案`、`compose_info0={“list”:“”}` |
| 成功标志 | 返回 `ret 0`，并拿到一个 `appMsgId`（贴图草稿 ID） |

划重点：表单编码 + 素材库上传 + type=77 + share_page_type0=8，这 4 个缺一个都存不上。这是实测验证过的，不要换成别的写法。

![](../images/ryan-muse-wechat-tietu-step-by-step-guide/007.webp)

7. 4 存完怎么核查（必做）

存完不要直接说“存好了”，必须核查下面 4 项：

1. 返回码：是不是 ret 0？是不是拿到了 appMsgId？
2. 草稿箱总数：是不是比存之前多了 1 篇？（比如存之前 8 篇，存之后应该是 9 篇。）
3. 类型统计：贴图类型 item_show_type 8 是不是由 0 变成了 1？图文类型 item_show_type 0 有没有被误动？
4. 内容核对：新草稿的文案是不是完整原文？图片是不是 4 条 share_imageinfo？标题是不是文案前 30 字左右？测试草稿、重复草稿、文章草稿有没有被误动？

核查全部通过，才能告诉用户“存好了”。任何一项不对，都要停下排查，不要说“大概存好了”。

![](../images/ryan-muse-wechat-tietu-step-by-step-guide/008.webp)

7. 5 证据文件

每次存完，建议留一份证据文件，记录：

- 话题、文案字数；
- 保存返回（ret、appMsgId、sub、type、编码方式）；
- 4 张图的 file_id 和尺寸；
- 草稿箱核查结果（总数、类型统计、测试草稿是否未动）。

这样以后出问题，能回头查，不用凭记忆。

## 第 8 章：手机端怎么预览与发表

这章是你的活，Muse 不会帮你点发表。

8. 1 预览步骤

1. 在手机上打开 公众号助手；
2. 进入 草稿箱，找到当天要发的贴图草稿（看标题 / 时间档，不要点错）；
3. 点开草稿，检查：
   - [] 4 张图都在吗？顺序对吗？有没有裂图 / 错图？
   - [] 文案是完整原文吗？有没有乱码、截断、错字？
   - [] 图片风格统一吗？画面清晰吗？文字有没有乱码？
1. 有问题：不要发表，先告诉 Muse 哪条、哪张图、什么问题，让 Muse 修好再存。
2. 没问题：继续下一步发表。

8. 2 发表步骤

1. 在草稿里点 “发表”；
2. 如果弹出微信验证，你当场扫码完成验证；
3. 等待发表成功提示；
4. 发表后，在已发表列表里确认这条贴图出现了。

- 不要在电脑端截图二维码、关掉浏览器后再扫码，二维码会失效，验证会失败。必须在发表流程还活着的时候当场扫。

## 第 11 章：常见问题与故障排查

11. 1 本地转发掉了（127.0.0.1:1080 没在监听）

现象：Muse 说转发没在监听，存草稿停下了。

处理：

1. 停下，不要直连去试；
2. 用你保存好的固定代理凭据（占位符：<你的代理地址> / <你的代理账号> / <你的代理密码>）重启本地转发；
3. 确认 127.0.0.1:1080 重新在监听后，再继续存草稿。

记住：转发没起来之前，任何公众号操作都不要做。

11. 2 会话过期 / 账号退出

现象：Muse 说会话过期，需要登录。

处理：

1. Muse 会给你一个登录二维码；
2. 你用管理员微信扫码，在登录流程还活着的时候当场完成；
3. 不要让 Muse 代扫，不要截图二维码后关掉页面再扫（会失效）；
4. 登录成功后，再继续存草稿。

11. 3 保存返回参数错误 200002

现象：存贴图草稿时返回 200002。

原因：用了 JSON 传参，没有用表单编码。

处理：

1. 改成 application/x-www-form-urlencoded 表单编码再存；
2. 确认 type=77、share_page_type0=8、guide_words0 / content0 都传了；
3. 不要反复用 JSON 重试，换编码一次就能解决。

11. 4 图片只有临时 file_id，没有 cdn_url

现象：图片上传后，素材库里查不到，草稿引用不上。

原因：用了普通上传，没有走素材库上传。

处理：

1. 贴图图片必须经素材库上传，参数 scene=1、writetype=doublewrite、groupid=1；
2. 拿到一致的 file_id / cdn_url 对后，再存草稿；
3. 不要用临时 file_id 硬存，存上了也引用不上。

11. 5 草稿数量不对

现象：存完后草稿箱总数不是“存之前 +1”。

处理：

1. 先不要发表，先核对：是不是存了两次？是不是存错类型（贴图存成图文）？
2. 核对 item_show_type 8（贴图）和 item_show_type 0（图文）各自的数量；
3. 核对新草稿的 appMsgId、文案、图片数量；
4. 数量对不上时，停下告诉用户，不要擅自删草稿。

11. 6 文案超字数 / 图片缺张 / 风格混搭

| 问题 | 处理 |
|---|---|
| 文案超过 250 字 | 删废话，重新数一遍，≤250 字再存 |
| 图片只有 3 张 | 补齐第 4 张，不要 3 张硬存 |
| 图片不是 3:4 / 不是 1536×2048 | 重新生成，不要拉伸变形凑数 |
| 风格混搭（2 张梦幻 + 2 张搞笑） | 统一成一种风格，重做不统一的那几张 |
| 图片里有乱码文字 | 重做，提示词里强调“文字极少” |

11. 7 选不到热门话题

现象：当天没什么大新闻，选不出“最热门”。

处理：

- 宁可停下提醒用户，也不要编一条假热点；
- 可以从信息源里选相对最有价值的一条，但必须来源可靠、不编造；
- 实在没有，就跳过这一小时，下一小时再选。
