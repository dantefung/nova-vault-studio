# 公开焚诀｜Orca 从入门到精通：一个人同时指挥一群 AI Agent的秘密

之前我截图过自己token消耗的截图，我说过感觉很惭愧，消耗了太多的token一直没有做出像样的作品，sass站的付费用户也才刚刚开始，反而是一些人对我怎么可以做到长时间那么大的消耗比较感兴趣，所以这里我公开我的多Agent指挥焚诀---Orca。

我再次对我消耗这么多token而毫无建树跟地球母亲说一声：对不起。

![](https://pbs.twimg.com/media/HUQNNbeaUAAlQ3M.png)

Orca 它是一个开源免费的 AI 开发工作台，让你在一个窗口里同时指挥多个编程 Agent，Claude Code、Codex 混着用都行，每个 Agent 一份独立的代码副本，谁也不踩谁。

这篇的我按照以下次序详细讲解：它是什么，跟你现在的用法比强在哪，用上以后一天的工作会变成什么样，怎么十分钟跑通第一个任务，然后是一个个具体用法。最后讲它的毛病，以及什么时候别用它。

没听过 Orca 的，从第一节往下读。已经装了的，可以直接跳到第六节，从"让三个 Agent 赛跑"开始。

Orca 自带一套命令行，但日常用不着你亲手敲：界面上点得到的，我告诉你在哪点；点不到的，Orca 里的 Agent 会替你调用，你只要知道该让它做什么。

**一、30 秒认识 Orca**

如果只记一句话：Orca 是给 Agent 用的开发工作台。

IDE 是给人写代码用的，Orca 官方给自己起的名字叫 ADE，Agent Development Environment，给人和一群 Agent 一起用。

几个基本事实：

它是 Stably 做的，开源在 GitHub 上，MIT 协议，官网写着背后是 Y Combinator。仓库 2026 年 3 月 17 日建立，截止今天查的时候已经有 88,773 个 star。macOS、Windows、Linux 都有，手机端有 iOS 和 Android。

它自己不带模型。你已经装好、登录好的 Claude Code、Codex、Cursor、OpenCode，它都能跑，官网列了 27 个，最后一项是"其他任何命令行 Agent"。钱照旧付给你原来的订阅，Orca 本身免费。官方文档也写明了，它不卖托管服务器，远程跑任务用的是你自己控制的机器和云账号。

所以装 Orca 不用换模型、不用换账号，你原来怎么付钱，现在还怎么付。

**二、多开谁都会，Orca 管的是多开之后**

你可能会想：多开几个 Agent，我自己开几个终端窗口也能做到。

确实能。难的是多开之后，你会接连撞上四件事。

第一件，副本跑不起来。要让几个 Agent 互不干扰，就得给每个 Agent 一份独立的代码副本。可新副本是从 Git 里重新拿出来的干净代码，存密钥的 .env 文件不在里面，装好的依赖包也不在里面。Agent 一启动，先卡在缺依赖、缺密钥上。

第二件，盯不过来。五个窗口里，哪个在干活、哪个卡在等你确认、哪个早就结束了，你得一个个切过去看。

第三件，看不过来。生成代码越来越快，瓶颈变成了你的验收。五份改动摆在面前，每份都要你读、要你挑毛病、要你把意见准确地传回去。

第四件，被一家绑住。只用一家的 Agent，额度用完就得停；想让另一家的模型接着干，上下文又带不过去。

![](https://pbs.twimg.com/media/HUQO6zMbMAA7-1p.jpg)

Orca 最突出的优点，就是这四件事各有一个对应的设计。新副本能自动带上指定的配置文件和共享依赖；Agent 干完活，Orca 会弹通知、响提示音；改动里能逐行批注、一次性发回给 Agent，还能标出哪些行是 AI 写的；Agent 不限厂商，账号能切，会话能交给另一家的 Agent 接着做。

还有一个设计很少被提到：Orca 不光给人用，也给 Agent 用。Agent 可以自己开新的工作区、读别的窗口里的报错、操作内置浏览器。后面讲的编排，负责派活的"项目经理"本身也只是一个 Agent，靠的就是这套能力去分配任务、收集结果。

反过来，如果你只用一家的 Agent，一次只做一件事，Orca 帮不上太多忙，官方客户端就够了。它的价值，跟你同时跑多少个 Agent、要验收多少改动成正比。

**三、用上 Orca 以后，一个人的一天**

下面是一个假设的一天。你一个人在做一款面向海外用户的 AI SaaS：网站加数据库，用 Stripe 收订阅。每一步后面标了对应章节，想学哪个直接跳。

![](https://pbs.twimg.com/media/HUQMboDbcAAq9Tn.png)

早上 9 点，晨检报告已经生成好了。一个定时任务在云服务器上先看一眼仓库有没有新改动，有才叫醒模型，汇总昨天卡住的地方。仓库没动的日子，它直接跳过，一分额度不花。（第十四节）

10 点，你发现同一笔支付偶尔会给用户开两次订阅。你开三个工作区，让 Claude Code、Codex、Cursor 同时修。哪个先跑完，Orca 弹通知叫你。（第六、七节）

中午，主会话聊了几十轮，开始变慢、开始忘约束。你右键把它交给一个新会话，只带最新进度，换成 Codex 接着做。（第八节）

下午 2 点，定价页三张卡片高度不齐。你在内置浏览器里用鼠标点一下那张卡片，Agent 拿到它的代码、样式和截图，一次改对。（第九节）

4 点，上线前让一个 Agent 当项目经理，带两个 Agent 分头审查前后端，你只看最后的汇总。（第十一、十二节）

6 点，你把几处意见直接钉在改动的代码行上，一次发回去返工；数据库迁移那一步设了一道关卡，必须你拍板。（第十节）

晚上合上电脑，任务在云服务器上接着跑。路上 Agent 有问题，你在手机上回一句。（第十三节）

这一天里，你不用挨个切窗口去找谁在等你，也不用跟 Agent 描述"右上角那个按钮"在哪。

四、10 分钟跑通第一个任务

官方文档把整个产品压缩成一行：加仓库 → 开工作区 → 选 Agent → 分屏 → 看改动 → 提交。

![](https://pbs.twimg.com/media/HUQMcVRa0AARFga.png)

安装。macOS 用 Homebrew 一条命令就能装，也可以和 Windows、Linux 一样，去官网下载安装包。

第一次启动。Orca 会请求访问你的主目录，还会问要不要导入你电脑上已有的 Claude Code、Codex 设置和 Ghostty 终端设置。导入以后，原来的配置就带过来了。

加仓库：点左侧的 Add Repo，选一个本地项目文件夹。Orca 会读出它的默认分支，之后每个新工作区都从这里分出去。

开工作区：点仓库名旁边的 +，起个任务名，比如"修复支付回调"。名字留空的话，Orca 会用一种海洋生物给它命名。它会在后台给这个任务准备一份独立的代码副本。

选 Agent：新工作区里会开一个窗口，带一个下拉框，选 Claude Code、Codex 或别的。Orca 会在这份副本里启动它，用的是你自己的登录。

分屏：把标签拖到窗格右边或底部就能分屏。

看改动、提交：Agent 干完，打开这个工作区的改动视图看它改了什么，满意就直接在 Orca 里提交、推送、开 PR。

![](https://pbs.twimg.com/media/HUQMdEeawAACPmb.jpg)

跑通以后再认一下界面。左侧是入口和项目列表，每个项目下面挂着工作区，工作区下面列着正在跑的 Agent，带模型名和运行时长。中间是标签页，Agent 会话、终端、内置浏览器、文件编辑器都是标签，可以随意分屏。右侧管文件、搜索和改动。底部状态栏显示各个账号的额度用了多少、什么时候重置，开新会话前瞄一眼，能避免任务派出去了额度先见底。

**五、让新开的 Agent 一进门就能干活**

新开一个工作区，Agent 一启动就报缺环境变量、缺依赖，这是并行开发里第一个劝退点。

原因前面说过，新副本是干净代码，没被 Git 管的东西都不在里面。Orca 的办法是让你提前列一张清单，放在项目根目录：哪些文件每个副本复制一份，比如存密钥的 .env；哪些目录大家共用一份，比如几百 MB 的依赖包，省得每个副本重装一遍。清单写一次，之后每个新工作区自动照办。设置里的 Repository 页也有一个 Worktree Shared Paths，点几下就能配。

配好以后，新开的 Agent 进门就能把项目跑起来。

第二件要配的是项目规矩。Orca 里没有一块单独的"公共记忆"面板，起作用的是 Agent 自己会读的规则文件：Claude Code 读 CLAUDE.md，Codex 读 AGENTS.md。放在项目根目录，之后新开的、派生出来的、被派去干活的 Agent，只要在这个项目里工作就会读到。现在claude支持了agent.md,所以我只写了agent.md

拿我的案例来说，一份够用的规矩就这么几条：用什么技术栈，不许引入新的界面库；已有测试只许新增，不许改、不许删；碰到数据库迁移、支付密钥、生产环境，先停下来问我；干完跑一遍检查，说清楚哪些验证过、哪些没验证。

写完要提交到 Git。新副本只认 Git 里的东西，你没提交的规则文件，新工作区里的 Agent 看不到。

规矩也别一次写成几十条。Agent 在同一件事上反复犯错，再补一条。

**六、改错代价大的 bug，让三个 Agent 赛跑**

同一笔支付偶尔会给用户开两次订阅，大概率是 Stripe 的支付通知重复发了，代码没挡住。这种 bug 改错了，就是真金白银的退款。

官方文档里有一个现成打法，也是 Orca 最有代表性的用法：让三个 Agent 同时修。

![](https://pbs.twimg.com/media/HUQMd2hacAAHEdd.jpg)

从同一个起点开三个工作区，分别启动 Claude Code、Codex、Devin，贴同一段需求，拖成三栏分屏看它们干活。都结束以后逐个看改动，挑出最好的那份，再用逐行批注修一轮，在它的工作区里提交、开 PR。另外两个工作区一键删掉，副本和分支一起清。

官方对这个打法的解释我很认同：不同的 Agent 犯不同的错。三个都改成一样的地方，大概率是对的；三个各改各的，那里就是这个问题真正难的部分。你等于花一份等待时间，拿到了三份答案和一份"哪里有分歧"的地图。

这一招要算账。技术博客 [andrew.ooo](https://x.com/andrew.ooo) 上的一篇 Orca 评测说得很直接：三个 Claude Code 并行，就是三倍的 Anthropic 额度。省下的是你来回重试的时间，额度照付三份。所以只在支付、权限、数据迁移这类改错了很麻烦的地方赛跑，改个文案就别这么干。

我觉得这也是我消耗这么大的一个重大原因！

三份结果各对一半，Orca 不会帮你自动合并。可以让赢的那个 Agent 参考另一份改动再改一轮，也可以把另一份里好的部分手动挑过来。

**七、三个 Agent 同时跑，你不用一直盯着**

三个 Agent 同时跑，你总不能盯着三个窗口看半小时。

Orca 跑的是 Agent，不只是终端，所以它分得清 Agent 是真干完了，还是只是暂停。Agent 从干活变成空闲，Orca 会弹系统通知、响一声，在对应的工作区上挂个标记。顶部有个铃铛汇总所有未读，点一下直接跳到那个工作区和窗格；macOS 的程序坞图标上也会显示未读数。通知可以按类别关，提示音能换成你自己的音频文件。

官方文档的原话是：排好三个 Agent，走开，等第一个干完再回来。

需要看日志的时候用分屏。macOS 上 Cmd+D 向右分，Cmd+Shift+D 向下分。左边 Agent 写代码，右边跑网站看报错。

在窗口上右键，能复制这个窗格的 ID。把日志窗格的 ID 发给 Agent，它就能自己去读那里的报错，你不用一段段复制粘贴。

右键菜单里还有"快捷命令"，适合把每天要跑十遍的测试命令存起来，点一下就跑。

**八、会话越聊越笨、额度见底，怎么接着干**

对话跑到几十轮，上下文越来越长，Agent 开始变慢，早先说好的约束也开始忘。右键菜单里有两个功能专门处理这种情况。

派生智能体会话

主线做到一半，想试另一个方案，又不想把主线搞乱。比如收款已经按 Stripe 写了一半，你想看看换成 Lemon Squeezy 要改多少。

在窗口上右键，选"派生智能体会话"。Orca 会开一个新的工作区，启动一个新 Agent，把当前对话的要点整理成一份草稿交给它，你还能先改几句再发。新会话和原会话平级，就像从主线上拉了一条分支，方案 B 试砸了直接删，主线一个字没动。

它也是一个完整的新会话，那份草稿要占它的上下文，后面每一轮照常计费。

在新会话中继续（最新版改名 Hand Off to Another Agent），这个我记得之前还有人专门写了一个这种skill，现在直接不需要了。

右键选这一项，Orca 从当前进度启动一个新会话，原会话保持不变。

上下文有两种带法。聚焦交接是推荐项，新会话只拿最新进度和当前工作区，需要时再回头读更早的细节。完整会话记录会让新 Agent 先读完全部历史，界面上直接提示了，这可能更慢，也会消耗大量上下文和额度。

弹窗还会列出这台电脑装了哪些 Agent，你可以让 Codex 接着 Claude 的进度往下做，反过来也行。1.4.224 把它改名成"交给另一个 Agent"，官方也把它当成了跨 Agent 交接的入口。一个账号额度快见底的时候，它最顺手。

Orca 如果没法确认新会话收到了上下文，会提醒你去看新会话的输入框，空着的话点"复制提示"自己粘进去。

找回上周那次会话

Orca 能搜索 Agent 的历史会话，还能跨电脑搜。上周哪个 Agent 怎么修好的那个 bug，搜关键词就能翻出来。

**九、前端改样式，不用再"描述位置"**

"右上角那张卡片往下挪一点"，你说得累，Agent 也常改错地方。

Orca 每个工作区有一个真正的 Chromium 浏览器。打开你的网站，开启工具栏上的 Design Mode，用鼠标点那个元素，Orca 会把这个元素的代码、浏览器算出来的实际样式、一张裁好的截图一起交给当前 Agent。开发环境配置得当的话，还会带上它在哪个源文件、第几行。[andrew.ooo](https://x.com/andrew.ooo) 那篇评测管它叫 sleeper feature，也就是最被低估的功能。

定价页上 Free、Pro、Team 三张卡片高度不一，点中最矮的那张，补一句：

让三张定价卡片底部按钮对齐，保留按钮现有的点击行为，电脑和手机宽度都要检查。

改完页面自动刷新，再点一次同一个位置核对。要注意，它定位源文件靠的是开发环境，随便点一个线上网站，找不到你本地项目里对应的代码。

这个浏览器 Agent 也能用。你可以让一个 Agent 写功能，另一个 Agent 打开浏览器，替你走一遍"填表、提交、看成功页或错误页、再试一次"。测试账号、允许点哪些按钮、怎样算成功，都写进交代给它的任务里。

十、验收不再靠肉眼翻：批注、AI 归属标记和关卡

Agent 写代码的速度已经比你读代码快了，验收得有工具帮你。

逐行批注

看改动时发现某一行有问题，在行号旁点 +，或者光标停在那一行按 c，就能把意见钉在这一行上。看完一轮，点 Send to agent，Orca 会把所有批注合成一条消息，交给你选的 Agent。改好的标成已解决，没解决的留到下一批。

批注按"什么情况下、哪里不对、期望怎样"写最好用，比如：

请求超时后这里恢复了按钮，但前一个请求可能已经成功。先查有没有已存在的订阅，再决定是否允许重新提交。

哪些行是 AI 写的

Agent 写进文件的每一行，Orca 都会记下来，在改动视图边上做个小标记；你在 AI 代码上手动改过的行，会变回"人写的"。审代码的时候，带标记的行就是该多看两眼的地方。这个标记只存在 Orca 本地，不会提交进 Git，需要留档可以导出。

项目托管在 GitHub 的话，PR 页面里还有 Fix broken checks，自动检查没过，一点就把失败原因交给 Agent 去修。

高危动作设一道关卡

Agent 太积极，最怕它自己就把数据库迁移跑了。Orca 的编排里有一种关卡，叫 Gate：给某个任务挂一个问题，比如"是否执行已审阅的订阅表迁移"，选项是"批准执行"或"继续调研"。不选，任务就卡在这儿不往下走。

有个细节必须知道：放行关卡的权限，项目经理那个 Agent 自己也有。你不在任务里写明"这道关卡只能由我决定"，它完全可能自己批了，再把迁移解释成"已经同意过"。关卡的用处是把决定记在任务上，事后查得到谁、在什么时候、选了什么，审批权归谁要你自己写死。

**十一、让一个 Agent 当项目经理：编排**

**这个我觉得是Orca目前对我帮助最大的地方，真的是非常非常好用！**

编排容易被理解成"多开几个 Agent"。它其实是让一个 Agent 当项目经理：拆任务、派给别的 Agent、收消息、验收，你只跟它一个人说话。

![](https://pbs.twimg.com/media/HUQMekBaoAA68Gt.jpg)

这里面最值得理解的设计，是"工单"和"这一次执行"分开记。

举个例子。负责查结账接口的 Agent 跑到一半断线了。要查的东西没变，失败的只是这一次执行。Orca 的做法是：工单不动，在同一张工单下面再开一次执行，并记下"这次是接着上次失败的那次来的"。前面的记录都还在，迟到的旧消息也不会跟新的混在一起。同一张工单连续失败三次，Orca 会停下来不再重试，提醒你该去查原因了。

从这里能看出 Orca 的设计取向：它只认能证明的事实。派一个 Agent 出去，Orca 会区分"任务说明已经送到了"和"确实看到模型开始干活了"。有些 Agent 根本不报告自己有没有开始，Orca 就老实写"无法确认"。只看到"派发成功"就以为 Agent 已经开工，就读错了 Orca 给你的信息。

还有三个说法要分清：交接、监督、定时。"交给另一个 Agent 接着做"是全权交接，交出去原来的 Agent 就不管了。"分给两个 Agent，你监督到验收完"才是编排。"每个工作日上午做一次"是后面讲的定时任务。你跟 Agent 交代的时候把这个词说清楚，它才知道该等到什么时候。

**十二、编排实操：两个 Agent 并行审查结账流程**

支付 bug 修好了，上线前让两个 Agent 分头查一遍，一个查后端，一个查前端，你只看最后的汇总。

第一次用编排，Orca 会弹出 Enable orchestration 的提示，点一下，它会把 Agent 之间互相协调需要的工具装好。

然后选一个 Agent 当项目经理，把下面这段话交给它，可以直接抄：

请用 Orca 编排做一轮受监督的并行审查。你是协调者，负责回答另外两个 Agent 的提问、核对证据，等两项任务都有明确结果再收尾。

>

目标：本项目的订阅结账流程。

A：只读检查支付回调处理、订阅状态写库和失败重试，结果写进 api-review.md。

B：只读检查定价页、结账跳转和支付失败后的页面提示，结果写进 ui-review.md。

两人都不改代码、不提交、不碰生产数据、不对外发消息。每条发现写清在哪个文件、怎么复现、证据和严重程度；没发现问题，也要写明查了哪些范围。

>

两份报告都到了以后，你回到代码里核对关键发现，写一份汇总：确认的问题、排除的问题、还缺什么证据、建议先修哪个。

被派出去的 Agent 看不到你跟项目经理的聊天，所以任务说明要像上面这样自己写全：目标、能动什么、不能做什么、交什么、怎么算完成。

接下来的事，项目经理会自己去做，大致是这样：

它先给这次协作开一个收件箱，然后同时派出两个 Agent。两个都只读，所以共用当前这份代码，不用另开副本。

接着它就等着。两个 Agent 有提问、有报警、干完了，消息都进这个收件箱。它被叫醒时拿到的是一整批消息，可能 A 的完成报告和 B 的提问同时到了。回完 B 的问题，A 的报告还在同一批里等着验收。

这一批全处理完，它才告诉 Orca"这批我看完了"。没确认的消息会一直重新出现，这是故意的，防的就是漏看。干完活的 Agent，它会把输出存档再关掉窗口，之后照样查得到。

这一轮算成功，要满足三条：两份报告真实存在，内容能对上代码，关键发现项目经理亲自复核过。两个 Agent 都说没问题，也可能都漏了同一个地方。

需要第三个 Agent 等前两个做完再复核，就跟项目经理说"C 要等 A 和 B 都完成再开始"。Orca 会记下这层先后关系，A、B 做完，C 才算可以开工；开不开工，还是项目经理来定。B 用不到 A 的结果，就别硬排先后，白白多等一轮。

改代码时还有一个坑：A 在自己的副本里改了接口，B 在另一个副本里改了页面，两个都做完了，改动也不会自动合到一起。验收前要定好用哪份代码、谁负责合并。

任务跑起来以后想缩小范围，直接让项目经理给那个 Agent 捎句话，比如"本轮只查信用卡支付"。对方会在干活的间隙读消息，比如开始看新文件或者跑完测试的时候，并不会被立刻打断。改动大的话，等它明确回复再继续。

**十三、合上电脑，任务照跑**

笔记本一合盖，本机上的 Agent 就停了。Orca 有几种办法把活挪到常开的机器上，区别在"工作现场归谁"：

本机：Agent、终端、浏览器都跟界面在同一台电脑上，日常开发用它。

SSH 远程：Agent 跑在远程机器上，看代码、看改动还在你的笔记本上。适合已经有开发机、GPU 主机或云服务器的人。1.4.224 起，Orca 会在远程机器上自动装好自己需要的运行环境，不再因为远端软件版本不对连不上。

Remote Orca Server：一台常开的机器跑 Orca，项目、工作区、终端、Agent 都归它，你的笔记本和手机只是连过去看和操作。笔记本合上，任务照跑。

Cloud VM：每个工作区一台用完即弃的云端虚拟机，目前放在实验功能里。

几种方式能在同一个 Orca 里混着用。

![](https://pbs.twimg.com/media/HUQMfUNbYAAEnzf.jpg)

推友 Asa（[@app_sail](https://x.com/app_sail)）2026 年 10 月 9 日发过一篇长文，用的就是 Remote Orca Server：在 Grok Bot 自带的美国云电脑上装好 Orca 当服务器，那台机器按他文中的说法有 16 GB 内存；MacBook 和手机上的 Orca 通过 Tailscale 连进去，直接控制跑在云电脑上的 Claude Code。

照这个思路搭，分四步。

第一步，打通网络。云服务器、笔记本、手机都装上 Tailscale，登录同一个账号。Tailscale 相当于给你的几台设备拉了一条只有自己能走的内网专线，服务不用暴露到公网。官方文档推荐的也是 Tailscale 或你自己控制的私有网络。

第二步，在服务器上装好、登录好 Agent。笔记本上的 Claude Code 登录了，服务器上的并不会跟着登录，要单独装、单独登。Claude 账号能不能在你所在的地区注册和使用，按 Anthropic 的条款来，这篇不展开。

第三步，在服务器上启动 Orca 服务，并告诉它用 Tailscale 给的那个地址对外配对。服务器装的是桌面版的话，在设置里打开 Remote Orca Servers，选 Advertise this app as a server，再点 New Link 生成一条访问链接；没有桌面的 Linux 服务器，用 Orca 的服务模式启动，它会打出配对信息，要接手机就让它生成手机配对码。顺手让服务器开机自动启动 Orca、挂了自动重启，这一步可以直接交给服务器上的 Claude Code 去配。

第四步，客户端接入。笔记本上在同一个设置页选 Add Server 填入链接，手机上装 Orca 的手机端扫码配对。

接上以后有两个设置要看。新项目默认在哪台机器上跑，看设置里的 Active Server；想让内置浏览器在服务器上运行，到浏览器设置里选 Server （streamed），不然笔记本一睡，浏览器自动化就断了。

配对链接等于这台服务器上整套环境的钥匙，谁拿到谁就能指挥你的 Agent，只发给自己的设备。服务器那边可以单独收回某台设备的权限。

Orca 在 1.4.223 的发布说明里自己写了：当前的 Remote Server 仍是实验功能，可能有 bug，Orca Server 2.0 即将推出。拿它挂重要任务，先用小任务试几天。

手机端官方标的是 beta。能看工作区和 Agent 状态、读终端输出、回答 Agent 的提问，也能看改动、做提交。它操作的始终是电脑或服务器上的会话，主机关了，手机这边就什么都看不到。手机上的提交、关窗口会真的执行，复杂的合并和长报告验收还是回大屏幕做。

**十四、每天早上自动晨检，没活就不花钱**

定时任务有一笔隐性浪费：每天到点准时叫醒一次大模型，哪怕项目里什么都没变。

![](https://pbs.twimg.com/media/HUQMgCBasAAdRBg.jpg)

Orca 左侧的"自动化"就是定时任务，可以按小时、每天、工作日、每周来排。它有一个很省钱的设计，叫探针：到点以后先跑一个很轻的检查，比如"项目里有没有新改动"，有才叫醒模型，没有就记一次"已跳过"，一分额度不花。

你可以直接跟 Orca 里的 Agent 说：

帮我建一个定时任务：工作日北京时间早上 9 点，先检查项目里有没有未提交的改动，没有就跳过；有的话只读检查一遍，汇总卡住的地方和需要我决定的事，不改文件、不提交、不发外部消息。先建成停用状态，我手动跑一次没问题再启用。

这段话里有几处讲究。

时区要说清楚。服务器在美国的话，它的系统时间多半不是北京时间，你的"早上 9 点"可能变成半夜。

要指定在你现在这个工作区里跑，它才看得到你还没提交的改动；不指定的话，每次都会新开一份干净副本，里面什么都没有。

先停用、手动跑一次，看结果对了再启用，免得一个写错的定时任务天天空烧。

1.4.224 又加了一个省钱选项：每个定时任务可以单独指定模型。晨检这种活，配一个便宜的小模型就够了。我觉得Haiku5.5完全可以胜任！

定时任务存在哪台机器上，就由哪台机器到点执行。存在笔记本上，笔记本睡了就不会准时跑。要真正 7×24，就让它存在那台云服务器上。

晨检报告要发给合作方，对方又没装 Orca，可以让 Agent 用 Orca 的 Artifacts 把报告变成一个免登录就能看的网页链接。第一次会被拒，这是故意的：对外发布的权限默认关闭，只能你自己在桌面端设置里的 Artifacts 页打开，Agent 没法偷偷把你的文件发到公网上。分享前打开看一遍，别留内部路径、密钥和客户数据；不想让人看了，随时可以撤回。

**十五、它的毛病，和不适合谁**

它是 Electron 应用。[andrew.ooo](https://x.com/andrew.ooo) 那篇评测的作者实测，安装包大约 250 MB，开着几个 Agent 时空闲内存占用在 400 到 800 MB，这还没算 Agent 本身和内置浏览器。

并行就是多花额度。三个 Agent 赛跑就是三份消耗。

更新非常快。官方自己的说法是每天都在发新东西，从 2026 年 9 月 11 日的 1.4.200 到 10 月 10 日的 1.4.224，正式版一路往上发。好处是问题修得快，比如 1.4.222 修好了用中文输入法按回车选词时会误触发送；坏处是功能和菜单名会变，"在新会话中继续"改名就是例子。团队用的话，固定一个版本，升级前看一眼发布说明里的已知问题。

几个亮眼的功能还挂着实验或 beta 标签：Remote Server、手机端、Cloud VM，还有新的聊天式界面。

独立副本解决的是几个 Agent 互相踩文件，合并冲突和你的验收工作量，它一样都没帮你省掉。

不适合谁：只用一家 Agent、一次只做一件事的人；电脑内存紧张的人；需要严格固定工具版本、又没精力跟进更新的团队。

**十六、怎么选：一张图找到最短路径**

所有选择都服从一个原则：最短可靠路径。能直接完成，就不搭流程；能改局部，就不推倒重来；一个会话能解决，就不开编排。

![](https://pbs.twimg.com/media/HUQMgCDaAAAefJd.png)

需求还没想清楚的时候，别上编排。编排管分工和追踪，管不了"到底要做什么"，派三个 Agent 只会得到三份不同的误解。

一件事拆完以后，每一份都要你仔细验收，也别拆。并行省下的时间，会在验收时一分一分地还回去。

我也没看到任何可靠数据能证明"开五个 Agent 效率提升几倍"。速度取决于任务能不能干净地拆开，以及你验收的成本有多高。

**十七、从 0 到 1 的实践路线**

Level 1：一个人，一个会话。装好 Orca，导入原来的 Agent 设置，跑通"加仓库 → 开工作区 → 选 Agent → 看改动 → 提交"。配好副本要复制的文件、共享的依赖和规矩文件。学会分屏和逐行批注。能独立判断 Agent 改了什么、有没有越界，就算过关。

Level 2：一个人，几条线。改错代价大的问题让三个 Agent 赛跑，拿不准的方案用派生会话试，聊久了交给新会话，前端问题改用 Design Mode。第一次上编排，先做一轮只读的并行审查，看懂项目经理每一步在干什么。

Level 3：一个人，一个常开的团队。真有互不依赖的开发任务，再让编排去改代码，每个 Agent 一份独立副本，提前定好谁合并。高危动作设关卡，重复的检查做成带探针的定时任务。确实需要合盖继续跑，再搭 Remote Orca Server 和手机端，并记住它还在实验阶段。

Orca 更新得快，换了版本以后，可以先让 Orca 里的 Agent 读一遍新版自带的说明，再照着这篇往下做。

能够读到这里的，我觉得对Orca应该有了很好的一个理解了，借用劲酒的一个广告：Orca虽好，可不要贪恋哦！
