# 如何低成本购买出海域名和服务器？

持续更新，专注独立开发

作者 | 梁唐

出品 | 公众号：Coder梁（ID：Coder_LT）


昨天建好了社群，很快就有群友跃跃欲试了。

用 AI 从0到1做个海外工具站赚美元

抛出了一个很关键的问题：AI 出海，怎么低成本购买域名和服务器呢？

很明显，出海产品需要在海外购买域名和服务器。

## 域名

海外域名的购买渠道不少，随便问下 DeepSeek 就能有答案。

比如Namecheap、GoDaddy等，这俩用户量都很大，而且都支持支付宝。

我之前的域名都是在 GoDaddy 上买的，用起来没什么问题，我也没对比过多家，不知道其他家什么样。

本来一切都挺好的，我也养成了习惯，每次有一个新的 idea，我都会先去买好域名备着，等待后续开发完成就可以直接上线了。

直到有一次我无意间发现原来cloudflare也可以购买，一对比才发现，自己被坑了。

原来 cloudflare 的域名便宜这么多。

下面用我很中意的koinote.ai这个域名做个例子，因为有点贵，最终还是没舍得下手。

这是它在 GoDaddy 上的价格，两年 1415。

这是它在 cloudflare 上的价格，一年 80 刀，两年 160 刀，算成 rmb 大概 1000 块不到，还是便宜不少的。

但 cloudflare 不支持支付宝付款，只支持外币卡和PayPal。

## 服务器

这个选择就更多了，五花八门。

老实讲我也没有特别仔细研究对比过，所以没办法讲得很技术，只能从我个人感受和体验上来简单分享一下我用过的几款，还会特别分享一下省钱小妙招。

全球有 13 个数据中心，提供好几种配置的机器可供选择，选择面我个人觉得是不错的。

价格从4 刀到 32 刀每月不等。

性价比并不算高，但是除了选择比较多之外，还有两个好处：

支持支付宝付款：

根据我的经验，200 刀赠金不说绰绰有余吧，至少省着点花的话够用一阵子了，足够度过前期流量起来之前艰难爬坡的岁月了。

瞄准的就是预算有限，对性能要求不那么苛刻的用户，说白了像是我们这样兜比脸干净的独立开发者。

### 国内厂商

其实很多国内云服务厂商也都提供境外的服务器。

我之前就买过腾讯云的 4 核 4G，299 一年的超高性价比款。

我现在的 Koinote 就是部署在上面，不过因为 Koinote 毕竟只是个 markdown 编辑器，没什么特别吃资源的场景，并且现在用户量也不大。

所以服务器轻松驾驭，也测不出极端情况下的性能瓶颈。

除此之外有名的服务器还有很多，像是vultr、搬瓦工等等。因为我这块研究不深，所以就不过多介绍了。

## vercel vs cloudflare

除了传统服务器之外，还可以走全栈项目的路子，不要服务器，把全栈项目整个架设在云端。

比如 vercel 就提供这样的服务，还会送一些免费额度，在前期可以不用花钱就能上线。并且 vercel 可以连接github，只需要 push 代码，vercel 自动帮你完成代码部署上线。

并且 nextjs 框架就是 vercel 推出的，它有一个很大的好处是SSR（服务端渲染），SSR 除了网页开启速度更快之外，还能获得SEO 上的巨大优势。搜索引擎的爬虫能更好的获取到网页信息，虽然 cloudflare 的架构也能做到，但兼容性要稍差一些。

vercel 的优点明显，缺点也同样不容忽视，最大的弊端就是它的价格太贵了，尤其是流量费用。我之前的文章分享过被 vercel 背刺的经历，流量稍微大了一些，或者被一些友商 ddos 攻击，稍不注意烧掉几千块的流量是非常有可能发生的。

> 我被攻击之前也觉得我不去惹别人，应该不会被攻击。

我被攻击之前也觉得我不去惹别人，应该不会被攻击。

另外一个选择是 cloudflare workers，它也可以部署大多数全栈项目，但是兼容性不及 vercel。上线之后需要仔细地回归反复测试所有 case，一不小心就会踩坑，这个我之前也遇到过，也写过文章分享过。

总体来说我更推荐 cloudflare workers，无他，便宜。

大家可以对比一下下图，看起来两边免费的额度都是 10 万次调用，但实际上 vercel 更容易满额的并不是 10 万次调用，而是 100GB-小时的 CPU 额度。

而 cloudflare 是真的 10 万次请求免费，绝大多数全栈应用，真的真的，绰绰有余。

毕竟兼容性问题是可以仔细排查解决的，而没钱，怎么排查也解决不了。

我之前开源的代码模板AgentFlowing就是基于 cloudflare workers 开发的。已经帮大家踩了不少坑，大家直接基于它开发就能省掉很多事。

## 项目架构

这是我国模站点的架构图，流量通过 cloudflare 进入 worker，一样可以获得SSR。

不过 cloudflare workers 并非是万能的，也不能 100% 代替传统后端。它的使用场景更多的是轻量级高并发的场景，对于一些逻辑复杂、需要处理长时间任务的情况就不是很适用。

当然这个问题 vercel 也有，它对于单个请求的响应时间也有限制。

如果业务逻辑复杂的话，纯 cloudflare worker 做全栈项目可能还是会有所不够。可能还是会需要一个传统的服务器介入来承担其中复杂逻辑的部分，然后页面展示、渲染交给 cloudflare workers。
