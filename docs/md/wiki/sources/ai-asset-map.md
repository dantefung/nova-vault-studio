# 企业上线100个Agent以后，为什么需要一张AI资产地图？

> 当 Agent 从几个变成上百个，企业需要的不是更长的 Excel 表，而是一张能回答"依赖什么、能做什么、影响谁"的资产地图。

<!-- more -->

## 01 100个Agent带来的五类管理盲区

一个 Agent 背后不只是模型，还包括提示词、知识库、MCP Server、API、数据库账号、工作流、审批规则和监控任务。数量上去后，出现五类盲区：

- **资产盲区**：业务部门自行创建 Agent，平台团队不知道是否仍在运行
- **责任盲区**：开发者转岗，Agent 继续使用原密钥和工具
- **权限盲区**：只知道 Agent 能调用 CRM，不知道能读哪些客户、能否改订单
- **依赖盲区**：模型/接口/知识库升级，不知道影响哪些 Agent 和流程
- **审计盲区**：系统发生修改，无法还原哪个 Agent、代表谁、依据什么策略执行

这些问题属于资产、配置、身份、流程和责任管理，不是更强的模型能解决的。

## 02 AI资产地图的三层能力

不是一张 Agent 登记表（名称/部门/负责人/模型/状态），而应当具备：

1. **资产注册表**：有哪些 Agent、模型、工具、数据集和 MCP 服务
2. **关系地图**：属于什么业务，依赖哪些系统，由谁维护，服务哪些流程
3. **治理控制面**：拥有什么权限，遵守哪些策略，运行质量如何

清单帮找到对象，关系帮理解影响，控制面帮采取行动。

## 03 八类必录信息

1. 身份：唯一标识、运行账号、认证方式、所属租户
2. 责任：业务负责人、技术负责人、维护团队、复审人
3. 目标：解决什么业务问题，服务哪个流程，如何判断成功
4. 能力：能够回答/判断/执行哪些动作，对外提供什么能力
5. 依赖：模型、提示词、知识库、MCP Server、API、应用、基础设施
6. 权限：可访问数据范围、可执行动作、环境、额度、有效期
7. 运行：版本、状态、调用量、成功率、成本、异常、人工接管率
8. 生命周期：申请、测试、上线、变更、复审、暂停、下线记录

模型名称只是一个属性。对企业风险影响更大的，是 Agent 能接触哪些业务对象、调用什么工具、谁批准了这项能力。

## 04 六条核心关系

Agent → 业务服务 | 责任人与维护团队 | 模型/指令/知识库 | MCP 工具与业务 API | 数据对象与权限策略 | 工作流/审批/审计记录

有了这些关系，才能回答影响分析：接口停机影响哪些 Agent？MCP Server 漏洞暴露哪些流程？负责人离职需要重新确认哪些 Agent？

## 05 与 CMDB 的关系

Agent 进入生产后，不需要另建割裂的数据库，而应扩展现有 CMDB 配置模型：

```
业务服务 → 应用 → 微服务 → API/数据库 → Agent → 模型/知识库/MCP工具 → 身份/权限/工作流/审计
```

CMDB 保存稳定身份和关系，可观测平台保存轨迹和指标，IAM 保存认证授权，ITSM 承接流程。AI 资产地图让它们围绕同一个 Agent 身份和关系模型协同。

## 06 权限管理

Agent 权限不能只绑定部门角色。资产地图为授权提供上下文：代表谁、处理什么、执行什么、在什么条件下执行。

OWASP 针对 Agentic AI 的风险清单包括工具滥用和身份与权限滥用。仅靠工具白名单不够——同一个退款工具，可以允许查询也可以允许执行，可以限定 100 元也可以放开全部额度。

## 07 异常响应示例

客服 Agent 错误执行退款 → 资产地图沿关系自动完成：定位 Agent 和版本 → 找到使用的模型/提示词/数据/工具 → 检查权限策略和阈值 → 查询同一版本服务范围 → 暂停高风险动作 → 创建事件和变更 → 修复后验证与审计归档。

## 08 四步建立最小可用地图

1. **统一身份**：每个生产 Agent 分配唯一标识，禁止公共账号和共享密钥
2. **登记八类信息**：先覆盖生产 Agent，没有负责人/业务目标/工具清单的不得进入生产
3. **打通流程**：Agent 上线自动创建配置项；变更自动关联；异常自动关联事件
4. **持续发现和复审**：从 Agent 平台、云账号、MCP 网关、API 网关和身份系统自动发现资产

## 09 上线前 12 问自检清单

- 每个生产 Agent 是否有唯一身份？
- 是否明确业务负责人和技术负责人？
- 是否关联业务服务、应用和工作流？
- 是否登记模型、指令、知识库和版本？
- 是否登记 MCP Server、工具和 API 依赖？
- 是否知道 Agent 能访问哪些数据对象？
- 是否区分读取、写入、审批和删除权限？
- 权限是否包含环境、额度和有效期？
- 依赖变化时能否自动完成影响分析？
- 异常时能否一键暂停高风险能力？
- 调用记录能否关联到 Agent 和业务任务？
- 是否设置定期复审、暂停和下线流程？
