# Ryan（@7998l201）：让 Muse 全权自动把 X 长文同步到微信公众号——手把手实操教程与零行丢失硬核验收

> 手把手教小白创作者搭建双模式同步流水线：支持原稿一键排版（摸鱼绿主题）或自动监控抓取 X 最新推文入库；严格遵守「AI 只备稿排版进草稿箱、作者在手机活会话里扫码发表」的安全分工铁律，实现 0 ERROR、0 WARNING、正文逐行 0 行丢失的标准化公众号自动化生产力。

<!-- more -->

适用人群：完全没做过公众号、没写过代码、第一次用 Muse 的小白。

读完本教程，你能照着步骤，让 Muse 帮你把 X 文章变成公众号草稿，再由你自己在手机上点一下发表。

全文没有代码基础要求。凡是需要你动手的地方，都写了“做什么、点哪里、看到什么算成功、出错怎么办”。

### 0. 教程能帮你做到什么 + 分工 + 准备清单

0. 1 教程能帮你做到什么

做完本教程，你将拥有一条可重复的流水线：

```
方式 A：你的原稿（MD + 配图）→ Muse 一键排版（摸鱼绿）→ 存入公众号草稿 → 你手机预览 → 你手机点发表
方式 B：Muse 自动抓取 X 新文章 → 同步更新到公众号草稿 → 你手机预览 → 你手机点发表
```

每天只需要你做两件事：看预览、点发表。其余排版、存草稿、传图、对齐检查都由 Muse 完成。

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/002.jpg)

0. 2 分工：谁做什么

| 事情 | 谁做 |
|---|---|
| 每天看 X 有没有新文章（方式 B 全自动抓取；方式 A 由你发素材） | Muse（方式 B）/ 你发素材（方式 A） |
| 把原稿排版成公众号样式（一键排版） | Muse |
| 把图片上传并插到正确位置 | Muse |
| 把文章存入公众号草稿箱 | Muse |
| 生成手机预览二维码给你检查 | Muse |
| 在手机上点“发表”并扫码验证 | **你做** |
| 删除草稿箱里的测试草稿 | **你做**（在自己浏览器里手动删） |

⚠️ 重要边界：Muse 绝不替你点“发表 / 继续发表”，绝不代扫验证二维码，绝不发布测试草稿。为什么？发表需要管理员微信当场扫码验证。截图发给你的验证二维码，一旦截图那边的浏览器关闭，二维码就失效了，扫了也发不出去（已在实测中验证过）。所以发表这一步，必须由你在自己的手机 / 浏览器活会话里当场完成。

0. 3 需要准备的东西清单

在开始之前，先备齐这些：

- 一个微信号（用于注册和登录公众号，以及发表时扫码验证）
- 一个邮箱（用于注册公众号）
- 你的身份证信息（个人公众号注册需要实名验证，按页面提示操作即可）
- 一台能打开微信公众号后台的电脑（用于偶尔手动删测试草稿、检查草稿箱）
- 一部手机，装好微信 + 公众号助手 App（用于预览和发表）
- 你的第一篇文章原稿（方式 A 见第 3.1 节怎么写；方式 B 由 Muse 自动抓取，见第 3.4 节）
- 每篇文章的配图：封面 1 张 + 正文图若干张（方式 A 见第 3.1 节怎么整理；方式 B 由 Muse 自动抓取）
- 和 Muse 对话的入口（本教程假设你已经能和 Muse 对话）

✅ 准备好上面这些，就可以从第 1 章开始。不需要先学代码，不需要先买服务器。

### 1. 注册与设置公众号

1. 1 注册公众号

做什么： 在微信公众平台注册一个公众号。

步骤：

1. 在电脑浏览器打开微信公众平台官网，点“立即注册”。
2. 选择账号类型：
   - 个人做内容：选 订阅号。
   - 公司 / 机构：按实际情况选订阅号或服务号。本教程以订阅号为例。
1. 按页面提示填写邮箱、密码、验证码，激活邮箱。
2. 选择主体类型（个人选“个人”），按提示完成实名验证。
3. 填写公众号信息：
   - 公众号名称：取一个你长期用的名字，后续可按平台规则修改，但不要频繁改。
   - 功能介绍：一句话写清你写什么，例如“分享 AI 内容、自动化工作流、实用教程”。
   - 运营地区：按实际情况选。

看到什么算成功：

- 能登录公众号后台首页，左上角能看到你的公众号名称和头像。
- 后台左侧菜单能看到“内容管理 / 草稿箱 / 发表”等入口。

出错怎么办：

- 收不到邮箱验证码：先看垃圾箱 / 推广邮件，等 1 分钟再点“重新发送”；仍收不到，换一个常用邮箱。
- 实名验证失败：检查姓名、身份证号是否和微信实名一致，拍照时保证光线充足、证件四角完整。
- 名称被占用：换一个名字，或在名字后加一个词，例如加上你的昵称。

1. 2 基本设置

进后台后，先做这 3 个设置：

| 设置项 | 在哪里 | 建议 |
|---|---|---|
| 头像 | 设置与开发 → 公众号设置 → 头像 | 用一张清晰、正方形头像，不要用模糊图 |
| 名称与简介 | 公众号设置 → 名称 / 功能介绍 | 和注册时一致，简介一句话说清定位 |
| 作者 | 写文章时每篇填作者 | 本教程统一用 `Ryan`（你也可以换成你的名字，定下来后不要频繁换） |

1. 3 作者签名：定下来，以后每篇都一样

为了让读者认出你，每篇文章末尾都要放一段固定签名。先定好，以后不再改。

本教程使用的固定签名是：

我是 Ryan，持续分享 AI 内容、自动化工作流、实用教程如果你觉得今天这篇有收获，欢迎点赞、在看、转发三连，我们下篇见

怎么做：

1. 把上面两句复制保存到你的备忘录里。
2. 每次给 Muse 下指令时告诉它：“签名用固定那两句”。
3. 如果某篇你想临时换第二句，必须明确告诉 Muse“这篇就用现在这句，不改回固定文案”，否则 Muse 会默认用固定文案。

⚠️ 不要在每篇文章里写不同的签名。签名不统一，读者记不住你。

1. 4 广告位说明

本教程在每篇文章末尾固定放一个广告区，结构是：

- 一张广告图
- 一段广告文案，写清充值入口是 oneai.click/，并注明“具体价格与服务以下单页为准”

规则：

- 广告文案里 不要自己编价格、折扣、会员时长承诺。价格以下单页为准。
- 广告只出现一次，不要在正文中间再插一次广告。
- 如果你没有广告需求，可以把广告区删掉，但要明确告诉 Muse“这篇不加广告”，否则 Muse 会默认加上。

### 2. 让 Muse 接入你的公众号

2. 1 Muse 是什么

Muse 是你的 AI 助手。你不需要给它装什么插件，你只需要用中文告诉它要做什么，它会帮你排版、存草稿、生成预览二维码。

你和 Muse 的配合方式是：

```
你：给原稿 + 配图 + 一句话指令
Muse：排版 → 存草稿 → 给你预览二维码
你：手机预览 → 手机点发表
```

2. 2 怎么给 Muse 下指令（直接复制改一改就能用）

第一次下指令模板：

```
我要让 Muse 全权运营我的微信公众号。
X 账号是 @7998l201，文章同步到公众号。
排版用摸鱼绿主题，全部左对齐。
每篇文末加固定广告和固定签名。
先存草稿，给我手机预览二维码，我确认后再由我在手机上发表。
```

以后每天下指令模板（两种方式任选一种）：

方式 A（一键排版，手动发素材）：

```
按摸鱼绿排版，存入草稿，给我预览二维码。
原稿如下（MD 格式），配图已按锚点整理好：
[粘贴原稿]
[上传配图并写清每张插在哪里]
```

方式 B（一键开启每天全自动同步）：

```
从今天起每天 07:15 监控 X 更新，08:15 前把新文章准备好放进草稿。
X 账号是 @7998l201，同一台电脑已登录 X 号和公众号后台。
有新 Articles 就自动抓取，已同步过的不要重复抓，存入草稿后给我预览二维码。
```

✅ 指令写清 3 点就够了：原稿是什么、图插在哪里、存草稿后给预览二维码。不要写“帮我发布”，因为发表由你自己在手机上完成。

2. 3 登录与扫码

做什么： 让 Muse 能打开你的公众号后台，帮你存草稿。

步骤：

1. 在电脑上告诉 Muse：“我要登录公众号后台存草稿。”
2. Muse 会打开公众号后台登录页，并提示你扫码。
3. 打开你手机微信，点右上角“+”→“扫一扫”，扫电脑上的登录二维码。
4. 手机上点“确认登录”。
5. 等电脑页面跳到公众号后台首页，说明登录成功。

看到什么算成功：

- 电脑页面显示公众号后台首页，能看到草稿箱。
- Muse 告诉你“会话已保存”，之后一段时间不用重复扫码。

出错怎么办：

- 二维码过期：刷新页面，重新生成一个二维码再扫。
- 手机点完确认，电脑没反应：等 10 秒，刷新一次；仍不行，重新扫一次。
- 提示需要管理员验证：用管理员微信扫，不要用非管理员微信扫，非管理员扫完还需要管理员再验证一次。

2. 4 固定中国 IP 代理的作用与边界

你可能会听到 Muse 提到“固定中国 IP 代理”。小白只需要理解 3 点：

| 问题 | 答案 |
|---|---|
| 它是干什么的？ | 让 Muse 打开公众号后台时，走一个固定的中国 IP，保证登录稳定，不被平台判定为异常登录。 |
| 我需要做什么？ | 什么都不用做。Muse 会自己走代理。你不要把代理信息发给别人，也不要用它打开别的网站。 |
| 它安全吗？ | 代理只用于打开 `mp.weixin.qq.com`（公众号后台），不用于别的站点。 |

⚠️ 边界：固定中国 IP 只用于登录公众号后台。不要让 Muse 用它去登录 X、去打开别的网站，也不要用直连（不走代理）去登录公众号后台。

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/003.jpg)

2. 5 会话 storage 说明

Muse 登录后会保存一个会话文件，名字类似 storage.json。你只需要知道：

- 它相当于“已登录状态”，让 Muse 下次不用每次都重新扫码。
- 凭据不记录、不复述：Muse 不会在聊天里把你的密码、Token、代理账号密码等写出来，你也不要把这些发到聊天里。
- 会话会过期。如果 Muse 告诉你“会话过期，需重新扫码”，你就按第 2.3 节重新扫一次码即可。

✅ 记住一句话：凡是密码、Token、代理账号密码，都不要发到聊天里，也不要写进文章原稿里。

### 3. 准备你的第一篇文章：两种方式，任选一种

本章是全教程最关键的一章。两种方式最终效果一样：文章都会变成排版好的公众号草稿，等你手机预览 + 手机发表。区别只在“文章资料怎么到 Muse 手里”。

3. 0 两种方式怎么选：先看对比表，选一种

| 对比项 | 方式 A：手动提供素材 | 方式 B：全自动抓取 |
|---|---|---|
| 适合谁 | 不想在这台电脑登录 X 号的人；只想手动发资料给 Muse 的人 | 同一台电脑同时登录了 X 号和微信公众号的人；想让 Muse 全自动同步的人 |
| 需要什么 | 你手动把 X 号文章资料发到本机电脑：MD 格式正文 + 封面图 + 文中配图 | 同一台电脑浏览器已登录 X 号（能打开 X 文章列表）且已登录公众号后台 |
| 你的操作 | 每次把 MD + 图片发给 Muse，并发一句一键排版指令 | 第一次发一句一键开启指令，之后每天只需看预览 + 点发表 |
| 步骤数 | 每篇约 3 步：准备素材 → 发给 Muse → 手机预览 + 发表 | 首次约 3 步：确认登录 → 发开启指令 → 之后每天只需预览 + 发表 |
| 注意事项 | 素材要按 3.1–3.3 的格式整理好；IP / 凭据绝不写进原稿 | 遇到 X 登录墙 / 验证要停下报告，不要绕过；去重：已同步过的不要重复抓 |
| 是否已验证 | ✅ 已验证的主流程（首批 4 篇就是这么跑通的） | ⚠️ 流程已定义，但长期稳定读取方案仍需验证（见 3.5） |

怎么选：

- 如果你说“我不想在这台电脑登录 X 号”→ 选 方式 A，看第 3.1–3.4 节。
- 如果你说“同一台电脑我已经登录了 X 号和公众号”→ 选 方式 B，看第 3.5–3.6 节。
- 不管选哪种，排版、存草稿、预览、发表的检查标准都一样，见第 3.7 节和第 4–7 章。

3. 1 方式 A：手动提供素材——素材怎么准备

方式 A 的核心：你手动把 X 号文章资料发到本机电脑，Muse 收到后一键排版。

3. 1.1 你要发给 Muse 的东西：3 样，缺一不可

| 素材 | 格式 | 数量 | 例子 |
|---|---|---|---|
| 正文 | MD 格式（`.md` 文件或直接粘贴 MD 文本） | 每篇 1 份 | `文章标题.md` |
| 封面图 | JPG / PNG 图片 | 每篇 1 张 | `00-cover.jpg` |
| 文中配图 | JPG / PNG 图片 | 每篇若干张 | `01.jpg、02.jpg……` |

做什么：

1. 打开 X 号，找到你要同步的那篇文章，把正文复制成 MD 格式（见 3.1.2）。
2. 把这篇文章的封面图保存为 00-cover.jpg。
3. 把正文里的每张配图按出现顺序保存为 01.jpg、02.jpg……。
4. 把 MD + 所有图片一起发给 Muse（发到本机电脑的聊天里）。

看到什么算成功： Muse 回复你“图片已按锚点核对，封面 1 张 + 正文 N 张，齐了”，说明素材齐了。

3. 1.2 MD 正文怎么写

核心原则：原稿是什么，公众号就是什么。

Muse 只做排版适配，不改写你的正文、不增删你的实质内容。所以原稿写好，正文就不会错。

MD 格式模板（直接复制改一改就能用）：

```
# 文章标题

开头一句话：这篇文章能帮读者解决什么问题。

## 01. 第一个章节标题

这里写正文段落。每个段落讲一个点，不要把十个点挤在一个段落里。

- 列表项 1
- 列表项 2

~~~bash
这里写命令 / 代码，一行一个命令
~~~

## 02. 第二个章节标题

这里继续写正文。
```

写 MD 的检查清单：

- 标题只有一个，写在最上面
- 章节标题用 ## 开头，按顺序编号（01、02、03……）
- 代码、命令用 ``` 包起来，不要塞进普通段落
- 标点用中文全角（，。！？：；），代码里的英文符号保持原样
- 全文读一遍，没有错别字、没有漏段

3. 1.3 封面与正文图怎么命名、锚点插图位置怎么写

命名方法（照做就不会乱）：

1. 封面图命名为 00-cover.jpg。
2. 正文图按出现顺序命名为 01.jpg、02.jpg……。

锚点插图位置怎么写：

锚点就是“告诉 Muse 这张图插在哪里”的一行标记。在 MD 里每个要插图的位置，写一行锚点，例如：

```
[插图：01.jpg，插在这段文字后面]
```

例子：

```
## 01. 先讲清楚

这里是正文段落……

[插图：01.jpg，插在这段文字后面]

这里是下一段正文……
```

整理时注意：

- 封面图要横图、清晰，标题文字不要贴边。公众号封面会被裁成 2.35:1 左右，重要文字不要贴边（见第 5.6 节）。
- 正文图和锚点要一一对应：有几张图，就有几个锚点；锚点写了哪张图，就要发哪张图。

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/004.jpg)

出错怎么办：

- 图片发漏了：Muse 会告诉你缺哪一张，你补发那张即可，不要重发全部。
- 图片顺序错了：重新按 01、02…… 编号，再发一次编号后的清单。
- 封面被裁掉重要文字：换一张留白更多的封面，或把封面文字往中间移，重新发给 Muse。

3. 2 方式 A：IP 与凭据绝不写进原稿 + 头部笔记多余文字要删

3. 2.1 IP 与凭据绝不写进原稿（红线）

- 原稿里 不要写真实 IP 地址（例如 xxx.xxx.xxx.xxx 这种四段数字）。
- 原稿里 不要写密码、Token、密钥、Cookie 内容。
- 如果文章必须讲到 IP，写占位符，例如“你的代理 IP”“固定 IP”，不要写真实 IP。
- 如果文章必须讲到登录，写“用 Cookie 登录，全程不碰密码”，不要贴真实 Cookie。

⚠️ 一旦真实 IP / 凭据写进原稿，就可能被排版进草稿、甚至发布出去。发布前 Muse 会用 IPv4 正则帮你检查一次，但最好的办法是：原稿里一开始就不写。

3. 2.2 头部笔记类多余文字要删

有一种文字最容易混进正文：你写原稿时给自己留的笔记，例如：

```
https://oneai.click/
ChatGPT充值、X Premium开通、Gemini Pro18个月会员……
入口：https://oneai.click/
根据这个网址，制作宣传视频……
```

这些是“你写给自己看的提醒”，不是给读者看的正文。发给 Muse 之前，先把这类笔记删掉。

判断方法：

- 这句话是给读者看的吗？不是 → 删。
- 这句话是“待办、提醒、指令”吗？是 → 删。
- 删完之后，文章从标题到正文读起来通顺吗？通顺 → 说明删对了。

✅ 如果你不确定某段是不是多余文字，直接问 Muse：“这段是不是头部笔记，要不要删？” Muse 会帮你判断。

3. 3 方式 A：一键排版——你一句话发给 Muse，剩下的 Muse 自动做

方式 A 的“一键”意思是：你不用分多步指挥，你发一句指令 + 素材，Muse 自动跑完排版 → 校验 → 存草稿 → 给二维码。

3. 3.1 一键排版指令模板（复制即用）

模板 1：单篇一键排版（最常用）

```
按摸鱼绿排版，存入草稿，给我预览二维码。
原稿如下（MD 格式），配图已按锚点整理好：
[粘贴 MD 原稿]
[上传封面 00-cover.jpg + 正文图 01.jpg、02.jpg……，并写清每张插在哪里]
要求：全部左对齐，文末加固定广告和固定签名，IP 用占位符，不要改写正文。
```

模板 2：多篇按顺序一键排版

```
下面是 N 篇原稿，按顺序 1→N 排版并存入草稿，每篇存好后给我该篇的手机预览二维码。
第 1 篇标题：________
[粘贴第 1 篇 MD + 上传该篇配图]
第 2 篇标题：________
[粘贴第 2 篇 MD + 上传该篇配图]
要求：每篇按摸鱼绿排版，全部左对齐，文末加固定广告和固定签名。
```

模板 3：只改排版、不重发素材（返工时用）

```
这篇草稿要改排版：________（例如“全部改左对齐”“PART 卡片标题不要换行”）。
原稿和配图不用重发，直接用上次那份，改完更新草稿，给我新的预览二维码。
```

3. 3.2 你发完一键指令后，Muse 会自动做什么（你不用管细节）

| 步骤 | Muse 自动做什么 | 你会收到什么 |
|---|---|---|
| 1. 排版 | 按摸鱼绿主题排版：标题、段落、列表、代码块、图片、卡片都按统一风格排好，全部左对齐，窄卡片防换行 | — |
| 2. 校验 | 跑校验程序，确认 0 ERROR、0 WARNING 才继续（见第 4.4 节） | “校验通过” |
| 3. 上传图片 | 把封面 + 正文图 + 广告图一张张上传到公众号素材库，拿到线上地址，替换正文里的本地路径 | “图片 N/N 已上传替换” |
| 4. 存草稿 | 用后端接口把排版好的 HTML 存入公众号草稿箱 | “已存入草稿” |
| 5. 给二维码 | 生成这篇的手机预览二维码发给你 | 一张预览二维码图片 |

你发完指令后只需做：

1. 等 Muse 回你“已存入草稿 + 预览二维码”。
2. 扫预览二维码，按第 6.2 节清单检查。
3. 没问题就按第 7 章在手机上发表；有问题就截图发给 Muse 说“这里有问题”。

✅ 记住方式 A 的一句话：你发素材 + 一句一键指令，Muse 自动排版存草稿，你只需预览 + 发表。

3. 4 方式 B：全自动抓取——同一台电脑登录 X 号 + 公众号，Muse 全自动同步

方式 B 的核心：你不用手动发素材。只要同一台电脑同时登录了 X 号和公众号，Muse 就能自动去 X 上抓新文章，同步更新到公众号草稿。

3. 4.1 方式 B 的前提：同一台电脑同时登录

在用方式 B 之前，先确认 3 个前提，缺一个都不要用方式 B，改用方式 A：

- 同一台电脑：X 号和公众号在同一台电脑的浏览器里登录。不要一台电脑登录 X、另一台电脑登录公众号。
- 已登录 X 号：在同一台电脑浏览器里打开 https://x.com/7998l201/articles，能看到文章列表，不是跳转到登录页。
- 已登录公众号后台：在同一台电脑浏览器里能打开公众号后台首页，能看到草稿箱，不用重复扫码（或已按第 2.3 节扫码登录，会话未过期）。

怎么确认前提通过：

1. 在同一台电脑浏览器里，先打开 X 文章列表页，能看到列表 → 说明 X 已登录。
2. 再打开公众号后台首页，能看到草稿箱 → 说明公众号已登录。
3. 两个都能打开，再发一键开启指令（见 3.4.3）。

⚠️ 如果打开 X 文章列表页被跳转到登录页，说明 X 没登录或登录失效。这时不要让 Muse 强行抓取，改用方式 A 手动发素材，或先重新登录 X 再试。

3. 4.2 方式 B：Muse 全自动流程（每天自动跑）

Muse 在方式 B 下每天自动跑的流程是：

```
07:15 检查 X 是否有新 Articles
  → 有新文章？没有 → 今天不做，等明天再检查
  → 有新文章？有 → 自动抓取新文章
    → 抓正文 + 封面 + 文中配图
    → 按原稿原封不动搬运，只做排版适配
    → 存入公众号草稿
    → 生成预览二维码给你
  → 你手机预览确认 → 你手机发表
```

每一步 Muse 具体抓取什么：

| 抓取项 | 说明 |
|---|---|
| 新文章标题 | X 上新 Articles 的标题，原样搬运，不改写 |
| 新文章正文 | X 上新 Articles 的正文（MD / 富文本），原封不动搬运，只做排版适配 |
| 封面图 | 新文章的封面图，1 张 |
| 文中配图 | 新文章正文里的配图，按正文出现顺序抓取，插回对应锚点位置 |
| 发布时间 | X 上新文章的发布时间，用于去重和排序 |

怎么去重：已同步过的不要重复抓

Muse 抓取前会先核对“已同步清单”，避免重复：

- 对比标题：标题已在公众号草稿 / 已发表列表里 → 跳过，不重复抓。
- 对比发布时间 + 链接：同一篇文章只同步一次，即使 X 列表里还显示它。
- 抓取后记录：每次抓取成功后，Muse 会记下“已同步：标题 + X 链接 + 同步时间”，下次检查时先查这份清单。

✅ 看到什么算去重成功：Muse 告诉你“今天 X 有 N 篇新文章，其中 M 篇已同步过，跳过；剩余 K 篇是新的，已抓取并存入草稿”，说明去重生效了。

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/005.jpg)

排版与存草稿：和方式 A 一样

方式 B 抓取到的正文 + 图片，排版规则和方式 A 完全一样：

- 摸鱼绿主题，全部左对齐，窄卡片防换行（见第 4 章）。
- 文末加固定广告和固定签名。
- IP 一律用占位符，发布前 IPv4 正则核查为 0。
- 用后端接口存草稿，图片先上传拿线上地址再替换（见第 5 章）。

3. 4.3 方式 B：一键开启指令模板（复制即用）

模板 1：一键开启每天全自动同步（最常用）

```
从今天起每天 07:15 监控 X 更新，08:15 前把新文章准备好放进草稿。
X 账号是 @7998l201，文章列表页：https://x.com/7998l201/articles
同一台电脑已登录 X 号和公众号后台。
要求：有新 Articles 就自动抓取正文 + 封面 + 文中配图，已同步过的不要重复抓；
按原稿原封不动搬运，只做排版适配，全部左对齐，文末加固定广告和固定签名；
存入草稿后给我每篇的手机预览二维码，我预览确认后自己在手机上发表。
```

模板 2：只抓取一次（试一次，不开每天）

```
今天帮我抓一次 X 最新的一篇文章，同步到公众号草稿。
X 账号是 @7998l201，同一台电脑已登录 X 号和公众号后台。
要求：只抓最新 1 篇，已同步过的跳过；排版按摸鱼绿，存入草稿后给我预览二维码。
```

模板 3：停止每天自动同步

3. 4.4 方式 B 的限制：如实说明，不要硬抓

```
从明天起停止每天自动监控 X 更新，不再自动抓取新文章。
已经存入草稿的文章保持不变，我自己手动处理。

```

方式 B 虽然方便，但有 2 个真实限制，小白必须知道：

| 限制 | 说明 | 遇到时怎么做 |
|---|---|---|
| X Articles 列表页登录墙 | X 文章列表页在未登录状态下会重定向到登录页，列表看不到。这是 X 的登录墙，不是你的账号出了问题 | 先确认同一台电脑是否已登录 X 号；若未登录，先登录再抓；若已登录仍被墙，改用方式 A 手动发素材 |
| 长期稳定读取方案仍需验证 | X 的登录墙、验证、反爬策略会变，长期稳定自动抓取的方案仍需验证，不能保证 100% 每天都自动成功 | Muse 会如实告诉你“今天抓取失败，原因是登录墙 / 验证”；你改用方式 A 手动发素材即可，不要让 Muse 绕过登录墙 / 验证 |

⚠️ 不要让 Muse 绕过登录墙 / 验证。 遇到登录墙 / 验证，停下报告，改用方式 A 手动发素材。这是红线。

⚠️ 不要声称自动监控已部署。 在长期稳定读取方案验证通过之前，不要对外说“已经自动监控了”。Muse 会如实告诉你今天有没有成功监控、成功抓取。

3. 5 两种方式共用的检查：排版后校验 + 预览 + 发表前确认

不管你选方式 A 还是方式 B，下面 3 项检查都一样，必须通过才能发表：

| 检查项 | 标准 | 在哪里看 |
|---|---|---|
| 排版后校验 | 0 ERROR、0 WARNING（见第 4.4 节） | Muse 会告诉你校验结论 |
| 手机预览 | 按第 6.2 节清单全部通过：标题、正文、配图位置、广告只一次、签名、IP 占位符、封面裁剪、左对齐、卡片不换行 | 扫预览二维码，在手机上检查 |
| 发表前确认 | 确认是最新版草稿、是正式文章标题（不是测试草稿）、群发通知 OFF、定时 OFF（见第 7 章） | 在公众号助手发表页面确认 |

一句话总结第 3 章：

- 方式 A：你发素材（MD + 封面 + 配图）→ 一句一键排版指令 → Muse 自动排版存草稿 → 你预览 + 发表。
- 方式 B：同一台电脑登录 X + 公众号 → 一句一键开启指令 → Muse 每天自动抓取 + 排版存草稿 → 你预览 + 发表。
- 两种方式的排版、校验、预览、发表标准完全一样。

### 4. Muse 排版

4. 1 排版是什么

排版就是把你的原稿变成好看的公众号样式：标题、段落、列表、代码块、图片、卡片都按统一风格排好。

本教程默认用 摸鱼绿 主题：绿色为主色，清爽、适合教程类文章。你不需要自己选主题，直接告诉 Muse“用摸鱼绿”即可。

4. 2 排版规则：左对齐、防换行

Muse 排版时遵守两条硬规则，你不需要记代码，只需要知道效果：

| 规则 | 你看到的效果 |
|---|---|
| 全部左对齐 | 所有正文、列表、代码块、图注都靠左对齐，不居中 |
| 防换行 | 窄卡片里的短标题（例如“导出 cookies”）不会被挤成两行，会自动缩小字号，保证一行显示，同组卡片字号统一 |

⚠️ 如果你在手机预览里看到某段正文被居中了，或者某个卡片标题被挤成两行，立刻截图发给 Muse，告诉它“这里居中了 / 这里换行了”，Muse 会修复并更新规则。

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/006.jpg)

4. 3 广告与签名：Muse 会自动加上

Muse 排版时会自动在文末加上两样东西，你不需要每次都提醒：

1. 广告区：一张广告图 + 一段广告文案（充值入口 oneai.click/，价格以下单页为准）。
2. 作者签名：固定那两句（见第 1.3 节）。

检查方法：

- 打开预览，滑到文章最底部，确认广告只出现一次，签名只出现一次。
- 如果广告出现两次，或签名出现两次，告诉 Muse“广告 / 签名重复了”。

4. 4 校验 0 ERROR 的含义

Muse 排版完会跑一个校验程序。你只需要看结论：

| 结论 | 意思 | 你要做什么 |
|---|---|---|
| 0 ERROR、0 WARNING | 完全合规，可以存草稿 | 什么都不用做 |
| 有 ERROR | 有必须修的问题（例如某段居中了、某个标签没闭合） | 等 Muse 修好再存草稿 |
| 有 WARNING | 有需要确认的小问题 | 看 Muse 的说明，确认是否要改 |

✅ 记住：只有 0 ERROR、0 WARNING 才算排版通过。不要让 Muse 带着 ERROR 去存草稿。

### 5. 存入草稿

5. 1 什么是草稿

草稿就是“还没发布、只有你能看到的文章”。存入草稿后，文章不会立刻发给读者，你可以慢慢预览、修改，确认无误后再发表。

草稿箱长这样（文字示意）：

```
草稿箱
├─ 第 1 篇：手把手教你：让 AI 全自动运营一个抖音号（30 天实验全记录）
├─ 第 2 篇：让 Muse 全权运营微信视频号：手把手实操
├─ 第 3 篇：小红书英文启蒙账号：从 0 到全自动运营 · 完整手把手教学
└─ 第 4 篇：X 账号代理 IP 登录运营：手把手教程
```

5. 2 后端接口路线：为什么不用手动粘贴

你可能想问：“我能不能自己复制粘贴到公众号编辑器？”可以，但不推荐。原因：

- 手动粘贴容易丢样式：段落可能被截断、图片相对路径会被剥离、标题可能粘不上。
- Muse 走的是 后端接口路线：直接调公众号后台的保存接口，把排版好的 HTML 存进去，样式不丢失、图片不丢失。

你不需要理解接口细节，只需要知道：让 Muse 用后端接口存草稿，不要让它用手动粘贴 / UI 注入的方式存。

5. 3 图片上传与替换

Muse 存草稿时，会先把你的图片一张一张上传到公众号素材库，拿到线上地址，再把正文里的本地图片路径替换成线上地址。

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/007.jpg)

看到什么算成功：

- Muse 告诉你“图片 10/10 已上传替换”或“图片 9/9 已上传替换”，说明图都传上去了。
- 打开草稿，正文里的图片都能显示，没有破图、没有空白框。

出错怎么办：

- 某张图显示不出来：告诉 Muse“第 X 张图是破图”，Muse 会重新上传那张。
- 广告图上传失败：如果广告图原图太大（例如 PNG 约 3.1M），经代理上传容易重置。Muse 会自动转成 JPG（约 276K，视觉一致）再上传，你不需要手动转。

5. 4 草稿箱长什么样

登录公众号后台 → 左侧菜单 → 草稿箱，你会看到所有草稿。每篇草稿显示：

- 标题
- 封面图（缩略图）
- 更新时间
- 作者

5. 5 测试草稿绝不发布

在调试过程中，草稿箱里可能会出现测试草稿，例如标题是：

```
测试段落，仅用于探测保存接口，完成后删除。
后端接口试点小段落，用于捕获保存请求，勿发布。
```

处理方法：

- 绝不发布它们。 它们不是正式文章，发布出去会让读者看到乱码 / 测试文字。
- 在你自己的浏览器草稿箱里，手动删除这两篇测试草稿。
- 不要让 Muse 去删，Muse 不会自动删测试草稿。

⚠️ 测试草稿只能由你在自己浏览器里手动删。删之前再看一眼标题，确认删的是测试草稿，不是正式文章。

5. 6 封面 2.35:1 提示怎么检查

存草稿时，后台有时会提示封面比率是 2.35:1。这不是报错，是提醒你“封面可能被裁剪”。

检查方法：

1. 打开草稿，看封面图缩略图。
2. 确认封面标题文字没有被裁掉一半，重要画面没有被切掉。
3. 如果被裁了，在编辑器里点封面，调整裁剪框，把重要内容移进裁剪框内，再保存。
4. 如果封面看着正常，不用管这个提示，直接预览即可。

### 6. 手机预览

6. 1 怎么扫预览二维码

Muse 存好草稿后，会给你发一张手机预览二维码。

步骤：

1. 打开微信，点右上角“+”→“扫一扫”。
2. 扫 Muse 发给你的预览二维码。
3. 手机上会打开一个临时预览链接，显示这篇文章的排版效果。
4. 在手机上从头滑到尾，逐项检查（见第 6.2 节清单）。

✅ 预览链接是临时的，会在短期内失效。收到二维码后尽快扫，过期了告诉 Muse，它会重新生成一张。

6. 2 逐项检查清单（照着勾）

预览时，按下面清单逐项打勾，全部通过才能发表：

- 标题：标题文字正确，没有错别字，没有多余符号
- 正文：每个段落都在，顺序正确，没有漏段、没有乱码
- 配图位置：每张图都在它该在的段落后面，没有插错位置，没有破图
- 广告只出现一次：滑到底部，广告图 + 广告文案只出现一次，不在中间重复出现
- 签名：签名只出现一次，内容是固定那两句（除非你明确要求例外）
- IP 占位符：正文里没有真实 IP 地址，只有“你的代理 IP”这类占位符
- 封面裁剪：封面图没有被裁掉重要文字，画面完整
- 左对齐：所有正文都靠左对齐，没有某段被居中
- 卡片不换行：横滑卡片里的短标题都在一行，没有被挤成两行

检查方法：

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/008.jpg)

- 发现任何一项不对，截图发给 Muse，告诉它“第 X 项有问题，截图里红圈处”，Muse 会修复并重新给你新的预览二维码。
- 全部通过后，告诉 Muse“这篇预览没问题”，再去第 7 章发表。

6. 3 预览二维码出不来怎么办

偶尔会遇到：点“预览”后，弹窗一直不出来，二维码出不来。

常见原因与办法：

| 原因 | 办法 |
|---|---|
| 正文太大（例如约 197KB），预览生成超时 | 在你自己的浏览器打开该草稿，重新点“预览”，再生成一次二维码 |
| 网络波动 | 等 10 秒，刷新页面，再点一次“预览” |
| 会话过期 | 按第 2.3 节重新扫码登录，再点“预览” |

✅ 预览二维码出不来，不代表草稿没存好。草稿本身可能已经保存成功，只是预览二维码没生成出来，重新点一次即可。

### 7. 手机端发表

7. 1 发表前确认

发表前，先确认：

- 手机预览已按第 6.2 节清单全部通过
- 草稿是最新版（如果你让 Muse 改过排版，要用最新版的草稿，不要发表旧版）
- 你要发表的是正式文章，不是测试草稿（再看一眼标题）

7. 2 手机端发表步骤（公众号助手）

做什么： 在手机上用公众号助手 App 打开草稿，点发表，当场扫码验证。

步骤：

1. 打开手机上的 公众号助手 App（不是微信，是单独的公众号助手）。
2. 找到你要发表的草稿，点开它。
3. 点底部或右上角的 “发表”。
4. 在发表设置里确认：
   - 群发通知：OFF（关）
   - 分组通知：OFF（关）
   - 定时发表：OFF（关）
   - 如果默认是 ON，手动关掉再继续。
1. 点对话框里的 “发表”。
2. 在二次确认对话框里，确认显示“未开启群发通知”，点 “继续发表”。
3. 页面弹出 “微信验证” 二维码，用管理员 / 运营者微信扫码验证。
4. 手机上点“确认发表” / “验证通过”。
5. 等页面提示“发表成功”，记下发布时间和文章链接。

看到什么算成功：

- 草稿箱里这篇文章消失了（或状态变成“已发表”）。
- 已发表列表里能找到这篇文章，有发布时间和链接。
- 在微信里打开公众号，能看到这篇文章已经发出去了。

出错怎么办：

- 点“发表”后没反应：等 5 秒，确认网络正常，再点一次。不要连续快速点多次。
- 验证二维码扫了没反应：确认你扫的是当前活会话里弹出的二维码，不是之前截图发给你的旧二维码。旧截图二维码一旦浏览器关闭就失效了，必须用当前页面新弹出的二维码当场扫。
- 提示“需管理员验证”：用管理员微信扫，不要用非管理员微信扫。非管理员扫完还需要管理员再验证一次。

7. 3 为什么不要用截图二维码代扫

再强调一次，因为很多人会在这里踩坑：

- Muse 截图发给你的验证二维码，是截图那一刻的二维码。
- 截图后，如果 Muse 那边的浏览器关闭了，这个二维码就失效了。
- 你再扫这个截图二维码，系统认不出来，发布不会成功。

正确做法：

- 由你在自己的手机 / 浏览器活会话里点“发表”，当场弹出二维码，当场扫。
- 不要让 Muse 截图二维码给你代扫。

8. 每天自动运营：两种方式的每日流程

![](../images/ryan-muse-auto-sync-x-posts-to-wechat-guide/009.jpg)

8. 1 每天的节奏（两种方式对照）

| 时间（北京时间） | 方式 A：手动提供素材 | 方式 B：全自动抓取 |
|---|---|---|
| 07:15 | 你把今天要发的原稿（MD + 配图）发给 Muse | Muse 自动监控 X 账号 @7998l201（https://x.com/7998l201/articles）是否有新 Articles |
| 08:15 前 | Muse 一键排版并存入草稿，给你预览二维码 | Muse 自动抓取新文章并存入草稿，给你预览二维码（已同步过的跳过，不重复抓） |
| 白天 | 你：手机预览 → 确认无误 → 手机点发表 | 你：手机预览 → 确认无误 → 手机点发表 |

✅ 两种方式你每天都只需要做：看预览 + 点发表。其他都由 Muse 准备好放在草稿里。

8. 2 每天你只需做的事（复制即用）

每天早上收到 Muse 的预览二维码后，做这 3 步：

1. 看预览：扫预览二维码，按第 6.2 节清单检查一遍。
2. 告诉 Muse：没问题就说“这篇没问题”，有问题就截图说“这里有问题”。
3. 手机发表：按第 7.2 节步骤，在公众号助手里发表。

方式 A 的额外一步： 每天早上先把原稿 + 配图发给 Muse，并发一句一键排版指令（见第 3.3.1 节模板），再等预览二维码。

方式 B 的额外说明： 你不需要每天发素材。Muse 每天 07:15 自动检查，有新文章才抓取，没有新文章就不做，等明天再检查。Muse 会告诉你“今天有 / 没有新文章”。

8. 3 X 列表页登录墙的注意事项

X 的文章列表页（https://x.com/7998l201/articles）在未登录状态下会重定向到登录页，列表看不到。这是 X 的登录墙，不是你的账号出了问题。

对你的影响：

- 方式 B：Muse 监控 X 更新时，可能会因为登录墙看不到列表。Muse 会告诉你“列表页有登录墙，长期稳定读取方案仍需验证”。这时不要强求 Muse 去绕过登录墙，改用方式 A 把 X 文章原稿直接发给 Muse，Muse 一样能排版存草稿。
- 方式 A：不受登录墙影响，因为素材是你手动发的，不需要 Muse 去打开 X 列表页。
- 不要声称自动监控已部署：在长期稳定读取方案验证通过之前，不要对外说“已经自动监控了”。

### 9. 常见问题与排错

9. 1 左对齐变居中

现象： 本地预览是左对齐，存到公众号草稿后，手机预览里某段正文变成居中了。

原因： 某段正文没有显式写左对齐，继承了父容器的居中样式，到了公众号编辑器里被强制居中。

办法：

1. 截图发给 Muse，告诉它“这里居中了，应该左对齐”。
2. Muse 会把全篇改成显式左对齐，校验通过后再更新草稿。
3. 重新扫新的预览二维码，确认已经左对齐了。

9. 2 PART 卡片换行

现象： 横滑卡片里某个短标题（例如“导出 cookies”）被挤成两行，和其他卡片不统一。

原因： 卡片宽度不够，字号太大，放不下一行。

办法：

1. 截图发给 Muse，告诉它“这个卡片标题换行了，应该一行”。
2. Muse 会把同组卡片标题统一缩小字号（例如从 13px 降到 11px），并加防换行，保证一行显示。
3. 重新预览，确认所有卡片标题都在一行。

9. 3 预览二维码出不来

见第 6.3 节：通常是正文太大导致超时，在自己浏览器重新点“预览”即可。

9. 4 会话过期

现象： Muse 告诉你“会话过期，需重新扫码”，或者打开后台提示要登录。

办法： 按第 2.3 节重新扫码登录一次即可。不要把密码发给 Muse。

9. 5 验证二维码失效

现象： 扫了验证二维码，发布还是没成功，草稿还在草稿箱，已发表列表没有这篇。

原因： 你扫的是旧截图二维码，截图后浏览器已关闭，二维码已失效。

办法： 在你自己的手机 / 浏览器活会话里重新点“发表”，当场弹出新二维码，当场扫。不要用旧截图二维码。

9. 6 草稿箱测试草稿删不掉

现象： 草稿箱里有测试草稿，Muse 说“删不掉”。

原因： 自动化删测试草稿容易误删正式文章，所以 Muse 不会自动删。

办法： 在你自己的浏览器打开草稿箱，找到标题是“测试段落……”或“后端接口试点小段落……”的草稿，手动点删除。删之前再看一眼标题，确认是测试草稿。

9. 7 封面裁剪

现象： 封面图重要文字被裁掉一半。

办法： 在编辑器里点封面，调整裁剪框，把重要内容移进框内，再保存。或换一张留白更多的封面图。

9. 8 广告图上传重置

现象： 广告图上传时连接重置、传不上去。

原因： 广告图原图太大（例如 PNG 约 3.1M），经代理上传容易重置。

办法： Muse 会自动把广告图转成 JPG（约 276K，视觉一致）再上传。你不需要手动转。如果仍失败，告诉 Muse“广告图上传失败”，它会重试一次。

### 10. 安全与红线

10. 1 IP 不公开

- 任何原稿、排版产物、已发布文章里，都不要出现真实 IP 地址。
- 需要讲 IP 的地方，只写占位符，例如“你的代理 IP”“固定 IP”。
- 发布前，Muse 会用 IPv4 正则检查一次，确认是 0 处才发表。

10. 2 凭据不进正文

- 密码、Token、密钥、Cookie 内容，绝不写进原稿、绝不写进正文、绝不发到聊天里。
- 需要讲登录的地方，写“用 Cookie 登录，全程不碰密码”，不要贴真实 Cookie。

10. 3 不编价格

- 广告文案里不要编具体价格、折扣、会员时长承诺。
- 统一写“具体价格与服务以下单页为准”，以 oneai.click/ 下单页为准。

10. 4 未确认不发布

- 没有你的明确确认，Muse 不发布任何文章，也不发布测试草稿。
- 你的确认方式是：手机预览后明确说“这篇没问题”，或直接在手机上点发表。

10. 5 测试草稿不发布

- 测试草稿标题里写了“完成后删除”“勿发布”，就是告诉你：不要发布它们。
- 正式发表前，再看一眼草稿箱，确认你要发表的是正式文章标题，不是测试草稿标题。

⚠️ 上面 5 条是红线，任何时候都不要突破。突破一次，可能造成 IP 泄露、凭据泄露、或把测试文章发给读者。
