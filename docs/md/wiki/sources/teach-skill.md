# Teach Skill——一个好用的教学 Skill

> Matt Pocock 的 `mattpocock/skills` 中的 teach skill，将 AI 从「百科全书式的应答器」转化为「有状态的学习教练」。

![teach skill 执行过程](images/teach-skill/001.jpeg)

## 核心问题：AI 教学的困境

大多数人与 AI 讨论学习时，得到的是一次性、碎片化的知识灌输——你问一个问题，AI 给一段答案，会话结束，记忆清零。这种交互模式在查询事实时效率尚可，但在需要系统掌握一门知识时，却暴露出根本缺陷：

- 没有动机对齐
- 没有进度追踪
- 没有跨会话的连续性
- 谈不上根据学习者特点调整节奏

## teach skill 的解决方案

Pocock（TypeScript 教育领域的标志性人物）的 teach skill 是一份精密的 Agent 工作流规范，延续了他一贯「小、可组合、基于真实经验」的工程哲学。

**它并非一个庞大的教学平台，而是一份精密的 Agent 工作流规范**，核心目标是将 AI 从「百科全书式的应答器」转化为「有状态的学习教练」。

## 持久化教学空间

当你调用 `/teach` 并声明学习目标后，它不会立即展开讲解，而是首先在当前工作目录建立一个持久化的教学空间：

| 文件/目录 | 作用 |
|----------|------|
| `MISSION.md` | 记录你的学习动机与成功标准 |
| `RESOURCES.md` | 汇总高信任度的外部资源 |
| `learning-records/` | 追踪每节课掌握的非显而易见要点 |
| `NOTES.md` | 保存你的个人偏好 |
| `lessons/` | 课程文件 |
| `reference/` | 参考图表和练习素材 |

## 前置「动机澄清」环节

teach 会询问你学习的真实目的：

- 是为了讲授课程、准备考试、解决工程故障，还是设计实验电路？
- 你已有的知识边界在哪里？
- 偏好先建立数学模型还是先观察物理现象？

这些回答被写入 MISSION.md 后，后续所有课时的生成、资源的筛选、练习的难度都会围绕这些约束进行校准。

> 这种「先对齐，后交付」的思路，与 Pocock 其他技能中著名的 `/grill-me` 一脉相承，本质上都是在修复人机协作中最常见的失败模式：误解。

## 内容生成：递进式课时

teach 将知识拆分为递进式课时，每节课以核心问题驱动，结尾设置可验证的预测题。它主动检索权威资源而非依赖训练数据。

**执行流程：**

1. **动机澄清** → 生成 MISSION.md
2. **资源检索** → 生成 RESOURCES.md
3. **课程生成** → lessons/ 目录
4. **参考材料** → reference/ 目录
5. **学习记录** → learning-records/ 目录
6. **偏好记录** → NOTES.md

teach 不强制输出格式——可以是 Markdown 文本、可运行的代码文件，或是在需要可视化时生成的 HTML 演示文稿。设计重心始终落在「状态化工作空间」与「结构化流程」上，而非表面的排版形式。

> Pocock 的主张是：真正的工程价值在于流程与纪律，而非载体。

## 宏观意义

teach 代表了一种值得关注的趋势——将教育学的基本原理（动机理论、间隔重复、检索练习、支架式教学）封装为可复用的 Agent 技能。不是为了替代教师，而是为教学者和自学者提供一种「外脑」：一个能够记住你的进度、尊重你的偏好、引用权威资源、并保持教学连贯性的智能协作者。

## 安装方式
