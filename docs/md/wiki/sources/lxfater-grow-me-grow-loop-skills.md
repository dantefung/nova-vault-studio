# lxfater：grow-me + grow-loop——把需求问答画成生长树，给 AI 干活装刹车

> 「grill-me 让 AI 追问需求」的痛点：聊三四轮 AI 没忘、人脑先看晕，最后全回「按你推荐的来」，需求沟通走过场。开发者开源两个 Skill 把需求沟通与进度搬出聊天框：**grow-me** 在本地起网页把问答画成生长树——答完一题开花、追问顺依赖长新枝，哪个决定连哪步一眼清；中途改前面的决定，受影响的下游题自动变黄叶逼着逐题重认；答完出白话方案与验收表，把拍板原话和任务包打包交给下一步。**grow-loop** 用本地小脚本给执行装刹车：每个任务包先派常规模型写代码跑测试，修满 2 轮不过自动升档换强模型；强模型再修 2 轮还不过立刻刹车问人，绝不死循环烧额度；跑通后换另一模型只读挑刺最多 2 轮；推代码/改线上等高风险动作硬拦下来等人批。两套 MIT 开源、不另收接口费，直连本地 Claude Code / Codex，进度存本地、半路换工具也能接着干。

很多人学大牛用 grill-me，让 AI 动手前先一轮轮追问需求

结果聊了三四轮，AI 没忘前面的事，人脑先看晕了

最后干脆全回按你推荐的来，需求沟通彻底走过场，你说是不是？

有位开发者开源了两个给 AI 用的 Skill

叫 grow-me 和 grow-loop，直接把需求沟通和干活进度搬出聊天框（见图 1）

搬出聊天框，怎么让人脑不看花眼？

上游 grow-me 会在本地起个网页，把问答画成一棵生长树

答完一题开花，追问顺着依赖长出新枝，哪个决定连着哪一步一眼就清

中途想改前面的决定，受影响的下游题会自动变黄叶，逼着逐题重认，不会糊弄过去

答完保存，直接出白话方案和验收表

还把你的拍板原话和任务包打成清单，交给下一步

清单有了，但派 AI 按包写代码老返工、死循环烧额度怎么办？

下游 grow-loop 用本地小脚本，实现了下面的功能：

每个任务包先派常规模型写代码跑测试，修满 2 轮不过，自动升档换强模型接着修

强模型再修 2 轮还是不过，立刻刹车问人，绝不死循环烧干额度！

跑通后换另一个模型只读挑刺，最多审 2 轮

推代码、改线上这类高风险动作，也硬拦下来等你批

两套都是 MIT 开源，不另收接口费

直接接本地 Claude Code 或 Codex 跑，进度存本地，半路换工具也能接着干
