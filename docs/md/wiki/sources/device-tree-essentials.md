# 扒一扒设备树的外皮，看看它本质上是在做什么？

> 驱动负责怎么干活，设备树负责告诉它活在哪。

设备树是很多人学嵌入式 Linux 时的第一个拦路虎。你明明只是想点个 LED、读个按键、挂个 I2C 传感器，结果教程一上来就让你改 `.dts`、看 `compatible`、写 `reg`、配 `interrupts`。刚从裸机或 RTOS 过来的人，很容易觉得这东西绕。

裸机里直接写寄存器地址不就完了？为什么 Linux 非要搞一套设备树？

核心结论：

> **设备树解决的是"硬件描述"和"驱动逻辑"分离的问题。**

驱动不要写死某块板子的所有细节。设备树负责告诉内核：这块板子上到底有什么硬件，它们挂在哪，地址是多少，中断怎么接。

## 一、为什么不能都写在驱动里？

假设你有一个 I2C 温度传感器。裸机里你可能想：I2C 地址 0x48，挂在 I2C1 上，中断脚接 GPIOA3——直接在驱动里写死不就好了？

如果只有一块板，这么做确实简单。

但 Linux 面对的不是一块板。一个 SoC 可能被做成十几种开发板、几十种产品。传感器可能挂在 I2C1，也可能挂在 I2C3；中断脚可能接 GPIOA3，也可能接 GPIOB7；有的板有这个传感器，有的板根本没有。

如果这些都写进驱动里，驱动很快会变成"板卡大杂烩"。

设备树就是为了解决这个问题：**板子的硬件差异写在设备树里，驱动只关心这个设备应该怎么工作。**

## 二、设备树到底描述什么

设备树不是描述软件逻辑的，它描述硬件。常见内容包括：

| 字段 | 作用 |
|------|------|
| compatible | 告诉内核该用哪个驱动匹配 |
| reg | 设备寄存器地址或总线地址 |
| interrupts | 中断号和触发方式 |
| clocks | 使用哪些时钟 |
| gpios | 相关 GPIO 怎么接 |
| status | 设备启用还是禁用 |
| pinctrl | 引脚复用配置 |

你可以把设备树理解成**板级硬件说明书**——只不过这份说明书不是给人看的，而是给内核看的。

比如一个驱动问："我负责的设备在哪？"设备树回答："这个设备在 I2C1，地址 0x48，中断接 GPIOA3，compatible 是 xxx。"然后内核根据 `compatible` 把设备和驱动匹配起来。

## 三、compatible 为什么这么重要

`compatible` 是设备树里最关键的字段之一，作用很简单：

> 告诉内核：这个设备和哪个驱动兼容。

Linux 驱动里通常会有一个匹配表，写着自己支持哪些 `compatible` 字符串。内核启动时，拿设备树里的设备节点去和驱动匹配，匹配上了就调用驱动的 probe 函数。

![compatible 匹配流程](../images/device-tree-essentials/002.png)

如果你设备树里的 `compatible` 写错了，驱动可能根本不会 probe。很多新手调驱动调半天，最后发现不是代码没执行，而是设备和驱动压根没匹配上。

## 四、设备树和驱动怎么分工

| 内容 | 应该放哪里 |
|------|-----------|
| 设备挂在哪条总线 | 设备树 |
| 设备寄存器地址 | 设备树 |
| 中断号和 GPIO 连接 | 设备树 |
| 设备怎么初始化 | 驱动 |
| 寄存器怎么配置 | 驱动 |
| 数据怎么读写 | 驱动 |
| 给用户态提供什么接口 | 驱动 |

- 设备树不应该写业务逻辑
- 驱动也不应该写死板级连接

这就是设备树的核心价值。

## 五、status 为什么经常改

你会在设备树里经常看到 `status = "disabled"` 或 `status = "okay"`。这个字段控制设备是否启用。

很多 SoC 的 `.dtsi` 文件会把芯片内部控制器都描述出来，但默认可能是 disabled。具体到某块板子，如果这个控制器真的用上了，就在板级 `.dts` 里把它改成 okay，并补上引脚、外设节点等信息。

这也是设备树分层的好处：

- `.dtsi` 描述芯片公共硬件
- `.dts` 描述具体板子的硬件连接

SoC 是同一个，但板子可以不同。

## 六、设备树不是万能配置文件

设备树很重要，但不要把它当成万能配置文件。它适合描述硬件事实，不适合塞业务策略。比如"这个 GPIO 接了哪个按键"适合放设备树；但"按下这个按键以后进入哪个业务页面"就不该放。

一个简单判断：

> 如果换一套应用业务，这个信息仍然是硬件事实，那它适合放设备树。

比如 I2C 地址、中断脚、供电 GPIO，这些是硬件事实。产品逻辑、协议规则、业务策略，那是应用层或驱动参数该考虑的事。

## 七、总结

设备树看起来绕，但解决的问题很现实：

> 同一个驱动，要适配不同板子的硬件连接。

它把"这块板子有什么硬件、怎么连接"从驱动里拿出来，交给设备树描述。驱动只负责"这个设备怎么工作"。

记住这几句话：

- `compatible` 决定设备和驱动怎么匹配
- `reg` 描述地址
- `interrupts` 描述中断
- `status` 决定设备是否启用
- `.dtsi` 偏芯片公共描述，`.dts` 偏板级描述
