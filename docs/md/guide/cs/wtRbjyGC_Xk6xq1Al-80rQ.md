## 五、Socket：为什么后端服务大多选它？



既然共享内存最快，为什么 Nginx 和后端服务、Redis 和客户端之间通信，几乎都用 Socket？



因为 Socket 有共享内存没有的三个能力：



• 跨机器：同一套 API，本机通信和跨网络通信可以无缝切换



• 双向全双工：一个连接双向收发，不用建两个管道



• 天然配合 epoll：连接、消息事件都能纳入事件循环统一管理



对于本机通信，还有一个性能更好的选择：Unix 域套接字（Unix Domain Socket）。它不走网络协议栈，不需要 TCP 三次握手，不做校验和，只是在内核里搬运数据，性能比走 127.0.0.1 的 TCP 高出不少。



MySQL、Redis、Nginx 到 PHP-FPM，本机通信都支持 Unix 域套接字，这也是线上调优的常见手段。

## 七、高频面试题精析



Q1：Linux 进程间通信有哪几种方式？各自特点？



按"数据怎么传"分成三类：



• 内核中转：管道、FIFO、消息队列、Socket，数据要在用户态和内核态之间拷贝 2 次



• 内存共享：共享内存，映射同一物理页，零拷贝，但要自己同步



• 辅助机制：信号量（做同步，不传数据）、信号（异步通知，只能传信号编号）



Q2：共享内存为什么最快？



两个原因：一是零拷贝，数据不用在用户态和内核态之间来回搬；二是通信时没有系统调用，直接读写内存。但代价是要自己解决同步问题。



Q3：管道的读端和写端关闭后，分别会发生什么？



• 写端全部关闭：读端读完剩余数据后，read 返回 0（EOF）



• 读端全部关闭：写端再写会收到 SIGPIPE 信号，默认行为是终止进程。所以网络服务里通常要 signal(SIGPIPE, SIG_IGN)



Q4：System V 和 POSIX 的 IPC 有什么区别？



System V（shmget、msgget、semget）出现得早，用整数 key 标识，API 比较繁琐；POSIX（shm_open、mq_open、sem_open）用路径名标识，接口更接近文件操作，也更现代。新项目建议优先用 POSIX。



Q5：Unix 域套接字为什么比 127.0.0.1 的 TCP 快？



Unix 域套接字不经过网络协议栈：没有 TCP 握手，不用计算校验和，不做拥塞控制和重传，也不需要分片，数据只在内核里做一次简单的搬运。



Q6：共享内存里能直接放 std::string、std::vector 吗？



不能。 这些容器内部有指向堆的指针，而堆在各进程里的地址空间是不同的，另一个进程拿到指针后是野指针。共享内存里只能放 POD 类型，或者使用基于偏移量（offset）而不是绝对地址的数据结构，比如 Boost.Interprocess 的 offset_ptr。



## 结语



回到最初的问题，Linux 进程间通信有这么多种，本质上只是在回答一件事：



> 隔离的进程，通过内核这个"中间人"，用什么方式交换数据？



隔离的进程，通过内核这个"中间人"，用什么方式交换数据？



• 让内核帮你搬（管道、消息队列、Socket）：安全省心，但要拷贝 2 次



• 让内核帮你共享（共享内存）：零拷贝最快，但同步自己负责



没有最好的 IPC，只有最合适的。简单场景用管道，通用服务用 Socket，极致性能用共享内存——这句话，值得记住。
