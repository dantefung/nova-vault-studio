这几天更新的内容，就是用户进程如何从控制台，也就是硬件，读取到用户输入的。



分成两步。



第一步是用户进程通过 read 系统调用，发起读操作。



read 系统调用通过 vfs，找到 tty 对应的 read 函数（这个是在 open 阶段设置好的），执行 tty 的 read 函数，尝试从 tty 的 read buffer 里读数据。



一般情况下，此时的 tty read buffer 还是空的，因为我们还没有输入任何字符，所以当前进程阻塞等待。



第二步，我们通过键盘输出任意内容并回车，这些字符通过串口通信方式，被 pl011 硬件接收到，pl011 接收到后，会放到它们的 receive fifo 里，然后产生一个接收中断。



我们之前注册的中断函数会被调用，在这个函数里，会把 receive fifo 里的内容，转移到 tty port 的 buffer 里。



接着，tty port buffer 里的内容，会再经过 tty line discipline 里的规则，经过一定的处理后，转移到 tty 的 read buffer 里。



最后，唤醒用户进程，告诉它 read buffer 里有数据了，它可以读取了。



用户进程从 tty read buffer 读取到这些数据之后，把它返回到用户空间，也就是我们自己写的程序。



这样我们就可以处理这些用户输入了。



整个过程还是非常复杂的。



在这个过程中，你还能看到我们输入的 ctrl-c 是如何转成 SIGINT 信号，发给当前运行进程的，也能看到 magic sysrq key 是如何被处理的。
