## 神级 Skills 与用法心法

### 第一梯队（神级）

- [Meta-skill](https://github.com/search?q=meta-skill+claude-code) — 管理 skill 的 skill，自动观察→记录改进点→定时优化所有 skill
- [Superpowers](https://github.com/obra/superpowers) — 头脑风暴 + 项目规划，中小项目最佳
- [GSD (Get Shit Done)](https://github.com/gsd-build/get-shit-done) — 大项目工作流，流程比 prompt 重要

### 神奇小工具

- `/close` — 会话结束自动 memory + commit + 日志
- `/lastpic` — 抓桌面截图给 Claude 看 UI bug
- [Humanizer](https://github.com/search?q=humanizer+skill) — 干掉 em-dash 这种 AI 味
- [tonone](https://github.com/search?q=tonone+agent) — 23 个专家 agent，各管一摊领域
- [authsome](https://github.com/search?q=authsome) — 一次登录所有 SaaS，Claude 拿不到密钥
- [LLM Council](https://github.com/search?q=llm+council) (Karpathy) — 重大决策让多模型投票

### 垂类神器

- 设计：[57 种风格 skill](https://github.com/Phibrand/awesome-design-skills)
- 安全：Supabase Sentinel + Aegis
- 调试：Dendrite 7 步根因法
- 研究：paperloom（论文→Obsidian 图谱）
- 财务：openaccountants（报税）
- 商业：bulletproof-business-plan

### 用法心法

① 把 Claude 当流水线编排，别当问答机
② 写 skill 的 ROI 远大于写 prompt
③ skill 里最值钱的是 validator 和脚本，不是自然语言
④ 让 Claude 给自己写 skill，套娃才是终点
⑤ 跨 session 的 memory > 自动化 skill 优化

<summary>爆款快速测试 - Dan Koe（展开）</summary>

> [爆款快速测试](https://youmind.com/zh-CN/shortcuts/w2FdXthnumZ3cf)

核心观点：一句话描述你的想法，生成 3 种不同版本用于社交媒体快速测试：

**版本 A：极简断言型（≤140 字）**
- 直接抛出反常识结论
- 制造"等等，什么？"的停顿感

**版本 B：问题-洞察-行动型（≤200 字）**
- 开头：让目标读者共鸣的痛点问题
- 中间：一个反直觉的洞察
- 结尾：一个可立即执行的微行动

**版本 C：反常识钩子 + 证据型（≤180 字）**
- 开头：颠覆常识的观点
- 中间：简短的证据/案例
- 结尾：一句话行动建议

<details>
<summary>Dan Koe 长文写作风格（展开）</summary>

> [Dan Koe 长文写作风格](https://youmind.com/zh-CN/shortcuts/bGL4EQgltggPov)

**核心原则**：好内容 = 高价值信息 + 人的温度 - 机器的痕迹

**去 AI 味负面清单**：
- 禁止开头写"这是一个关于...的指南"
- 禁止 AI 惯用语：综上所述、毋庸置疑、不言而喻
- 禁止过度格式化，每段都变成列表
- 允许节奏变化，有的地方讲故事（长），有的地方给金句（短）

**叙事框架（APAG 模型）**：
- **Attention**：反直觉观点或痛点直接开场
- **Problem**：深入剖析现状
- **Amplification**：构建新的世界观或方法论
- **Guide**：提供具体可执行的步骤

</details>

<summary>社媒长文变短文 - Dan Koe（展开）</summary>

> [社媒长文变短文](https://youmind.com/zh-CN/shortcuts/ZkCp62xi0icEZx)

将 Newsletter 拆解为 4 种类型各 5 条（共 20 条）社媒内容储备：

- **类型 1：核心悖论**（5 条）— 提取反常识观点，制造认知冲突
- **类型 2：反直觉真相**（5 条）— 挑战主流观点，给出证据
- **类型 3：三步行动清单**（5 条）— 可立即执行的步骤
- **类型 4：常见错误 + 修正**（5 条）— 指出误区，给出正确做法

<details>
<summary>Gas Town 多 Agent 工作流（展开）</summary>

> 出处：[Steve Yegge - Gas Town](https://steve-yegge.medium.com/welcome-to-gas-town-4f25ee16dd04)

**Gas Town 工作流模式**：
- **proj agent**：负责任务分配和进度协调，给 dev agent 生成可直接复制的指令（包含参考文档、代码位置、核心工作内容）
- **dev agent**：专注于开发执行
- **tech agent**：负责代码 review 和文档修改
- **规则**：每个窗口固定一个 agent，严格隔离上下文

**优势**：proj 生成的指令比人工更详细（包含查看什么文档的什么位置），可以同时驱动多个 dev agent 并行干活，实现真正的多 Agent 协作开发。

</details>
