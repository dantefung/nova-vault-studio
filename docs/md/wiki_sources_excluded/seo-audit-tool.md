# 网站上线前，先用这个免费工具做一次 SEO 体检

> 前天看到哥飞分享了一个 On Page SEO 体检工具，刚好我有几个新站刚上线，就顺手拿它测了一下。

**工具地址**：[https://seo.web.cafe/audit/](https://seo.web.cafe/audit/)

---

## On Page SEO vs pSEO

先区分一下概念：

| 类别 | 说明 |
|------|------|
| **On Page SEO** | 关注单个页面本身有没有把 SEO 基础项做好：标题、描述、正文结构、关键词覆盖、页面抓取等 |
| **pSEO** | Programmatic SEO，用模板和数据批量生成页面，承接大量长尾搜索词 |

这次工具做的是 **On Page SEO 检查**。它本身不是 pSEO 工具，但很适合用在 pSEO 页面批量上线前做抽查。

## 用法

输入页面 URL，再输入几个关键词，它会自动选出聚焦度最高的主关键词，然后给这个页面做一次 On Page SEO 体检。

作者拿自己的一个新站页面测了一下，分数是 **65，C 级**——页面还有很多优化空间。

![测试截图](images/seo-audit-tool/001.png)

工具提示页面主题和关键词相关，但聚焦度不够，建议把关键词落进 Title、H1 和正文，让页面主题更准。

这个反馈对新手挺有用。很多时候做页面会先关心功能能不能跑、页面好不好看，但 Google 看到的是另一套东西：Title 写没写清楚，Description 有没有覆盖关键词，H1 和正文是不是在讲同一个主题，页面开头有没有快速说明重点。

![评分详情](images/seo-audit-tool/002.png)

## 它具体看哪些东西

主要分成三组检查：

### 1. 关键词覆盖

会看关键词有没有出现在：Title、Description、H1、H2/H3、URL 和开头 100 词里。

作者这次的结果：Title 和开头 100 词通过，Description 和 URL 没通过，H1、H2/H3 只算部分通过。

### 2. 页面基础项

分别打分：

| 项目 | 得分 | 说明 |
|------|------|------|
| Meta 元信息 | 25/25 | 通过 |
| 链接 | 7/7 | 通过 |
| 图片与媒体 | 8/8 | 通过 |
| 社交与结构化数据 | 10/10 | 通过 |
| 关键词优化 | 16/40 | **主要问题区** |

### 3. 页面状态数据

- 状态码（如 200）
- 加载耗时
- 页面体积
- 词数
- 内链 / 外链
- 图片数量
- 页面语言

这些信息不一定直接告诉你怎么改，但能帮你快速判断页面有没有明显异常。

## 最有价值的地方

把问题压得很具体。不会泛泛地说「SEO 不够好」，会直接指出：

- Description 没覆盖
- URL 没覆盖
- H1/H2/H3 只部分覆盖
- 关键词聚焦度偏低

这样你至少知道该改哪里。

## 适合放进页面上线前自查

1. 页面生成后，拿目标 URL 跑一次
2. 看主关键词聚焦度和总分
3. 优先处理 Title、Description、H1、正文开头、URL 这些基础问题
4. 改完后再看一眼分数和提示有没有明显改善

**对 pSEO 尤其有用**：pSEO 页面最容易出的问题，是模板一旦有缺陷，就会影响一批页面。比如模板没有把关键词写进 Description，或者 H1 写得太泛，单看一个页面问题不大。但如果几百个页面都是这样，后面再返工就很麻烦。

### 复制报告给 AI

工具还有一个按钮可以「复制报告给 AI」。把报告丢给 Codex、Claude Code 或其他 Coding Agent，让它先按提示改一版 Title、Description、H1 和正文结构。

> 如果你看过上一篇《独立开发者的网页杂活，可以交给这款免费 Agent 浏览器》，也可以把它和这种页面检查工具联动一下，让 Agent 打开网页、提交 URL、读取结果。

## 它不能替代 SEO 判断

页面分数高，只能说明基础 On Page SEO 做得比较完整。关键词有没有搜索量、竞争强不强、页面有没有真正解决用户问题，还是要自己判断。

但对刚开始做工具站、内容站，或者正在批量做 pSEO 页面的人来说，这个工具已经够实用了。它不解决所有 SEO 问题，但能帮你在上线前挡掉一批低级错误。

> 尤其是 Title、Description、H1、URL、正文开头这些地方，早一点检查，后面就少一点返工。
