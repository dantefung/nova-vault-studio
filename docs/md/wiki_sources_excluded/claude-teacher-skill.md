# 我把 Claude 官方教师 Skill 装进了自己的备课系统

> 安装指令（发给你的 Agent）：帮我装上 github.com/anthropics/k12-teacher-skills

前段时间，作者写过一篇 Claude 教师版——接了课标知识图谱和教学 Skills 的教育智能体。但由于 Claude 很难访问，教师版账号更难获得，说得热闹也没真正用上。

最近，Anthropic 把 Claude for Teachers 内部使用的两套 K-12 教师 Skill 完整公开到了 GitHub：

- **k12-lesson-planning** — 从 0 开始设计教案
- **k12-lesson-differentiation** — 拿已有教案，为不同学习水平的学生重新设计支持

![Skill 仓库概览](images/claude-teacher-skill/002.png)

把两套 Skill 装进 WorkBuddy，备了一次课——任务很简单：七年级生物开学第一课，「生物与非生物」。

![任务输入](images/claude-teacher-skill/003.png)

连课本都没有，但 Skill 问他用哪本教材，就找到了真正的第一课。

第一套 Skill 跑完，得到三份 Word：

1. 45 分钟版教师教案
2. 学生讲义
3. 听课观察模板

![第一套 Skill 产物](images/claude-teacher-skill/004.png)

接着把课程交给第二套差异化 Skill，又生成了四份文件：

1. 教师分层教学方案
2. A、B、C 三组学生材料

![第二套 Skill 产物](images/claude-teacher-skill/005.png)

**一句备课要求，最后变成了七份互相关联的教学文件。**

这时才真正理解，Anthropic 所说的 Skill 和我们平常保存的一段「万能备课提示词」，区别到底在哪里。

![对比说明](images/claude-teacher-skill/006.jpeg)

## 一、仔细看：两套 Skill 给你带来了什么样的教案

如果只是普通 AI 备课，很容易得到一份我们看过无数次的结构：

> 导入 — 新授 — 活动 — 总结 — 作业

Claude 官方 Skill 做的第一件事，却不是急着填教案栏目。他会询问你切入点、受众对象、教材版本。

![Skill 提问界面](images/claude-teacher-skill/007.png)

然后把一节课设计成：

> 现象导入 → 探究分类 → 论证讨论 → 写作建模 → 模型修订 → 通关测试

以「生物与非生物」这节课为例，四个环节：

| 环节 | 内容 |
|------|------|
| **起** | 播放黏菌寻找食物的延时影像，问学生：它到底是不是活的？ |
| **承** | 学生拿到猫、向日葵、蘑菇、机器人、石头、病毒等分类卡，放进「生物/非生物」两个盒子，同时在学案里记录观察、判断和证据 |
| **转** | 机器人和病毒被故意留下来成为争议项。学生不能只说「我觉得机器人不是生物」，而需要回到正在形成的「生命特征清单」中寻找依据 |
| **合** | 回到开头——你现在还认为黏菌是生物吗？哪一条证据改变了你的判断？ |

> 「起承转合」是作者为讲这份教案做的标注，并非 Skill 内容

目标、课堂任务、学生材料和形成性评价被整合在了同一个结构里。

### 差异化 Skill 的表现

把已设计好的课程交给差异化 Skill 后，它没有重新设计三节不同难度的课。

![差异化方案](images/claude-teacher-skill/008.jpeg)

三组学生面对的仍然是同样的「什么是生物」，仍然使用同一批分类卡，也要达到同一个目标：

> 基于观察证据，论证某物是生物还是非生物。

**区别主要在于学习支架上：**

- **A 组**：提供示例行（如「猫——会吃食、会动、会朝声音转头——需要营养、能对外界刺激作出反应」）和句式支架（「我主张\_\_。我的证据是\_\_。这支持我的判断，因为\_\_」）
- **B 组**：减少这些结构化帮助
- **C 组**：在原任务上增加一个要求——「有人说『会动的就是生物』。写出一条能够反驳这个说法的证据，并说明为什么它不成立」

作者最佩服的点：**这套 Skill 在努力维持一整套教学设计之间的关系，保证教学评的一致性。**

## 二、拆开看：Skill 不只是更长的提示词

很多人第一次听到 Skill，会把它理解成「高级提示词」。甚至我们自己设计 Skill 时，也很容易沿着这个思路，把一段两百字提示词扩展成两千字。Anthropic 公开的仓库提供了一个很好的反例。

![Skill 文件结构](images/claude-teacher-skill/009.jpeg)

一套完整的 Skill 包含的东西，更接近一套**写给 AI 看的工作规程**：

![Skill 工作顺序](images/claude-teacher-skill/010.jpeg)

Skill 规定了一套工作顺序：

1. 首先区分：这是从 0 设计一节新课，还是修改一份已有课程
2. 如果是新课，识别年级、学科、主题、时间以及真正缺失的背景信息，还不能无限追问（这是个工程学设计）
3. 然后调用相应学科的教学原则——科学课不会因为「教案模板」里有「教师讲解」这一栏，就自动变成教师解释概念、学生抄笔记
4. 完成课程以后，学生材料、教师教案和观察评价之间必须保持一致

所以，让第二套 Skill 做差异化时，它也没有把原课推翻重来，而是先保留共同学习目标，再改变学案里对学生完成任务的支持程度。

**Skill 规定的是：**

- 什么时候追问，什么时候查资料
- 先做什么，后做什么
- 哪些东西可以改变，哪些东西必须保持
- 生成以后又该用什么标准检查

## 三、长远看：这份 Skill 里最有价值的是三个教学判断

![Skill 文件树](images/claude-teacher-skill/011.jpeg)

每个人都可以保存这套 Skill，每个人也可以在 Claude for Teacher Skill 的基础上作出更适合自己的版本：

> 我很喜欢这套 Skill，请帮我改造成更适合我的版本，你可以问我对于课标、教学法、学段的偏好。

交互几轮下来，就做出了专属备课 Skill，还可以随着使用不断升级：

> 根据我近期使用该 Skill（@你的专属备课 Skill）之后作出的更改，更新当前 Skill

### 三个最有价值的教学判断

**1. AI 备课不能只有一个万能模板**

Anthropic 的做法是先识别学科，再调用对应的教学原则。作者测试的七年级生物，最后形成的是「现象—观察—证据—论证—模型修订」的学习过程，而不只是把知识点填进「导入—新授—练习—总结」的格子。

> 真正值得做成 Skill 的，不是某种固定教案格式，而是一个备课思路

生物课怎样使用现象和证据，历史课怎样处理史料，数学课怎样使用模型——这些才是教师真正值得保存下来的专业经验。

**2. 差异化应该改变支持，而不是降低目标**

第二套 Skill 最值得留下的一条原则：让不同学生继续面对共同的核心任务。

> 共同目标，不同支架；增加支持，鼓励思考。

**3. AI 生成的材料也需要「出厂检验」**

过去看 AI 备课，最容易关注一份教案写得漂不漂亮。这次更值得注意的，是七份文件能不能彼此对得上——教师教案要求什么，学生材料就真的做什么；课堂观察和出门测，又继续检查同一个学习目标。

> 一套成熟的 Skill 不应该只告诉 AI「怎么生成」，还应该规定：什么情况下，这份材料才能交付。

## 回顾

回头看，作者原本只是想把 Claude for Teachers 里的两个 Skill 搬出来，看看能不能在自己的 Agent 里跑起来。真正跑完一轮以后，更在意的却不是那七份 Word，也不是以后究竟用 Claude、ChatGPT 还是 WorkBuddy。

> 模型可以换，平台可以换，课程标准和教材也会变化。真正值得长期积累的，也许是一套越来越清楚的教学判断：知道什么值得保留，什么需要修改，以及一节好课为什么这样设计。

> 只要基本功足够硬，什么时候开始 Vibe Coding 都不太晚。
