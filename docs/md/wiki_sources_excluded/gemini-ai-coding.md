# 【万字】Gemini 到底能不能杀死程序员？聊聊 AI 编程

> AI 编程很重要，但它不会消灭程序员——它进入的是「自然语言编程」时代，消灭的是只会工具使用的「代码搬运工」。

## 核心观点

近年与律师、医生、教师、工程师、分析师等"传统中产"群体交流，发现他们**愿意学 AI 且学得有模有样**——能用 Coze 搭工作流，甚至开始零代码基础做 AI 编程。这从侧面印证：**编程门槛在急剧下降**，Gemini 3.0 发布时"前端已死"的渲染也可窥见端倪。

![律师行业 AI 交流](images/gemini-ai-coding/002.jpeg)

结论有三：

1. **AI 编程很重要**，对程序员行业影响巨大；
2. 但**说 AI 消灭程序员是不对的**——我们进入的是**自然语言编程时代**；
3. 真实复杂 AI 项目里，核心代码约 1 万行，提示词却大几十万行。**提示词的编写就是自然语言编程**，AI 消灭的是只会套用工具、被称"代码搬运工"的那部分人。

> 开发范式正在转移：程序员接下来需要和很多"非专业"人士（产品经理、医生、律师）抢占提示词编写权限。

## 学习路径：实践是最好的老师

AI 行业变化过快，仅以工具、技巧的方式学习很容易做无用功。两条准则：

- **以战练兵**：想办法解决实际问题，带目标学习，效率最高；
- **打好基础**："以战养战"下限很低，需系统性学习，AI 技术基础能力的重要性远超一切。

零基础学 AI 编程的三个爬坡阶段：

1. **提示词工程**
2. **理解工作流**
3. **案例实践**

## AI Coding 方法论

以下以一个**毫无技术背景的产品经理**视角展开 AI 结对编程。实际开发流程包含：需求拆解、架构设计、提示工程、代码生成、多轮迭代、前后端搭建和部署测试。

AI Coding 的核心思路：**让 AI 参与每个开发阶段，充当智能助手或"结对编程者"**——你是产品经理，它是程序员。

### 一、需求拆解

写代码的前提是需求明确。第一步是把业务梳理成清晰的功能（技术）模块。

以"用户反馈收集工具"为例，拆解为：

1. 前端页面（反馈表单）
2. 后端 API（提交反馈、存数据库）
3. 管理后台（查看/导出反馈列表）

**错误做法**：直接告诉 AI"帮我做个收集反馈的工具"。

若对互联网项目流程一无所知，可启用 **AI 协助**，问"需要哪些技术组件""该用什么前后端技术栈"等，模型会给出技术选型。提问时要**尽可能提供上下文和限制条件**：

> 我需要一个 Web 应用来收集用户反馈。每天约有 100 条反馈，需存储文本和用户联系方式。我希望有一个简单后台查看所有反馈。请问我应该选择怎样的前端、后端框架和数据库？需要哪些主要模块？

提示词需明确需求细节和非功能需求（规模），AI 才能给出更定制化的方案。

### 二、架构设计

确定页面、后台服务、数据存储及其交互。可让 AI 拆解前后端任务、生成项目结构：

- **拆解任务**：前端页面填反馈、后端接口接收、管理端查看/导出，请 AI 检查是否全面（AI 会提醒表单验证、错误提示等细节）；
- **生成结构**：`index.html`, `feedback.js`；`app.py` / `server.js`；`schema.sql` 等。AI 建议的结构是通用的，需结合实际调整。

有技术背景的 PM 可让 AI 给出 API 设计：

> 请设计反馈接口的 API，包括请求方法、URL、请求参数和返回格式

AI 会产出类似 Swagger 风格的描述（`POST /api/feedback - Body: {user, contact, message}`），大大加快后续实现。

### 三、提示词编写

用清晰语言"告诉" AI 想要的功能和行为，是 AI 编程最核心的一环：

> 请使用 Python Flask 创建一个简单的待办事项(Task)管理 API，包括：列出任务(GET /tasks)、新增任务(POST /tasks)、删除任务(DELETE /tasks/id)。每个任务包含 id、title、done 三个字段。请给出完整的 Flask 后端代码。

AI 会据此生成可工作的后端雏形，再进一步要求它为前端提供 HTML/JS 代码交互。

### 四、迭代开发

单轮就能成功的情况很少见，需要不断追问、澄清、追加要求。**迭代是常态**，你要扮演"产品经理"和"测试"的角色：

1. **生成初版代码**：运行测试观察基本功能；
2. **分析问题反馈 AI**：把具体问题（bug、缺验证、UI 丑）反馈给 AI，它拥有上下文能定位问题；
3. **引导 AI 修复**：要求修改代码，仔细检查改动，学习 AI 如何定位解决问题；
4. **反复测试**：模拟用户行为，提交空内容、并发提交等，发现的新问题再交给 AI。

#### 插曲：调试技巧

- **保持每次修改单一性**：一次只让 AI 改/加一处功能，便于定位新问题；
- **勇于推翻重来**：AI 可能引入冗余或绕路实现，代码质量下降就从头再生成——**因为你需求描述得更好了，第二遍往往更清晰，且推倒重来几乎零成本**；
- **保存每个阶段代码**：便于回退或比较版本差异。

### 五、集成

分别生成前后端后，需确保接口路径、数据格式一致。最好**在同一个上下文**里让 AI 了解前后端需要配合（先生成后端，再让同一 AI 生成前端）。

不同模型/工具生成的，可把后端规范提供给前端 AI 对齐。前后端集成常见问题是**跨域（CORS）**——把错误信息贴给 AI，它会指导在后端添加 CORS 支持。

### 六、部署

对原型项目，前端托管静态服务（GitHub Pages、Netlify），后端部署云服务（Railway、Heroku）。最难的部署流程也可完全交给 AI 指导：

- **环境搭建**：问"如何将 Flask 应用部署到云服务器"，AI 给出安装依赖、启动方法；
- **云服务**：很多平台提供一键部署，只需编写配置。

部署后邀请小范围用户试用，收集新需求再反馈 AI 迭代。

## 案例实操：TRAE 开发反馈收集工具

以更适合国内用户的 **TRAE** 为例（可用海外版，国内限制部分基座大模型调用），配合 **ChatGPT** 提供初始信息和提示词。

### 一、代码之前

先用 ChatGPT 梳理后端项目结构，复制到 TRAE：

![项目结构梳理](images/gemini-ai-coding/004.png)

```
feedback_app/
├── app.py                    # Flask 入口
├── config.py                 # 配置文件
├── extensions.py             # 数据库、JWT、CORS 扩展初始化
├── models/feedback.py        # Feedback 模型
├── routes/
│   ├── feedback_api.py       # 用户反馈接口
│   └── admin_api.py          # 后台管理接口
├── services/
│   ├── feedback_service.py   # 反馈业务逻辑
│   └── admin_service.py      # 管理员业务逻辑
├── utils/
│   ├── auth.py               # JWT/Token 工具
│   ├── validators.py         # 参数校验
│   └── pagination.py         # 分页工具
└── requirements.txt
```

**经验**：把单个文件（或几个文件、区域选中的代码）给到对话框，**不要整个文件夹**——token 消耗极快，编辑器反应慢。

### 二、后端

让 ChatGPT 生成"如何给 AI 编辑器定义要求"的提示词；编写前把智能体切到 **Builder 模型**（才有权限写文件）。

![TRAE 后端代码生成](images/gemini-ai-coding/005.png)
![项目运行成功](images/gemini-ai-coding/006.png)

TRAE 编写中会主动请求运行命令行，点击允许即可。**建议不要添加任何命令行到白名单**——TRAE 偶尔会抽风删改文件，代码复杂时反而增加审查工作量。

启动后可用 Postman / Apifox 测试接口，或把 controller 层文件交给 AI 整理接口文档。

### 三、前端

新开 TRAE 窗口生成前端框架，把后端接口文档交给编辑器，让它阅读文档对接后端接口。配置本地 SQL 服务（或安装 SQL 插件访问 .db 文件）验证数据链路。

![前端框架搭建](images/gemini-ai-coding/007.png)
![前后端联调成功](images/gemini-ai-coding/008.png)

### 四、调试迭代

梳理待优化问题（页面丑、启动无登录页）逐项解决。**美化 UI 的提示词**可让 ChatGPT 生成，并切换表现更好的基座模型（如 Gemini-2.5-pro 美化前端优于其他模型）。

![登录页面](images/gemini-ai-coding/009.png)
![UI 美化效果](images/gemini-ai-coding/010.png)

编辑器启动项目报错时会自动识别并改正；多次修改后添加新功能（待办事项）、做前后端联调、加日志，直至流程完整。

### 五、建议与提交

实际使用中 **Cursor 效果更好**（Claude Code 国内难以选用），但工具同质化会越来越严重。完成后用 `git init` → `add .` → `commit` → 推送到 GitHub，或直接用可视化工具提交。

![优化后页面展示](images/gemini-ai-coding/012.png)

### 六、后端部署

后端部署到 **Railway**：把 Railway 地址给编辑器，让它读取对接文档、识别报错信息、修改配置达到部署要求。

![后端部署到 Railway](images/gemini-ai-coding/013.png)

### 七、前端部署

前端用 **Netlify** 部署，把报错信息（最好连网站地址）交给 ChatGPT 结合实际情况分析修改。

## AI 编程工具选择

各基模都在卷编程模块——编程很接近"造物主"，基座能力越强，后续 Agent 工具调用和自我进化越快。从 GitHub Copilot、Trae，到 ChatGPT、CodeBuddy，各家卷得飞起。

评测维度：**可用性、代码生成质量、稳定性、语言支持、集成能力、安全与隐私、适用场景、用户类型适配性**。但同质化比较严重。

### 可用性

- **Copilot** 插件式集成，无缝接入 VS Code / JetBrains，近零学习成本；
- **CodeBuddy** 支持多 IDE + CLI，安装简便；
- **Cursor** 独立编辑器，界面接近 VS Code，上手较快；
- **Replit** 在线 IDE，学习曲线平缓，学生/初学者易上手。

> 很多非专业开发者把 Cursor 这类 IDE 当智能体用（帮他们做文件读取）——Coding IDE 演变为 Agent 的模式会很顺滑。

### 代码质量

模型能力决定输出质量。现阶段公认较强的是 **OpenAI 和 Claude**，Google Gemini 表现强势：

- **ChatGPT**：代码理解和生成极强，复杂算法、边缘案例接近最佳；
- **Claude**：上下文窗口大，可一次分析上百页代码，擅长超长文本；
- **Gemini 3.0**：主打"杀死前端"。

工具逻辑很清晰——**"你的能力 60 分，我做到 70 分就行"**（Cursor、Manus 皆是此思路）。场景化（本地化）体验也很关键：**Trae 针对中文编程做过优化**，对中文注释、变量名处理更好，中文需求支持大概率超过 Cursor 和 Claude Code。

### 稳定性

包含工具本身稳定可靠 + 生成代码的一致性和可控性。Claude Code 这类针对性工具国内难选。**直接无脑选大厂**，不怕突然关门。

### 集成能力

指与现有工作流、开发环境、工具链的结合。Copilot 插件即插即用、集成广泛；Cursor/Trae 内聚强但局限于自身环境；CodeBuddy 支持多端、灵活性独树一帜。企业选型应盘点团队现有环境。

## AI 编程的局限性

尽管威力惊人，仍有明显边界需理性看待：

### 小众领域无力胜任

AI 对**芯片编程、硬件编程、并行计算底层优化**等仍显无力。原因：

- **训练数据极少**，模型掌握有限，甚至因公开代码匮乏而不了解基本语法；
- **没有针对性微调**，即使提供样例也易出错或遗忘规则（如让 AI 写 Zig 语言可能答不上）；
- 企业内部**自研 DSL** 同理——拿开源模型写肯定一问三不知。

**AI 能帮忙的范围与训练数据范围密切相关**，超出即"无米之炊"。

### 为什么不训练？—— ROI 过低

模型训练遵循**二八原则**：解决 20% 常用的增删查改、网页/小程序设计，已能解决市场上 80% 的问题，基模没兴趣花大力气解决长尾问题。

### 模型的本质缺陷

当前模型看似聪明，实则仍在**概率堆积**；即便引入 CoT 思维链，效果也有限——生成模式一旦走错一步，会错误连锁，很难自行完全纠正。AI 前端的强力效果其实是基模花大力气训练出来的。

### 应对：微调 + 提示词

- **微调**：解决小领域问题的可行方向，但困难很多；
- **提示词做产品训练**：不能说完全没效果，但意义不大——模型可能连基本语法都没学会，且上下文装不下"一本书"。

---

## 结语

**小众领域 AI 编程能力的提升 = 工程技术 + 领域 KnowHow 的组合。**

通过微调、提示等技术教会 AI 专业知识，同时依赖领域专家的输入和验证闭环，让 AI 不断迭代更可靠。而**如何借助 AI 获得工程技术（工具使用能力），再运用领域 KnowHow 解决实际问题，就是 AI 编程真正的核心。**

AI 编程并不难，它也不会一定淘汰谁，只是**"懂业务"被提到了更重要的位置**。
