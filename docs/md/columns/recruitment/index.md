# 智能招聘：AI 驱动的 HR 工作流自动化

## 核心路径

### 第一阶段：业务拆解

招聘流程的痛点：
- **筛选流程两道关**，评价标准不一致 → HR 推过去的简历业务部门不想要
- **简历入人才库**，录入工作量巨大
- **一天上百份简历**，很多根本没被 HR 打开过 → 靠抽签决定生死

### 第二阶段：AI 适用边界

**适合 AI（规则可循）**：
- 信息提取（字段固定）
- 结构化存储（填表）
- 简历打分（标准事先定义）
- 面试问题准备（基于简历内容生成）

**必须人工（专业判断/沟通）**：
- 最终面试决策
- 跟候选人深度沟通
- 谈 offer

### 第三阶段：技术架构

```
自动化任务（每日 9 点）
    ↓
hr-resume Skill（自定义）
    ↓
├─ 邮箱连接器（采集附件）
├─ 飞书连接器（多维表读写）
└─ 评分 + 推送（自动）
```

### 第四阶段：渐进式落地

> **不要一开始就追求覆盖整个流程，先把几个高频环节跑通，效果稳定后，再逐步接入后续的流程，渐进式推进反而更稳妥。**

## 评分标准（核心）

| 维度 | 权重 |
|------|------|
| 学历匹配度 | 10% |
| 经验相关性 | 30% |
| 技能契合度 | 10% |
| 项目深度 | 30% |
| 稳定性指标 | 10% |
| 综合潜力 | 10% |

每个维度满分 10 分，加权后总分满分 10 分。**得分 ≥ 8 分自动推送业务负责人**。

## 持续校准

自动化流程上线后，**真正的难点不是搭建而是校准**：
- 岗位要求会变 → 评分标准跟着调
- 业务负责人判断会变 → 评分标准同步调整
- 典型问题：某岗位推 10 份高分简历给业务负责人，只有 2 份符合要求 → **说明评分标准不合理，重新校准**
