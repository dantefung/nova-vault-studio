# DeepSeekHarness 的新范式：让 Agent 为自己构建工具

> dsh 的「一切皆插件」架构——Agent 在对话中途发现自己缺一个能力，可以当场写成插件、加载、调用、用完即销毁。能力不是出厂配置，而是现场装配。

---

## 核心观点

大多数 AI 助手的工具集是「出厂配置」，DeepSeek Harness 换了一种哲学：**一切皆插件，插件即插即用**。

## 脚本 vs 插件

| 维度 | 写脚本执行 | 造插件 |
|------|-----------|--------|
| 能力形态 | 一次性动作，执行完即消亡 | 注册为工具，进入模型工具箱 |
| 再次使用 | 每次重新写、重新执行 | 同会话内随叫随到、反复调用 |
| 中间状态 | 跑完就没了 | 可记住进度、计数等状态 |
| 定时/监听/后台 | 做不到 | 平台原生支持，不用时自动清理 |
| 界面 | 只有文本输出 | 可带实时界面：进度条、按钮、可视化 |
| 升级与回滚 | 改了就是覆盖，旧版本丢失 | 版本化，随时回滚 |
| 授权 | 只受执行环境约束 | 涉及界面时，加载前经过用户授权 |
| 清理 | 代码残留在目录和对话里 | 停止销毁，界面、工具、状态零残留 |

## 五条最佳实践

| # | 原则 | 说明 |
|---|------|------|
| 1 | **能力按需，工具集永不膨胀** | 常驻工具保持精炼，临时能力随用随造、用完即焚 |
| 2 | **对话复杂度恒定** | 结果压缩，插件销毁后模型看不到工具存在 |
| 3 | **出错可回滚，迭代无成本** | 每次修改是新版本，旧版本随时可回滚 |
| 4 | **安全是设计出来，不是事后补的** | 显式信任流程，授权针对当前版本 |
| 5 | **一个插件，同时扩展 Agent 和界面** | 后端能力和前端表现天然配对 |

## 完整流程

识别缺口 → 先查后写 → 写插件 → 激活（需授权）→ 调用（实时进度卡片）→ 继续主线 → 销毁归零
