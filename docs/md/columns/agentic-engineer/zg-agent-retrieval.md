# 阿里开源本地 Agent 检索工具 zg 深度解析

## 问题的本质：意图与文本之间的「词汇鸿沟」

你问编程 Agent：「启动时恢复主题偏好的逻辑在哪里？」Agent 拿着这句话去搜代码：先 grep「theme preference」，没有结果；换成「restore theme」，还是没有；再试「startup settings」……几轮下来读了一堆无关文件，最后给出的结论还是错的。而代码里，这个函数其实叫 `hydratePreferences`。

这不是模型不够聪明，而是检索工具与任务形态错配了：Agent 拿到的是自然语言意图，手里的工具却只认得精确的关键词。

这就是检索领域经典的**词汇鸿沟（vocabulary mismatch）**问题。

## 好的检索是流水线，不是一次搜索

真实任务中的检索几乎从来不是「一步到位」的，而是分阶段的：

| 阶段 | 你手里有什么 | 该用什么武器 |
|------|-------------|-------------|
| 探索 | 只有模糊的任务描述 | 语义检索：按含义发现相关内容 |
| 聚焦 | 有了候选方向和初步关键词 | BM25 / 混合检索 |
| 验证 | 目标已经明确 | ripgrep：精确、穷尽地定位 |

**三个关键概念：**

- **BM25**：经典关键词相关性排序算法，根据词频、文档长度等因素给结果打分排序
- **向量检索（语义检索）**：用 Embedding 模型把文本编码成向量，语义相近的内容在向量空间里距离也近
- **RRF（Reciprocal Rank Fusion，倒数排名融合）**：多路检索结果的融合算法

zg 做的事情，就是把这条流水线装进一个工具：语义检索、BM25、混合检索（向量 + BM25 经 RRF 融合）、rg 精确匹配，一个入口全给到。

## zg 是什么

**一句话定位**：zg 是面向人与 Agent 的本地优先检索基础设施，对代码、文档等本地内容进行提取、组织与索引。

**技术栈**：
- **Zvec**：以嵌入式方式在设备内提供向量检索与 BM25 能力，无需部署独立数据库服务
- **ripgrep（rg）**：负责精确、穷尽的文本匹配

**四个设计宗旨**：
- 全流程检索：从模糊探索、相关收敛到精确验证
- 多文件格式支持：代码、Markdown、CSV、JSON 等
- 上下文高效：多路结果融合排序、按需提供预览
- 本地优先：扫描、索引、本地 Embedding 默认全在设备内完成

## 三步上手

```bash
# 1. 安装
npm install -g @zvec/zvec-grep

# 2. 自动发现本机 Agent 并完成 MCP 配置
zg install

# 3. 为当前工作区建立本地索引
cd your-repository
zg index

# 4. 开始检索
zg query --human "theme preference persistence on startup"
```

## 结语

Agent 时代的本地检索，正在从「关键词匹配」走向「意图发现」。zg 把语义检索、BM25、混合排序与 rg 精确匹配组织成一条完整流水线，用本地优先的方式交付给人和 Agent。
