# DeepSeekHarness 的新范式：让 Agent 为自己构建工具

> DeepSeek Harness 专栏第 04 篇。Agent 在对话中途发现自己缺一个能力，可以当场写成插件、加载、调用、用完即销毁。能力不是出厂配置，而是现场装配。

---

## 核心机制

大多数 AI 助手的工具集是「出厂配置」。DeepSeek Harness 换了一种哲学：**一切皆插件，插件即插即用**。

- **能力可以现场长出来**：Agent 当场把能力写成插件，加载后工具凭空出现在工具列表
- **能力可以现场消失**：任务做完，插件销毁，工具列表恢复原样

## 脚本 vs 插件

| 维度 | 写脚本执行 | 造插件 |
|------|-----------|--------|
| 能力形态 | 一次性动作，执行完即消亡 | 注册为工具，进入模型工具箱 |
| 再次使用 | 每次重新写、重新执行 | 同会话内随叫随到、反复调用 |
| 中间状态 | 跑完就没了 | 可记住进度、计数等状态 |
| 定时 / 监听 | 做不到 | 平台原生支持，不用时自动清理 |
| 界面 | 只有文本输出 | 可带实时界面：进度条、按钮 |
| 升级与回滚 | 改了就是覆盖 | 版本化，随时回滚 |
| 授权 | 只受执行环境约束 | 涉及界面时经过用户授权 |
| 清理 | 代码残留在对话里 | 零残留 |

## 五条最佳实践

1. **能力按需，工具集永不膨胀**——常驻精炼，临时随用随造
2. **对话复杂度恒定**——插件销毁后模型看不到工具存在
3. **出错可回滚，迭代无成本**——每次修改是新版本
4. **安全是设计出来，不是事后补的**——显式信任流程
5. **一个插件，同时扩展 Agent 和界面**——后端能力和前端表现天然配对

## 完整流程

识别缺口 → 先查后写 → 写插件 → 激活（需授权）→ 调用（实时进度卡片）→ 继续主线 → 销毁归零
