# pstack 拆解：动手前先把事情搞懂的四个 Skill

> pstack 里有四个 skill 专门干这件事：/how、/why、/recall、/teach。

## 四个 Skill 详解

### /how — 讲代码怎么运作

问题小就直接讲；问题复杂、跨多个文件，就并行派 2 到 4 个只读的 Explore 子代理分头查，再汇总成：
- 概览
- 关键概念
- 运行流程
- 代码位置
- 坑

### /why — 当初为什么这样写

1. 用 `git blame`、`git log` 找到提交和 PR 号
2. 再用 `gh` 读 PR 正文、评论和 review
3. 看接了哪些 MCP
4. 查能接上的工单、文档、聊天、报错

每条结论标来源和把握程度，没接上的来源写明。

### /recall — 开工前恢复上下文

1. 用 `pwd -P` 得到项目路径，把 `/` 换成 `-`
2. 只读 `~/.claude/projects/<这个名字>/*.jsonl` 里最近 7 天的用户和助手消息
3. 跳过工具调用这类记录
4. 用 `git` 和 `gh` 核对真实状态
5. 输出现状、反复出现的问题、下一步

### /teach — 讲到你真懂

- 大问题同时调用 how 和 why
- 小问题按需调一个
- why 默认只查相关范围
- 先给最短的完整答案，等追问再展开
- 复杂的图一次只加一个部件

## Claude Code 版 Skill 生成提示词

```
帮我给这个项目写四个 skill：how、why、recall、teach，路径是 .claude/skills/<名字>/SKILL.md，文件顶部用 --- 包住 name 和 description，description 写清什么时候用。

how：解释某块代码怎么运作。问题小就直接讲；问题复杂、跨多个文件，就并行派 2 到 4 个只读的 Explore 子代理分头查，再汇总成概览、关键概念、运行流程、代码位置、坑。

why：解释为什么这样写。先用 git blame、git log 找到提交和 PR 号，再用 gh 读 PR 正文、评论和 review，然后看接了哪些 MCP，查能接上的工单、文档、聊天、报错。每条结论标来源和把握程度，没接上的来源写明。

recall：开工前恢复上下文。用 pwd -P 得到项目路径，把 / 换成 -，只读 ~/.claude/projects/<这个名字>/*.jsonl 里最近 7 天的用户和助手消息，跳过工具调用这类记录，用 git 和 gh 核对真实状态，输出现状、反复出现的问题、下一步。

teach：大问题同时调用 how 和 why，小问题按需调一个，why 默认只查相关范围；先给最短的完整答案，等我追问再展开，复杂的图一次只加一个部件。

每个 skill 自己写全，不引用外部文件。先在回复里给我看四份草稿，我确认后只写这四个文件，不改别的，不覆盖已有的同名 skill。
```
