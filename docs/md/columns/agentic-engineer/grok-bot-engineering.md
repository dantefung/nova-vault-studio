# 面向工程的 Grok Bot

> 作者是 SpaceXAI 的工程师，正在用 Grok Bot 构建 Grok Bot。Grok Bot 是一个能力很强的工程实习生，有自己的计算机，可以管理编码智能体，并从你的工作方式中学习。

## 认识我的工程师机器人

我有五个工程机器人，每个都专注不同领域：

- **Baltata**：负责 Grok Bot 移动端共享层，以及 iOS 上所有与 Grok Bot 相关的内容
- **Shaoruru**：负责 Grok Bot 桌面客户端和 CI/CD 相关工作
- **Hogan**：负责基础设施，以及调查归属不明确的用户问题
- **Craig**：负责 Android 上的 Grok Bot
- **Quill**：负责 Grok Bot harness

每个机器人都能创建 Cursor 云端智能体，读取转录内容，查看附在 PR 上的证明材料，并通过排队发送消息或中断运行来跟进。

## 突破上下文限制进行扩展

为了让机器人在超出上下文限制后仍能跟上工作进度，我让每个工程师机器人管理一个共享的 Notion 数据库。每 30 分钟，它们会检查每个 PR 的以下内容：

- Bugbot 评论或安全发现
- 失败的 CI 运行
- 合并冲突

在 Grok Bot 之前，我一次可以手动管理 15 个云端智能体。现在，我的智能体集群可以同时管理 **200 多个智能体**。

## Grok Bot 运营这个迷你组织

运营负责人是 **Jenny**，团队里唯一不写代码的智能体。每天早上 5 点，Jenny 都会和团队里的每个智能体进行一对一会面，回顾我们的手册，暴露阻塞项，并强化我想营造的氛围。

当某个机器人犯了错误时，我就让它去找 Jenny 做根因分析和事后复盘。Jenny 会深入梳理导致这个问题的推理过程，然后更新行动手册，并把变更通知给其他工程机器人，这样同样的错误就不会发生第二次。

## 每夜审计

每天凌晨 3 点，我的工程智能体都醒着，清理代码库、提升代码质量、清扫废弃逻辑、加快应用加载速度，并减小打包体积。每天早上，我都会收到一批新的 PR，让我们的代码保持整洁、没有废料。

更多每夜审计的想法：安全审计、CI/CD 构建时间审计、国际化审计、一致性审计、补追审计。

## P0 紧急流程

每当我说某个任务是 P0 时，它们就会启动一个临时例程，每五分钟检查一次转录内容，监控进展和推理过程，并在云端智能体开始浪费不必要时间时主动进行引导。

## 使用经验与技巧

- **给云端智能体一个完整的反馈闭环**：云端智能体可以截图，Grok Bot 会利用它的多模态能力来确认视觉更改是否已经应用；如果结果与你的要求不一致，它会提出异议。
- **把 Grok Bot 当成一个有天赋的实习生**：直接聊天就行，不需要调用技能，不需要很长的提示词。
- **避免重复是关键**：如果你发现自己每天不止一次地做某件事，而且它遵循清晰的模式，就和你的机器人讨论一下。
- **给机器人开每日例会**：每天重复关键点，有助于它们记住复杂的工作流。
- **更多地放手**：在安全的时候，给它们足够的自由去交付；在风险更高的领域，则更加谨慎。
- **让它们协同编排**：构建一个机器人错误复盘流水线，让同样的错误不会发生第二次。
