# 多 Agent 架构设计模式：六种主流方案解析

## 1. 主从协调模式（Supervisor / Coordinator Pattern）

**运作机制**：单一中枢 Agent 面对用户输入，负责任务理解、子任务拆解，根据各专业 Worker Agent 专长分发。Worker 执行后结果汇总给 Supervisor，评估是否满足终止条件或重新分派。

**代表实现**：LangGraph Supervisor 架构、CrewAI（Hierarchical 流程）、MetaGPT 的管理层模式。

| 优势 | 局限 |
|------|------|
| 权限清晰、流程集中可控、可插件化程度高 | 中心节点容易成为性能与并发瓶颈 |

## 2. 图编排与状态机模式（Graph-based / StateFlow Pattern）

**运作机制**：将多 Agent 协作显式建模为状态转移图。每个节点是 Agent、确定性函数或工具调用；边定义状态转移条件。Agent 根据输入更新共享状态（State），沿预设逻辑边流动。

**代表实现**：LangGraph、AutoGen（GroupChat / StateFlow）、LlamaIndex Workflows。

| 优势 | 局限 |
|------|------|
| 工程确定性最高 | 相比纯自主 Agent 丧失一定探索灵活性 |

## 3. 流水线与装配线模式（Sequential Pipeline Pattern）

**运作机制**：模拟人类标准化协作流水线（如瀑布式软件工程）。各 Agent 各司其职，前序 Agent 输出经标准化处理后作为后序 Agent 输入。

**代表实现**：ChatDev、CrewAI（Sequential 流程）。

| 优势 | 局限 |
|------|------|
| 输入输出标准统一、任务边界明确、上下文隔好 | 容错弹性较差，前序幻觉或偏差易被下游放大 |

## 4. 环境共享记忆模式（Blackboard / Shared State Pattern）

**运作机制**：源自传统 AI 的"黑板架构"。Agent 之间不直接点对点通信，而是共同读写共享环境（状态数据库、文件沙箱、任务看板、向量数据库）。Agent 监听环境变化自主决定触发动作，产物写回黑板。

**代表实现**：AutoGPT、SWE-agent、Voyager。

| 优势 | 局限 |
|------|------|
| 高度解耦；天然支持异步并发与状态持久化 | 并发读写冲突控制要求高，黑板数据索引与状态一致性维护成本高 |

## 5. 对等辩论与共识模式（Multi-Agent Debate / Consensus Pattern）

**运作机制**：多个配置不同模型、不同 Prompt 或不同视角的 Agent 针对同一任务发表见解、交叉质询、寻找漏洞，经设定轮次后由裁判 Agent 或多数投票达成共识。

**代表实现**：CAMEL、Multi-Agent Debate 系列研究、代码审查评审系统。

| 优势 | 局限 |
|------|------|
| 能显著抑制单一模型的事实幻觉与逻辑盲区 | 多轮对话易在无意义细节上陷入震荡或死循环，收敛判定难 |

## 6. 动态移交模式（Dynamic Handoff / Swarm Pattern）

**运作机制**：每个 Agent 仅关注自己的局部职能，配备一组移交工具。检测到用户诉求超出自身范围时，当前 Agent 主动调用移交工具，将对话上下文连同控制权平滑转移给下一个专业 Agent。

| 优势 | 局限 |
|------|------|
| 极度轻量、启动快、延迟低 | 移交链条较长时可能死循环，难以应对强依赖多步规划的复合任务 |

## 作者观点

对第五种（对等辩论）兴趣不大，但对**第一、二、四种**觉得很有进步空间。

目前工业界明显趋势是**三者架构的融合版**，但仍有很多问题，比如**图结构和概率性模型二者的规划冲突**。

作者正在基于卡兹克开源的系统尝试架构一个 agent 的微内核，图结构和概率性的结合对于信息源任务会有帮助。
