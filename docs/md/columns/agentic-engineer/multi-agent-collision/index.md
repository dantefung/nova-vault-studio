# 多 Agent 协作冲突的血泪教训与解决方案

> 多个 Agent 同时改一份项目文件如何避免打架？这是我在长期跑 30+ 终端任务中踩坑无数才总结出的经验。

## 问题

如果你同时跑多个 Codex 任务窗口操作同一个项目，一定会遇到这些问题：

- 两个 Agent 同时修改同一个文件，互相覆盖
- main 分支更新太慢，Worker 基于过期代码工作
- 几十个测试并行跑，电脑直接卡崩
- 信息更新不及时，Agent 各自为战

## 三个核心解决方案

### 1. 浏览器锁

给测试资源加锁，避免一次性跑几十个测试把电脑干崩。谁先拿到锁谁跑，其他人排队。

### 2. 主管理者 + Worker 权限分离

分唯一主 main 管理者和多 worker 协作者：

| 角色 | 职责 | 权限 |
|------|------|------|
| **Main 管理者** | 维护 main 分支，合并决策 | 可写 main |
| **Worker 协作者** | 在 branch/worktree 中分任务 | 只写 branch，不可写 main |

相当于主管和员工的权限不同——主管负责合并，员工负责干活。

### 3. AI 习惯分析

把自己日常的困扰和遇到的问题发给 AI，让它结合电脑所有软件运行日志来分析你的习惯。多跑几次，重复看，AI 就能记住你的最佳做法。

## 实操建议

- 习惯在终端跑任务：多个终端窗口同时打开，均分软件内存，降低单一压力避免卡死
- 有任何想法快速拉电脑文件，大量复制粘贴分析干活
- 不要让 Agent 直接写 main，永远通过 branch/worktree 隔离

## 总结

这套机制的核心是**权限隔离 + 资源锁 + 习惯闭环**。对正规程序员来说可能是常识，但我走了很久弯路才搞明白——现在分享出来，希望你能少踩坑。
