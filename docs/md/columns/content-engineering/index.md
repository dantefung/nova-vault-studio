## 核心理念

> 素材库只是把东西存起来；**内容工程让旧内容继续参与新内容生产**。

### 文件 vs 系统

| 维度 | 文件 | 系统 |
|------|------|------|
| 形态 | 散落的 .md/.docx | 结构化的内容单元库 + 关系网 |
| 调用 | 重新翻 | 直接检索相关节点 |
| 复用 | 低 | 高（观点跨平台重组） |
| 增长 | 线性（多一份文件） | 复利（多一份文件整张网重写） |
| 适合 | 写少时 | 写多时（> 1000 篇/上百万字时） |

### 内容工程的核心动作

1. **拆单元**：把内容拆成 5 类可调用对象（QST 问题 / CON 概念 / OPI 观点 / CAS 案例 / SOL 方案）
2. **建工程**：3 层结构（规则层 / 状态层 / 内容单元库）
3. **保回溯**：原始素材不直接改动，只复制到新工程
4. **跑 Agent**：让 Agent 持续处理复杂工程，不断检查自己前面做过什么
5. **长节点**：每进入一篇新文章，系统继续长出新的节点和关系

## 适用场景

- 已经有大量本地内容（公众号、推文、课程稿、笔记），想"系统化"而不是"再写一遍"
- 多人协作的内容团队，需要共享知识资产而不是各写各的
- 想用 Agent 加速内容生产，而不是让 Agent "从零写"

## 何时不适合

- 本地内容 < 100 篇时——成本大于收益
- 早期内容创作者——应该先写，量大了再工程化
- 一次性单篇内容——直接写就行
