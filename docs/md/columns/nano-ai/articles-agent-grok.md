# 拆解 Grok Bot：给 Agent 一台自己的电脑




[从零手写 Agent · EP15](/agent/)




Teardown · Grok Bot



> 前三课拆的都是编码 Agent：跑在你的电脑上，读写你的代码，你在旁边看着。xAI 今年推出了两个 Agent，一个是同类的编码 Agent Grok Build，另一个 Grok Bot 换了一个完全不同的场景：**它有自己的一台云电脑，替你登录网站、长期在线干活，你不在的时候也一样。**

>

> 这一课以 Grok Bot 为主，因为它把这个系列第 6、7 课的"常驻"推到了尽头；最后再简单看一下 Grok Build。



* * *



## 01Grok Bot 是什么



  * **2026 年 8 月 11 日** ：Grok Bot 以早期测试版推出，先开放给最高档的订阅用户。

  * **8 月下旬** ：逐步开放到更便宜的档位；同时上线了 X 连接器，可以搜索帖子、时间线和提及。

  * **9 月 3 日** ：开放企业版，带访问、网络和审计控制。



xAI 对它的描述是"可以把真正的工作交给它的 AI 队友"。和聊天助手的区别在于：聊天助手回答问题、给建议；Grok Bot 登录你的工具，自己把一串操作做完，需要你批准时再来问你。



它的账号体系和 Cursor 打通，可以在桌面应用、iOS 应用里使用，也能在 X 的私信和 Slack 里和它对话。

## 03一台云电脑：解决"你不在"的问题



第 6 课把 Agent 接进聊天软件，第 7 课让它定时运行，但有一个前提始终没变：程序跑在你的电脑上。你的电脑一关机、一断网，一切就停了。



Grok Bot 的做法是：**给它一台自己的电脑。** 每个用户有一台持久的云电脑，你所有的 bot 共用它的文件、浏览器会话和登录状态。官方的说法是，关掉应用、合上笔记本、锁上手机，后台的任务和定时流程都不会停。每个 bot 有自己的屏幕，一个 bot 同一时间做一件需要操作电脑的事。



这台电脑也是安全边界。第 3 课我们说过，真正可靠的隔离在操作系统层面；第 13 课 Codex 的答案是本机沙箱，第 14 课 Pi 的答案是"放进容器里"。Grok Bot 的答案更彻底：**干脆不在你的机器上运行。** 它默认碰不到你的电脑；想让它在你的桌面上执行命令，得在设置里打开，默认还是每次都问。



## 04浏览器即工具：没有接口的地方也能干活



第 2 课的"主流怎么做"里提过 Grok Bot 一句：工具从"一个函数"变成了"一台电脑"。现在可以展开说。



它的工具选择有一个顺序：**有连接器就用连接器，因为更结构化、更可靠；没有，就打开浏览器，像人一样操作网站。** 这意味着那些没有 API、也没有 MCP 服务器的系统，它也能用。第 8 课的 MCP 需要服务方或社区先写好服务器，Grok Bot 不需要。



用浏览器干活，最麻烦的是登录。它的处理方式值得一看：



  * **它看不到你的密码。** 登录时用的是保险库、连接的密码管理器，或者一个安全表单，bot 能完成登录，但看不到具体的值。

  * **人才能做的步骤交还给人。** 单点登录、通行密钥、验证码，它会把电脑的控制权交给你，你完成这一步，它再接着干。官方原话是，它"应该把这些步骤交给你，而不是绕过去"。

  * **网站可能拦截云端流量。** 这时你可以在它的电脑上自己登录，或者打开一个选项，让流量从你自己的网络出去。



对照第 6 课：我们的 Telegram 机器人需要你提供 Bot Token，并且反复强调 Token 等于控制权、不能泄露。Grok Bot 把凭证这件事做成了产品的一部分：凭证由专门的地方保管，Agent 只拿到"能登录"的能力，拿不到凭证本身。



## 05审批：无人值守时怎么办



第 7 课的核心问题是：定时任务到点执行时没人在旁边，需要确认的操作怎么办？我们的答案是"创建时预授权，且有上限"。



Grok Bot 的做法是三层：



  1. **按工具和风险决定。** 一个操作要不要审批，取决于它用的是什么工具、动作风险多大，以及你有没有打开自动审核。

  2. **你可以加"先问我"的规则。** 针对发送、发布、删除、购买、修改生产系统这类动作，单独设成必须先问。这和 Claude Code 的 ask 规则是一个思路。

  3. **无人值守的审批会过期。** 定时流程或者其他 bot 发来的审批请求，大约 30 分钟不处理就作废；你正在聊天时发起的审批，会一直等你。



第三条和我们第 6 课"超时等于拒绝"是同一个原则：没人回答的时候，最安全的默认值是"不做"。区别是时间尺度：我们等 2 分钟，它等 30 分钟，因为它预期你可能在开会，而不是在电脑前。



## 06多个 bot：分工，而不是一个全能助手



第 9 课讲子 Agent 时，我们的主 Agent 临时派出帮手，干完就走。Grok Bot 的多 Agent 是另一种形态：**几个长期存在、各有分工的 bot。**



  * 每个 bot 有自己的对话和学到的角色，彼此分开。

  * 有些关于你的信息是共享的，比如名字和时区。

  * bot 之间可以互相发消息、在群聊里协作，也可以通过共享的文件、浏览器会话来传递上下文。

  * 一个团队可以共用一个 bot，把它加进 Slack。



这更接近第 9 课提到的 Claude Code "Agent 团队"，而不是子 Agent。它解决的不是上下文问题，而是"一个助手的记忆和角色会互相干扰"：写周报的 bot 和盯数据的 bot 分开，各自的记忆更干净。



有一条安全规则值得注意：其他 bot 发来的审批请求，和定时流程一样，30 分钟过期。这和 Claude Code 文档里"一个 Agent 发给另一个 Agent 的消息，不能代替你批准权限"是同一种警惕：**Agent 之间的消息，不能被当成人的授权。**



## 07技能与定时：从"教一遍"开始



Grok Bot 也有技能：描述怎么做一件事。它多了一个有意思的入口，叫"教一个任务"：你在浏览器里做一遍，最长 10 分钟，它把这段操作录下来，生成一份技能草稿，你审核后保存。



定时流程（Routines）把一个工作流交给某个 bot，按时间或者在支持的情况下按事件触发。官方建议的顺序是：先在一次真实的任务上测试技能，确认没问题，再把它做成定时流程。



这个"先手动、再固化、最后自动"的顺序，和第 5、7 课的设计精神一致：技能是你读过、验证过的东西，定时任务是你在场时做出的决定。



## 08模型：你不能选



Grok Bot 没有模型选择器。官方文档说，它为每个任务选择后端模型，可能是 xAI 自家的，也可能是第三方服务商的，每次请求都可能不同，应用里也不显示是哪个模型处理的。



这和前三课形成鲜明对比：Claude Code 只用 Claude，Codex 和自家模型深度绑定，Pi 让你自由选。Grok Bot 选择把模型完全藏起来，你面对的是"一个能干活的队友"，而不是"一个模型加一套工具"。好处是省心；代价是你无法控制，也无法复现某次行为背后用的是什么。



## 09Grok Build：xAI 的编码 Agent



xAI 在 5 月发布了终端编码 Agent Grok Build，早期测试版面向 SuperGrok 和 X Premium Plus 用户。对照前面的零件，它的特点很清楚：



  * **计划模式可以逐条改。** 动手之前生成计划，你不只能批准或拒绝，还能对某一步批注、改写。

  * **子 Agent 并行，各用一个 git worktree。** 这是第 9 课"并行写会冲突"的一种工程解法：各写各的副本，最后合并。

  * **无头模式。** 用 
`-p`
 参数在脚本和自动化流程里运行。

  * **开箱支持 AGENTS.md、MCP、技能、钩子和插件。** 第 13 课说的跨厂商标准，它全部接上了。



Grok Build 也是 Grok Bot 在 Linux 上的入口：没有桌面应用的 Linux 用户，可以通过它的终端界面使用 Grok Bot。



## 10它的取舍与代价



**1\. 数据都在云端。** 它需要云端存储，你的文件、浏览器会话、登录状态都在它的电脑上。删除一个 bot 会删掉它的资料、对话和定时流程，但共享电脑上的文件和登录状态可能还留着。



**2\. 浏览器操作慢，也更难预测。** 页面改版、弹窗、验证码，都会让流程中断。官方也建议：有连接器就优先用连接器。



**3\. 看不到用的是哪个模型。** 出了问题，很难判断是模型的原因还是流程的原因。



**4\. 适合的场景和编码 Agent 不同。** 它擅长的是跨网站、跨工具的事务性工作，而不是在一个代码仓库里深度工作。



## 11本课小结



  * Grok Bot 把循环搬到了云端：每个用户一台持久的云电脑，你不在它也在干活

  * 工具优先用连接器，没有就操作浏览器；凭证由专门的地方保管，Agent 看不到

  * 审批按工具和风险决定，可加"先问我"规则，无人值守的审批 30 分钟过期

  * 多个长期存在的 bot 分工协作，Agent 之间的消息不能当成人的授权

  * 模型对用户隐藏；Grok Build 是同门的终端编码 Agent，计划可逐条改，子 Agent 用 worktree 并行
