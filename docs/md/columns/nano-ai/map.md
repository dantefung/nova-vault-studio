## 全部知识点（按学习阶段）



### 阶段 奠基 · Transformer · GPT



> Transformer 与预训练



#### 反向传播 + Adam（2017.00）



- **所属线路**：规模与训练



- **是什么**：一切训练的底层：链式法则把损失的梯度算回每个参数，Adam 给每个参数配自适应的步长。

- **为什么重要**：后面所有模型，不管结构怎么变，都是用这套方法训出来的。

- **要学会什么**：

  - 交叉熵损失

  - 计算图与链式法则

  - SGD、Adam

  - 学习率预热与衰减

- **论文**：
[1412.6980](https://arxiv.org/abs/1412.6980)




#### Transformer（2017.06）



- **所属线路**：模型主线 · 注意力与位置编码



- **是什么**：完全用注意力取代 RNN 的编码器-解码器架构，今天所有大模型的起点。

- **为什么重要**：可以并行训练，任意两个词之间一步就能建立联系。后面所有站点，几乎都是在它上面换零件。

- **要学会什么**：

  - 词嵌入与位置编码

  - 缩放点积注意力、多头注意力

  - 残差连接 + LayerNorm

  - 前馈网络 FFN

  - 因果遮罩与自回归生成

- **先学哪几个**：反向传播 + Adam

- **论文**：
[1706.03762](https://arxiv.org/abs/1706.03762)




#### GPT-1（2018.06）



- **所属线路**：模型主线



- **是什么**：只用 Transformer 的解码器，先在大量无标注文本上预训练「预测下一个词」，再针对具体任务微调。

- **为什么重要**：确立了「预训练 + 微调」范式和 decoder-only 路线，今天的大模型都是这条路线的后代。

- **要学会什么**：

  - 语言模型目标：下一个词预测

  - 预训练与微调的分工

  - decoder-only 结构

- **先学哪几个**：Transformer



#### BERT（2018.10）



- **所属线路**：模型主线



- **是什么**：只用编码器，双向看上下文，用「完形填空」（掩码语言模型 MLM）预训练。

- **为什么重要**：让 NLP 全面进入预训练时代。生成式大模型最终选了 decoder-only，但 BERT 路线仍是向量检索、Embedding 模型的基础。

- **要学会什么**：

  - 掩码语言模型 MLM

  - 双向注意力 vs 因果注意力

  - 为什么生成任务最终选了 decoder-only

- **先学哪几个**：Transformer

- **论文**：
[1810.04805](https://arxiv.org/abs/1810.04805)




#### GPT-2（2019.02）



- **所属线路**：模型主线



- **是什么**：15 亿参数的 decoder-only 模型，只靠预训练就能零样本完成多种任务，权重后来全部公开。

- **为什么重要**：结构简单、权重公开，是手写复现大模型的最佳起点。Pre-LN、GELU、输入输出权重共享都在这里定型。

- **要学会什么**：

  - Pre-LN 结构

  - GELU 激活

  - 嵌入层与输出层权重共享

  - BPE 分词

  - 采样：temperature、top-k、top-p

- **先学哪几个**：GPT-1



#### GPT-3（2020.05）



- **所属线路**：模型主线



- **是什么**：1750 亿参数。不改任何参数，只在提示里给几个例子，就能完成新任务（in-context learning）。

- **为什么重要**：证明规模本身会带来新能力，开启了大模型军备竞赛。

- **要学会什么**：

  - 少样本 / 上下文学习

  - 提示词的作用

  - 规模与能力的关系（配合 Scaling Laws 一起看）

- **先学哪几个**：GPT-2、Scaling Laws

- **论文**：
[2005.14165](https://arxiv.org/abs/2005.14165)




### 阶段 规模与训练 · Scaling · 并行



> 怎么把模型训大



#### Scaling Laws（2020.01）



- **所属线路**：规模与训练



- **是什么**：损失随参数量、数据量、计算量按幂律下降，可以用小模型的实验预测大模型的表现。

- **为什么重要**：让「堆规模」变成可以计算的投资决策。

- **要学会什么**：

  - 幂律拟合

  - 计算量估算 C ≈ 6ND

  - 这篇早期结论偏向「大模型、少数据」

- **先学哪几个**：反向传播 + Adam

- **论文**：
[2001.08361](https://arxiv.org/abs/2001.08361)




#### Chinchilla（2022.03）



- **所属线路**：规模与训练



- **是什么**：修正了 Scaling Laws：同样算力下，参数量和数据量应该同比例增长，大约每个参数 20 个 token。

- **为什么重要**：70B 的 Chinchilla 打败了 280B 的 Gopher。之后的模型都开始用更多数据训练更小的模型。

- **要学会什么**：

  - 计算最优配比

  - 为什么考虑推理成本后，大家训练得比 Chinchilla 建议的还久

- **先学哪几个**：Scaling Laws

- **论文**：
[2203.15556](https://arxiv.org/abs/2203.15556)




#### 混合精度训练（2017.10）



- **所属线路**：规模与训练



- **是什么**：用 FP16 做计算、FP32 保存主权重，再加上损失缩放，防止小梯度下溢成 0。

- **为什么重要**：训练速度和显存效率直接翻倍；后来的 BF16、FP8、FP4 训练都从这里出发。

- **要学会什么**：

  - 浮点格式：FP32 / FP16 / BF16 / FP8

  - 损失缩放

  - 主权重

- **先学哪几个**：反向传播 + Adam

- **论文**：
[1710.03740](https://arxiv.org/abs/1710.03740)




#### Megatron-LM（2019.09）



- **所属线路**：规模与训练



- **是什么**：把单个矩阵乘法按行、按列切到多张 GPU 上算（张量并行）。

- **为什么重要**：单卡放不下的模型终于能训练；和流水线并行、数据并行一起组成「3D 并行」。

- **要学会什么**：

  - 张量并行的切分方式

  - 通信开销

  - 数据 / 张量 / 流水线并行怎么组合

- **先学哪几个**：Transformer

- **论文**：
[1909.08053](https://arxiv.org/abs/1909.08053)




#### ZeRO（2019.10）



- **所属线路**：规模与训练



- **是什么**：把优化器状态、梯度、参数分片放到各张卡上，消除数据并行里的冗余副本。

- **为什么重要**：DeepSpeed 的核心；PyTorch 的 FSDP 也基于同样的思想。

- **要学会什么**：

  - 为什么 Adam 状态占显存大头

  - ZeRO-1 / 2 / 3 三个阶段

- **先学哪几个**：反向传播 + Adam

- **论文**：
[1910.02054](https://arxiv.org/abs/1910.02054)




### 阶段 现代架构 · LLaMA · GQA · MLA



> 开源模型的标准配方



#### LLaMA（2023.02）



- **所属线路**：模型主线 · 注意力与位置编码



- **是什么**：Meta 的开放权重模型，确立了之后开源模型的标准配方：Pre-RMSNorm、SwiGLU、RoPE。

- **为什么重要**：开源生态从这里爆发。后来的 Qwen、Mistral、DeepSeek 都沿用或改进了这套结构。

- **要学会什么**：

  - RMSNorm

  - SwiGLU

  - RoPE 旋转位置编码

  - LLaMA 2 起的 GQA

  - 用更多数据训练较小的模型

- **先学哪几个**：GPT-2、RoPE 旋转位置编码、Chinchilla

- **论文**：
[2302.13971](https://arxiv.org/abs/2302.13971)




#### RoPE 旋转位置编码（2021.04）



- **所属线路**：注意力与位置编码



- **是什么**：把位置信息变成对 Q、K 向量的旋转，两个词的点积只和它们的相对距离有关。

- **为什么重要**：几乎所有现代大模型的标配；长上下文扩展（位置插值、NTK、YaRN）都围绕它展开。

- **要学会什么**：

  - 二维旋转与复数视角

  - 为什么能表示相对位置

  - 位置插值与 YaRN

- **先学哪几个**：Transformer

- **论文**：
[2104.09864](https://arxiv.org/abs/2104.09864)




#### MQA 多查询注意力（2019.11）



- **所属线路**：注意力与位置编码



- **是什么**：所有注意力头共用同一组 K、V，只保留多组 Q。

- **为什么重要**：KV Cache 直接缩小到原来的 1/头数，解码大幅提速，代价是质量会掉一点。

- **要学会什么**：

  - 为什么解码的瓶颈是读 KV Cache

  - MQA 与 MHA 的显存对比

- **先学哪几个**：Transformer、KV Cache

- **论文**：
[1911.02150](https://arxiv.org/abs/1911.02150)




#### GQA 分组查询注意力（2023.05）



- **所属线路**：注意力与位置编码



- **是什么**：MHA 和 MQA 的折中：把注意力头分成几组，每组共享一份 K、V。

- **为什么重要**：质量接近 MHA，KV Cache 接近 MQA。从 LLaMA 2 70B 开始成为标配。

- **要学会什么**：

  - 分组方式与 KV Cache 大小计算

  - 从 MHA 权重转换成 GQA（uptraining）

- **先学哪几个**：MQA 多查询注意力

- **论文**：
[2305.13245](https://arxiv.org/abs/2305.13245)




#### FlashAttention（2022.05）



- **所属线路**：注意力与位置编码



- **是什么**：不改变数学结果，只改变计算顺序：分块在 GPU 片上 SRAM 里算完 softmax，不再把 n×n 的注意力矩阵写回显存。

- **为什么重要**：注意力从「卡在显存带宽」变成接近算力上限，长上下文训练从此可行。

- **要学会什么**：

  - GPU 显存层级：HBM vs SRAM

  - 在线 softmax

  - IO 感知的算法设计

- **先学哪几个**：Transformer

- **论文**：
[2205.14135](https://arxiv.org/abs/2205.14135)




#### 滑动窗口注意力（2023.10）



- **所属线路**：注意力与位置编码



- **是什么**：Mistral 7B 采用：每个 token 只看最近 W 个 token，层层叠加后，感受野仍然能覆盖很远。

- **为什么重要**：计算量和 KV Cache 不再随上下文增长；后来常和全局注意力层交替使用（Gemma 2、gpt-oss 都这么做）。

- **要学会什么**：

  - 局部注意力 vs 全局注意力

  - 滚动 KV Cache

  - 局部 / 全局层交替

- **先学哪几个**：GQA 分组查询注意力

- **论文**：
[2310.06825](https://arxiv.org/abs/2310.06825)




#### MLA 多头潜在注意力（2024.05）



- **所属线路**：注意力与位置编码



- **是什么**：DeepSeek-V2 提出：把 K、V 压缩成一个低维潜在向量再缓存，用的时候再还原；RoPE 部分单独处理。

- **为什么重要**：官方报告称 KV Cache 相比 DeepSeek 67B 减少 93.3%，质量还更好。它是 DeepSeek 系列的核心。

- **要学会什么**：

  - 低秩压缩与矩阵吸收

  - 解耦 RoPE

  - 和 GQA 的 KV Cache 对比

- **先学哪几个**：GQA 分组查询注意力、RoPE 旋转位置编码

- **论文**：
[2405.04434](https://arxiv.org/abs/2405.04434)




### 阶段 混合专家 MoE · Switch · Mixtral



> 参数大、计算小



#### 稀疏门控 MoE（2017.01）



- **所属线路**：混合专家 MoE



- **是什么**：Shazeer 等人在 LSTM 层之间插入上千个「专家」网络，由门控网络为每个输入只挑几个专家来算。

- **为什么重要**：参数量可以远大于计算量，「总参数 vs 激活参数」这对概念从这里开始。

- **要学会什么**：

  - 门控网络与 top-k 路由

  - 负载均衡损失

  - 条件计算

- **先学哪几个**：反向传播 + Adam

- **论文**：
[1701.06538](https://arxiv.org/abs/1701.06538)




#### GShard（2020.06）



- **所属线路**：混合专家 MoE



- **是什么**：把 MoE 放进 Transformer 的 FFN 层，在 2048 个 TPU 上训练 6000 亿参数的翻译模型。

- **为什么重要**：解决了 MoE 的分布式训练：专家并行 + 专家容量限制。

- **要学会什么**：

  - 专家并行与 all-to-all 通信

  - 专家容量与丢弃 token

  - top-2 路由

- **先学哪几个**：稀疏门控 MoE、Transformer

- **论文**：
[2006.16668](https://arxiv.org/abs/2006.16668)




#### Switch Transformer（2021.01）



- **所属线路**：混合专家 MoE



- **是什么**：每个 token 只路由到 1 个专家，把 MoE 大幅简化，扩展到 1.6 万亿参数。

- **为什么重要**：证明 top-1 路由可行且稳定，并给出了一整套实用的训练技巧。

- **要学会什么**：

  - top-1 路由

  - 负载均衡辅助损失

  - 选择性精度与稳定训练

- **先学哪几个**：GShard

- **论文**：
[2101.03961](https://arxiv.org/abs/2101.03961)




#### Mixtral 8x7B（2023.12）



- **所属线路**：混合专家 MoE



- **是什么**：8 个专家选 2 个，总参数 47B、每个 token 激活约 13B，开放权重。

- **为什么重要**：第一个被广泛使用的开源 MoE 模型，让社区真正看到 MoE 的性价比。

- **要学会什么**：

  - decoder 模型里的 top-2 路由

  - MoE 推理：显存按总参数算，计算按激活参数算

- **先学哪几个**：Switch Transformer、LLaMA

- **论文**：
[2401.04088](https://arxiv.org/abs/2401.04088)




#### DeepSeekMoE（2024.01）



- **所属线路**：混合专家 MoE



- **是什么**：把专家切得更细、每次选更多个，并保留几个所有 token 都会经过的「共享专家」。

- **为什么重要**：专家分工更专一，成为 DeepSeek-V2 / V3 和许多后续模型的 MoE 结构。

- **要学会什么**：

  - 细粒度专家切分

  - 共享专家隔离

  - 专家级 / 设备级负载均衡

- **先学哪几个**：Switch Transformer

- **论文**：
[2401.06066](https://arxiv.org/abs/2401.06066)




#### gpt-oss（2025.08）



- **所属线路**：混合专家 MoE



- **是什么**：OpenAI 自 GPT-2 以来第一个开放权重模型：120B（每 token 激活约 5.1B）和 20B 两个 MoE 版本，权重原生 MXFP4 量化。

- **为什么重要**：可以直接看到 OpenAI 的架构选择：全局 / 滑动窗口注意力交替、attention sink、GQA。

- **要学会什么**：

  - MXFP4 低精度权重

  - attention sink

  - 推理强度（reasoning effort）设置

- **先学哪几个**：滑动窗口注意力、DeepSeekMoE

- **论文**：
[2508.10925](https://arxiv.org/abs/2508.10925)




### 阶段 对齐与推理模型 · RLHF · DPO · R1



> 从会续写到会思考



#### InstructGPT / RLHF（2022.03）



- **所属线路**：对齐与推理能力



- **是什么**：三步：人工示范做监督微调（SFT）→ 用人类偏好训练奖励模型 → 用 PPO 强化学习优化。

- **为什么重要**：1.3B 的 InstructGPT 在人类评估中胜过 175B 的 GPT-3，是 ChatGPT 的直接前身。

- **要学会什么**：

  - 监督微调 SFT

  - 奖励模型与偏好数据

  - PPO 与 KL 惩罚

- **先学哪几个**：GPT-3

- **论文**：
[2203.02155](https://arxiv.org/abs/2203.02155)




#### ChatGPT（2022.11）



- **所属线路**：模型主线



- **是什么**：把 GPT-3.5 经过指令微调和 RLHF 做成对话产品，迅速走红。

- **为什么重要**：大模型从研究走向大众；从这里开始，「对齐」成了每个模型的必修课。

- **要学会什么**：

  - 预训练模型和对话模型的区别

  - 对话模板与系统提示词

  - 为什么需要 SFT + RLHF

- **先学哪几个**：GPT-3、InstructGPT / RLHF



#### Constitutional AI（2022.12）



- **所属线路**：对齐与推理能力



- **是什么**：Anthropic 提出：用一套写明的原则让模型自我批评、自我修改，用 AI 反馈代替部分人类标注（RLAIF）。

- **为什么重要**：降低了对人工标注的依赖，让对齐目标可以被明确写下来。

- **要学会什么**：

  - 自我批评与修订

  - RLAIF

  - 原则（宪法）的设计

- **先学哪几个**：InstructGPT / RLHF

- **论文**：
[2212.08073](https://arxiv.org/abs/2212.08073)




#### DPO（2023.05）



- **所属线路**：对齐与推理能力



- **是什么**：证明 RLHF 的目标可以直接写成偏好数据上的分类损失，不需要单独的奖励模型和 PPO。

- **为什么重要**：实现简单、训练稳定，成为开源模型后训练的首选之一。

- **要学会什么**：

  - Bradley-Terry 偏好模型

  - 隐式奖励

  - DPO 与 PPO 的取舍

- **先学哪几个**：InstructGPT / RLHF

- **论文**：
[2305.18290](https://arxiv.org/abs/2305.18290)




#### 思维链 CoT（2022.01）



- **所属线路**：Agent



- **是什么**：在提示里给出带推理步骤的例子，模型就会一步步推理再给答案。

- **为什么重要**：Agent「先想再做」的基础，也是后来推理模型的源头。

- **要学会什么**：

  - 少样本 CoT 与「Let's think step by step」

  - 自洽性投票

- **先学哪几个**：GPT-3

- **论文**：
[2201.11903](https://arxiv.org/abs/2201.11903)




#### GRPO（2024.02）



- **所属线路**：对齐与推理能力



- **是什么**：DeepSeekMath 提出：去掉价值网络，对同一个问题采样一组回答，用组内平均分做基线。

- **为什么重要**：显存和工程复杂度大幅降低，成为推理模型强化学习的主流算法。

- **要学会什么**：

  - 优势函数与基线

  - 组相对优势

  - 可验证奖励：数学、代码

- **先学哪几个**：InstructGPT / RLHF

- **论文**：
[2402.03300](https://arxiv.org/abs/2402.03300)




#### OpenAI o1（2024.09）



- **所属线路**：对齐与推理能力



- **是什么**：回答前先生成很长的思维链，用强化学习训练模型「怎么想」。

- **为什么重要**：开启了「推理时计算」这个新维度：想得越久，答得越好。

- **要学会什么**：

  - 测试时扩展（test-time compute）

  - 长思维链

  - 推理模型和普通模型的用法差别

- **先学哪几个**：思维链 CoT、InstructGPT / RLHF



#### DeepSeek-R1（2025.01）



- **所属线路**：对齐与推理能力



- **是什么**：在 V3 上直接用 GRPO + 规则奖励做强化学习（R1-Zero），模型自发学会反思和长推理；再经过冷启动数据和多阶段训练得到 R1，权重开放。

- **为什么重要**：首次公开验证纯强化学习能让推理能力涌现，推理模型的方法论从此被开源社区掌握。

- **要学会什么**：

  - R1-Zero 和 R1 的区别

  - 规则奖励：答案正确 + 格式

  - 把推理能力蒸馏到小模型

- **先学哪几个**：DeepSeek-V3、GRPO

- **论文**：
[2501.12948](https://arxiv.org/abs/2501.12948)




### 阶段 推理部署 · KV Cache · vLLM



> 跑得快、跑得省



#### KV Cache（2019.05）



- **所属线路**：推理部署



- **是什么**：自回归生成时，把已经算过的每个 token 的 K、V 存起来，每一步只为新 token 计算。

- **为什么重要**：生成从「每步重算整句」变成「每步只算一个 token」。代价是 KV Cache 的显存成了推理的核心瓶颈，MQA、GQA、MLA 都在压缩它。

- **要学会什么**：

  - Prefill 与 Decode 两个阶段

  - KV Cache 大小怎么算

  - 为什么解码受显存带宽限制

- **先学哪几个**：Transformer



#### GPTQ（2022.10）



- **所属线路**：推理部署



- **是什么**：训练后量化：逐层利用二阶信息补偿误差，把权重压到 4 bit，精度几乎不掉。

- **为什么重要**：让大模型能在消费级显卡上运行。

- **要学会什么**：

  - 训练后量化 vs 量化感知训练

  - 逐层误差补偿

  - 分组量化

- **先学哪几个**：KV Cache

- **论文**：
[2210.17323](https://arxiv.org/abs/2210.17323)




#### 投机解码（2022.11）



- **所属线路**：推理部署



- **是什么**：小模型先猜几个 token，大模型一次并行验证；输出分布和只用大模型完全一致。

- **为什么重要**：不改模型、不损质量就能提速 2–3 倍；后来演化出 Medusa、EAGLE，以及 DeepSeek-V3 的 MTP 用法。

- **要学会什么**：

  - 草稿 + 验证流程

  - 接受率与拒绝采样

  - 为什么输出分布不变

- **先学哪几个**：KV Cache

- **论文**：
[2211.17192](https://arxiv.org/abs/2211.17192)




#### AWQ（2023.06）



- **所属线路**：推理部署



- **是什么**：激活感知的权重量化：找出对激活影响大的少量权重通道，重点保护。

- **为什么重要**：4 bit 量化的主流方案之一，部署简单。

- **要学会什么**：

  - 显著权重通道

  - 按通道缩放

- **先学哪几个**：GPTQ

- **论文**：
[2306.00978](https://arxiv.org/abs/2306.00978)




#### vLLM / PagedAttention（2023.09）



- **所属线路**：推理部署



- **是什么**：像操作系统的分页内存一样管理 KV Cache，再配合连续批处理。

- **为什么重要**：论文称 KV Cache 显存浪费从 60%–80% 降到 4% 以下，吞吐提升数倍；vLLM 成了开源推理服务的事实标准。

- **要学会什么**：

  - KV Cache 碎片

  - 分页与块表

  - 连续批处理

- **先学哪几个**：KV Cache

- **论文**：
[2309.06180](https://arxiv.org/abs/2309.06180)




#### SGLang（2023.12）



- **所属线路**：推理部署



- **是什么**：用 RadixAttention（前缀树）复用多个请求共享前缀的 KV Cache。

- **为什么重要**：多轮对话、Agent、少样本提示这些大量共享前缀的场景显著提速。

- **要学会什么**：

  - 前缀缓存

  - 结构化输出与约束解码

- **先学哪几个**：vLLM / PagedAttention

- **论文**：
[2312.07104](https://arxiv.org/abs/2312.07104)




### 阶段 今天的主流模型 · DeepSeek · Qwen



> 2024–2026 前沿



#### Llama 3（2024.04）



- **所属线路**：模型主线



- **是什么**：词表扩到 128K，全系列使用 GQA，用约 15T token 训练；405B 版本在 2024 年 7 月发布。

- **为什么重要**：开源模型第一次在多数基准上逼近闭源前沿；技术报告完整公开了数据、训练和后训练流程。

- **要学会什么**：

  - 大规模数据清洗与配比

  - 长上下文扩展

  - 后训练流程：SFT + 拒绝采样 + DPO

- **先学哪几个**：LLaMA、DPO

- **论文**：
[2407.21783](https://arxiv.org/abs/2407.21783)




#### DeepSeek-V3（2024.12）



- **所属线路**：模型主线 · 混合专家 MoE · 规模与训练 · 推理部署



- **是什么**：6710 亿总参数、每个 token 激活 370 亿的 MoE 模型，集成了 MLA、无辅助损失的负载均衡、多 token 预测（MTP）和 FP8 混合精度训练。

- **为什么重要**：官方报告的训练成本约 278.8 万 H800 GPU 小时，远低于同级模型，却达到前沿水平。它基本就是今天开源大模型的架构模板。

- **要学会什么**：

  - MLA 怎么压缩 KV Cache

  - 细粒度专家 + 共享专家

  - 无辅助损失的负载均衡（路由偏置）

  - 多 token 预测 MTP

  - FP8 训练与 DualPipe 流水线

- **先学哪几个**：MLA 多头潜在注意力、DeepSeekMoE、LLaMA

- **论文**：
[2412.19437](https://arxiv.org/abs/2412.19437)




#### Qwen3（2025.04）



- **所属线路**：模型主线



- **是什么**：阿里的开放权重系列，同时提供稠密和 MoE 版本（旗舰 235B 总参数、22B 激活），一个模型里可以切换「思考 / 不思考」两种模式。

- **为什么重要**：中文开源模型的主力之一；混合思考模式把推理能力做成了可开关、可设预算的功能。

- **要学会什么**：

  - 稠密 vs MoE 怎么选

  - 思考模式与思考预算

  - QK-Norm 稳定训练

- **先学哪几个**：DeepSeek-V3、DeepSeek-R1

- **论文**：
[2505.09388](https://arxiv.org/abs/2505.09388)




#### Kimi K2（2025.07）



- **所属线路**：模型主线



- **是什么**：月之暗面的 MoE 模型，1T 总参数、32B 激活，用 MuonClip 优化器稳定训练，主打 Agent 和工具调用。

- **为什么重要**：证明 Muon 优化器能扩展到万亿参数；开源模型的 Agent 能力明显追近闭源模型。

- **要学会什么**：

  - Muon 优化器与 QK-Clip

  - 大规模 Agent / 工具调用数据合成

  - 和 DeepSeek-V3 结构的异同：更多专家、更少注意力头

- **先学哪几个**：DeepSeek-V3

- **论文**：
[2507.20534](https://arxiv.org/abs/2507.20534)




#### NSA 原生稀疏注意力（2025.02）



- **所属线路**：注意力与位置编码



- **是什么**：DeepSeek 提出：压缩、挑选、滑动窗口三路注意力结合，从训练开始就是稀疏的。

- **为什么重要**：稀疏注意力从推理时的近似技巧，变成可以端到端训练的架构。

- **要学会什么**：

  - 粗粒度压缩 + 细粒度块选择

  - 面向硬件的稀疏 kernel

- **先学哪几个**：FlashAttention、滑动窗口注意力

- **论文**：
[2502.11089](https://arxiv.org/abs/2502.11089)




#### 线性注意力混合（2025.08）



- **所属线路**：注意力与位置编码



- **是什么**：Qwen3-Next 用 Gated DeltaNet 这类状态大小固定的线性注意力，替换大部分注意力层：每 3 层线性注意力配 1 层标准注意力。

- **为什么重要**：长上下文的计算和显存接近线性增长。Kimi Linear（2025.10）也走类似的混合路线；但 MiniMax-M2 因效果问题退回全注意力，这条路仍有争议。

- **要学会什么**：

  - 线性注意力和 RNN 的关系

  - Delta 规则与门控

  - 混合层比例怎么定

- **先学哪几个**：FlashAttention

- **论文**：
[2412.06464](https://arxiv.org/abs/2412.06464)




#### DSA 稀疏注意力（2025.09）



- **所属线路**：注意力与位置编码



- **是什么**：DeepSeek-V3.2 采用：一个轻量的「索引器」为每个 query 挑出最相关的 k 个 token，只对它们做注意力。

- **为什么重要**：长上下文的注意力计算从 O(L²) 降到 O(L·k)，DeepSeek 同时把 API 价格下调了一半以上。

- **要学会什么**：

  - 闪电索引器（lightning indexer）

  - top-k 稀疏选择

  - 在已训练模型上继续训练成稀疏

- **先学哪几个**：NSA 原生稀疏注意力、MLA 多头潜在注意力

- **论文**：
[2512.02556](https://arxiv.org/abs/2512.02556)




#### DeepSeek-V4（2026.04）



- **所属线路**：模型主线 · 注意力与位置编码 · 混合专家 MoE · 规模与训练



- **是什么**：2026 年 4 月发布。Pro 版约 1.6T 总参数、49B 激活，Flash 版 284B / 13B，面向 100 万 token 上下文设计。

- **为什么重要**：据技术报告，在 100 万 token 长度下，单 token 推理计算量和 KV Cache 分别只有 V3.2 的约 27% 和 10%；注意力、残差连接和低精度训练都有新设计。

- **要学会什么**：

  - CSA / HCA：压缩 + 稀疏的混合注意力

  - mHC：流形约束超连接，稳定深层残差

  - 专家权重 FP4、其余 FP8 的混合精度

  - Muon 优化器

- **先学哪几个**：DeepSeek-V3、DSA 稀疏注意力



### 阶段 Agent · ReAct · MCP



> 让模型去做事

- **所属线路**：Agent

- **要学会什么**：

  - 什么时候停下来

- **要学会什么**：

  - 工具调用数据怎么构造

  - 自监督过滤

## 推荐学习顺序（21 站）



1. **Transformer**（2017.06）— 完全用注意力取代 RNN 的编码器-解码器架构，今天所有大模型的起点。

2. **GPT-2**（2019.02）— 15 亿参数的 decoder-only 模型，只靠预训练就能零样本完成多种任务，权重后来全部公开。

3. **反向传播 + Adam**（2017.00）— 一切训练的底层：链式法则把损失的梯度算回每个参数，Adam 给每个参数配自适应的步长。

4. **KV Cache**（2019.05）— 自回归生成时，把已经算过的每个 token 的 K、V 存起来，每一步只为新 token 计算。

5. **Scaling Laws**（2020.01）— 损失随参数量、数据量、计算量按幂律下降，可以用小模型的实验预测大模型的表现。

6. **LLaMA**（2023.02）— Meta 的开放权重模型，确立了之后开源模型的标准配方：Pre-RMSNorm、SwiGLU、RoPE。

7. **RoPE 旋转位置编码**（2021.04）— 把位置信息变成对 Q、K 向量的旋转，两个词的点积只和它们的相对距离有关。

8. **GQA 分组查询注意力**（2023.05）— MHA 和 MQA 的折中：把注意力头分成几组，每组共享一份 K、V。

9. **FlashAttention**（2022.05）— 不改变数学结果，只改变计算顺序：分块在 GPU 片上 SRAM 里算完 softmax，不再把 n×n 的注意力矩阵写回显存。

10. **vLLM / PagedAttention**（2023.09）— 像操作系统的分页内存一样管理 KV Cache，再配合连续批处理。

11. **Switch Transformer**（2021.01）— 每个 token 只路由到 1 个专家，把 MoE 大幅简化，扩展到 1.6 万亿参数。

12. **DeepSeekMoE**（2024.01）— 把专家切得更细、每次选更多个，并保留几个所有 token 都会经过的「共享专家」。

13. **MLA 多头潜在注意力**（2024.05）— DeepSeek-V2 提出：把 K、V 压缩成一个低维潜在向量再缓存，用的时候再还原；RoPE 部分单独处理。

14. **DeepSeek-V3**（2024.12）— 6710 亿总参数、每个 token 激活 370 亿的 MoE 模型，集成了 MLA、无辅助损失的负载均衡、多 token 预测（MTP）和 FP8 混合精度训练。

15. **InstructGPT / RLHF**（2022.03）— 三步：人工示范做监督微调（SFT）→ 用人类偏好训练奖励模型 → 用 PPO 强化学习优化。

16. **DPO**（2023.05）— 证明 RLHF 的目标可以直接写成偏好数据上的分类损失，不需要单独的奖励模型和 PPO。

17. **GRPO**（2024.02）— DeepSeekMath 提出：去掉价值网络，对同一个问题采样一组回答，用组内平均分做基线。

18. **DeepSeek-R1**（2025.01）— 在 V3 上直接用 GRPO + 规则奖励做强化学习（R1-Zero），模型自发学会反思和长推理；再经过冷启动数据和多阶段训练得到 R1，权重开放。

19. **ReAct**（2022.10）— 让模型交替输出「思考 → 行动（调用工具）→ 观察结果」，循环直到任务完成。

20. **MCP 模型上下文协议**（2024.11）— Anthropic 发布的开放协议，统一 Agent 连接外部工具和数据源的方式。

21. **DeepSeek-V4**（2026.04）— 2026 年 4 月发布。Pro 版约 1.6T 总参数、49B 激活，Flash 版 284B / 13B，面向 100 万 token 上下文设计。
