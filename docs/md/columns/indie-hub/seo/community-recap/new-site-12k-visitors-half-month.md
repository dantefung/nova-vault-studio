# 放弃批量上站后，一个新站半个月来了1.2万访客

上个月，我批量上线了30多个游戏站。有些站月访客过万，但后来都陆续回落，有的甚至归零。最后赚到的一点广告费，连域名的成本都没覆盖。我不得不放弃继续批量上新站。

随后，我搭建了一个新的内容平台，这次不再局限于某个新词，而是通过不断地挖掘关键词和长尾词给网站增加内页。结果网站一点都不爆，而是十分佛系地缓慢上涨，半个月左右涨到1.2万访客：

![image](./images/001.png)

最近一天访客数超过3600，30分钟实时访客最高超过150：

![image](./images/002.png)

GSC也呈现出逐步向上的走势：

![image](./images/003.png)

可能有读者会想，这样不断铺页面，不会被谷歌惩罚吗？这个问题我也担心。最近生财就有圈友的网站，在短时间大涨后又迅速回落了99%。当然，单凭流量回落，也不能直接判断原因。

说实话，我也不确定这个网站的访客增长是否可以持续。然而，我对这个网站做足了功课：比如页面内容尽可能不要太过单薄，尽可能能给用户提供一些真正的价值；再比如把页面内容保存在数据库，这样有利于页面之间的关联和数据共用；再比如改版了3个Skills，实现通过Skills直接调研后添加页面并入库，以及后续内容的不断更新；等等。

其中一个Skill在更新内容时，还通过Codex的定时任务设置了串行队列，有时连续跑了将近24小时。这也让我第一次实现日用10亿Token，并跻身生财的Token排行榜前100：

![image](./images/004.png)

最近，大家都在聊Agent和自动化，生财有些圈友每天Token使用量高达上百亿，其自动化程度让我望尘莫及。不过，通过这个网站最近的实践，我也开始有了一些想法：能否把这个网站获取关键词、添加页面和更新页面这些流程对应的Skills，通过Codex的定时任务，或者Hermes、小龙虾，进一步串起来，让其中适合重复执行的环节自动运行？这样，是否有机会实现一个网站的自动更新和自动运营？

当然，这个网站的流量能不能持续，最后能不能赚到钱，现在都还不能下结论。日用多少Token，也不能替我回答这些问题。

你觉得，一个网站要实现“自动更新”和“自动运营”，需要做哪些事情？欢迎交流。
