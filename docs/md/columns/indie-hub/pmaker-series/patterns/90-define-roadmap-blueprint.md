# 产品演进蓝图

[首页](https://pmaker.space/index.html)/[定义产品](https://pmaker.space/index.html#dingyi)/产品演进蓝图
蓝图不是排期表。它排的是验证顺序，功能只是每一步的手段。

## 产品演进蓝图

把接下来三版画在一张图上，每一版写清楚它要验证什么。功能列表是结果，不是起点。

你会遇到的现象

*   做完第一版，不知道下一步该做什么，只能看谁在提需求
*   排期表列得很满，但说不清为什么是这个顺序
*   做了半年，回头看不出产品比当初进步在哪

排期表

3 月：记录、分类

4 月：统计、图表

5 月：导出、分享

按功能排。上线之后无法判断对错

演进蓝图

v1 验证有人愿意记 → 次周留存

v2 验证记了会回来看 → 回访频率

v3 验证愿意付钱 → 付费转化

按假设排。每一版都有明确结论

左边那张表最大的问题是它无法失败。做完了就是做完了，没有一个标准告诉你要不要继续往下走。

## 怎么写

每一版四行，写不满就说明这一版还没想清楚。

| 这一行 | 写什么 | 例子 |
| --- | --- | --- |
| 要验证的假设 | 一句能被证伪的话 | 他愿意每天花十秒记一笔 |
| 为此要做的 | 能验证这条假设的最小范围 | 只做记一笔的完整流程 |
| 看哪个数 | 一个指标，不是一堆 | 次周留存 |
| 什么算成立 | 提前定一条线 | 次周留存高于 25% |

第四行必须提前写。事后再定标准，人总能找到理由说服自己这个数还不错。

左边那张表最大的问题不是排得不对，是**它无法失败**。而只画三版就够了——再往后的都是猜，画得越远越像承诺，改起来心理负担越大。

## 什么时候改

*   **每一版发完就重看一遍。**假设成立，按原计划走下一版；不成立，下一版应该是换个方式再验一次同一条假设，而不是往前推进。
*   **只画三版。**再往后的都是猜。画得越远越像承诺，改起来心理负担越大。
*   **假设变了要写清楚原因。**蓝图的价值有一半在于它记录了你当初怎么想的，回头看能知道判断错在哪。
*   **别把它当承诺发出去。**对外可以讲方向，具体版本内容留在内部。发出去之后，改动就变成了失信。

一个人做产品的时候，这张图可以就是一份 markdown，三段，每段四行。重要的不是形式，是每一版开工前你都能说出「这一版我在赌什么」。
