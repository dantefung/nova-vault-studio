# 画用户路径

[首页](https://pmaker.space/index.html)/[设计交互](https://pmaker.space/index.html#jiaohu)/画用户路径
主路径只有四步，但每一步都要想清楚：走不通的时候他去哪，中途走开了回来还能不能接上。

## 画用户路径

把一次完整任务画成一条线：从哪进来、走几步、每一步可能岔到哪、走不下去时怎么办。

你会遇到的现象

*   主流程能走通，稍微不按预期操作就卡死
*   用户填到一半退出，回来发现全没了
*   让 AI 一页页做，每页都对，串起来发现少了一步

## 怎么画

| 步骤 | 做什么 |
| --- | --- |
| 定起点 | 用户从哪进来。首页、搜索结果、推送、还是别人发的链接。起点不同，他知道的信息不一样 |
| 列主路径 | 顺利情况下的每一步。控制在三到五步，超过就该考虑拆或简化 |
| 标判断点 | 每一步之后问一句：这里会不会有分支。用菱形标出来，两条路都要画 |
| 补异常出口 | 每一步都问：他中途走了怎么办、失败了去哪、没权限怎么办 |
| 画返回路径 | 每个终点都要能回到起点或某个稳定位置，不能是断头路 |

主路径超过五步是个信号。要么是任务本身该拆成两次，要么是中间有几步可以合并或用默认值跳过。

红色那一排下面的字，就是**情绪线推出来的设计决定**——「客户有点多，找起来烦」直接推出「支持搜索、把最近合作的排前面」。写不出情绪，通常说明你对这个场景还不够熟。

## 分支从哪来

四个地方最容易长出分支，画的时候逐个问一遍。

*   **身份不同。**登录没登录、免费还是付费、什么角色。同一个按钮对不同人的结果不一样。
*   **数据状态不同。**第一次用还是老用户、有没有历史数据、当前对象处在什么状态。
*   **操作失败。**网络断了、校验没过、权限不够、并发被人改了。每一种的落点都不同。
*   **用户中途离开。**切走了、关了页面、手机来电话了。回来时能不能接着上次的地方继续。

最后一条在移动端尤其重要。假设用户随时会被打断，那么每一步的中间结果都该被保住——这条判断会直接改变你的数据设计，因为你得有个地方存草稿。

## 加一条情绪线

路径画完之后，可以在每一步下面标一下用户此刻的状态：着急、犹豫、担心出错、想赶紧结束。这就是用户体验地图。

| 步骤 | 他在想什么 | 于是这一步要 |
| --- | --- | --- |
| 选择客户 | 客户有点多，找起来烦 | 支持搜索，把最近合作的排前面 |
| 勾选记录 | 别漏了，漏了要重来 | 显示已选数量和总额，支持全选 |
| 有未确认的 | 又要跳走，回来还得重选 | 就地处理，或者保住已勾选的状态 |
| 生成对账单 | 格式对不对，客户能看懂吗 | 先给预览，确认之后再发出去 |

情绪那一列不是文学修饰，它直接推出了右边那列的设计决定。写不出情绪，通常说明你对这个场景还不够熟。
