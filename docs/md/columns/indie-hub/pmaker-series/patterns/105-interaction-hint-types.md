# 提示的五种形式

## 提示的五种形式

提示要跟事情的严重程度匹配。用弹窗报一条无关紧要的消息，用户下次就学会了闭眼点确定。

你会遇到的现象

*   用户对所有弹窗都直接点确定，从来不看内容
*   重要的提示被做成了轻提示，一闪而过没人注意到
*   推送发多了，用户直接关掉了通知权限

## 五种形式

| 形式 | 什么时候用 | 长什么样 |
| --- | --- | --- |
| 数字提示 | 有几条待处理的东西 | 图标角上的小红点加数字，不打断任何操作 |
| 气泡提示 | 引导用户注意某个新功能 | 屏幕角落的短文本气泡，看不看都行 |
| 全局提示 | 重要的状态变化或紧急信息 | 顶部横幅或中央弹窗，覆盖在内容上 |
| 消息公告 | 长篇信息，比如维护通知、更新说明 | 专门的公告板块，用户主动点进去看 |
| 推送 | 用户不在应用里，但你需要他知道 | 系统通知中心。最贵的一种，用多了会被关掉 |

除了这五种，还有一批用得少但有用的：工具提示（悬停显示说明）、焦点提示（高亮当前输入框）、进度提示（上传下载的进度条）、确认框（关键操作前拦一道）、动画提示（完成时的打勾动效）。

## 强中弱三档

选形式之前先判断强度。标准只有一条：这件事用户如果不处理，会不会出问题。

## 警告、提示、错误

按目的分，提示语只有三类，它们的语气和落点都不同。

| 类型 | 目的 | 例子 |
| --- | --- | --- |
| 警告 | 提前告诉他后果，但不拦着 | 「确定删除这些文件吗？这个操作不可恢复」 |
| 提示 | 帮他做得更好，不是纠正错误 | 「为了账户安全，建议用更复杂的密码组合」 |
| 错误 | 说清出了什么问题，怎么改 | 「密码错误，请重新输入」 |

警告的关键在于不阻止用户，只给他一个思考的机会。把警告做成拦截，用户会开始机械地点确定，警告就失效了。
