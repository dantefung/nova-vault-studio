# 参考锚定

## 参考锚定

与其说「做得简洁一点」，不如说「参考某个具体东西的某个具体部分」。

你会遇到的现象

*   说了一堆形容词，做出来还是那个通用模板样子
*   来回改了五轮，每轮都在用另一组形容词描述同一件事
*   你心里有个大概的样子，但说不出来

形容词的问题是它在描述感受，而感受因人而异。「简洁」对你是留白多，对它可能是元素少；「专业」对你是信息密度高，对它可能是配色偏深蓝。你们用同一个词，指的不是同一件事。

对照物没有这个歧义。它是一个客观存在的东西，你可以指着它说「就这个」，也可以指着说「这个不要」。

## 锚定哪几件事

| 锚定什么 | 怎么说 | 比说形容词好在哪 |
| --- | --- | --- |
| 结构 | 参考邮件客户端的左导航加列表加详情 | 「布局清晰」说不出该有几栏 |
| 密度 | 信息密度参考某个任务管理工具的列表 | 「简洁」既可能是留白多，也可能是内容少 |
| 语气 | 文案语气参考某个产品的错误提示 | 「友好」是个方向，不是个标准 |
| 代码风格 | 参考项目里已有的某个文件 | 「保持一致」不说清跟谁一致等于没说 |
| 反面参考 | 别做成某类页面那样，理由是什么 | 排除法有时比正面描述更快收敛 |

最后一行常被忽略。给一个「不要像这样」的例子，往往比三个正面例子更能锁定方向。

给参考时最容易漏的一步是**说清借什么、不借什么**——只借结构不借功能，只借密度不借配色。还有一个几秒钟的检查：让它先复述一遍打算借哪些，你能立刻发现理解偏差。

## 怎么给

*   **指名到具体部分，不要指整个产品。**「参考某产品」太大，「参考它的任务列表那一屏」才可执行。
*   **说清借什么、不借什么。**只借结构不借功能，只借密度不借配色。不说清楚它会连功能一起抄（见[借形](https://pmaker.space/patterns/borrow-form.html)）。
*   **用截图。**能给图就给图，一张截图比一段描述准得多。给完之后还要说明你看中的是它的哪一点。
*   **项目内部的参考最好用。**「照着已有的 OrderList 组件的写法」，这是最强的锚——它就在代码库里，没有任何解释空间。
*   **让它先复述。**要求它说一遍打算借哪些、不借哪些，你能在几秒内发现理解偏差。

- 它的配色。配色用项目现有的设计令牌
