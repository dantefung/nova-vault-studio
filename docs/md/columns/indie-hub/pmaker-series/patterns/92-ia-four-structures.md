# 四种组织结构

## 四种组织结构

内容之间的关系决定结构。先看清楚这批内容本身是树状、表状、链状还是网状，再决定界面怎么组织。

你会遇到的现象

*   分类怎么分都有东西放不进去，或者能放进两个分类
*   用户要找一个东西，得先猜它被归到了哪一类
*   层级越挖越深，第四层往下基本没人到达

## 怎么选

| 结构 | 什么时候用它 | 代价 |
| --- | --- | --- |
| 层级 | 内容天然有从属关系，一个东西只属于一个分类 | 分类边界模糊时会很痛苦，用户得猜你怎么归的类 |
| 矩阵 | 一个东西同时有多个属性，用户从不同角度找它 | 要做好筛选和排序，否则等于把难题丢给用户 |
| 线性 | 步骤有严格先后，前一步没完成后一步没意义 | 中途要能退回和保存，否则用户断在半路就全丢了 |
| 自然 | 内容之间的关联比归属更重要，探索本身是价值 | 新用户会迷路，必须配一个入口页或者推荐 |

矩阵和层级最容易混淆。判断方法：一个内容能不能同时属于两个分类。能，就是矩阵，硬做成层级会一直有东西无处安放。

分类里出现「综合」「其他」，或者同一个东西被放进多个分类还互相不同步——这两个症状说的都是同一件事：**这批内容本来是矩阵，被硬做成了层级。**

## 经常是混着用

真实产品很少只用一种。常见的组合是：整体层级，某一层内部用矩阵，关键任务走线性。

一个电商产品里的三种结构

层级 首页 → 品类 → 子品类，用户按分类逛

矩阵 子品类里按价格、品牌、评分交叉筛选

线性 下单流程：地址 → 支付 → 完成，不能跳步

自然 详情页底部的「看了又看」，靠关联跳转

混用没问题，但同一个界面里不要同时暗示两种结构。既有分类树又有标签云，用户会不知道该按哪套逻辑找。

## 选错的样子

*   **该用矩阵却用了层级。**表现是分类里出现「综合」「其他」，或者同一个东西被放进多个分类还互相不同步。
*   **该用层级却用了自然。**表现是新用户打开之后不知道从哪儿开始，只能靠搜索。
*   **该用线性却做成了自由跳转。**表现是用户跳着填，最后提交时才发现前面漏了必填项。
*   **该用自然却强行分类。**表现是内容之间明明有关联，但界面上完全体现不出来，用户只能靠记忆去翻。
