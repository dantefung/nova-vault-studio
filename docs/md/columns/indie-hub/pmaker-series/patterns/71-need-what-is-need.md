# 什么是需求

## 什么是需求

需求是用户在某个处境下想达成的状态。它不是用户说出来的那句话，也不是你打算做的那个功能。

你会遇到的现象

*   照着用户说的做完了，他还是不满意
*   功能一个个加上去，产品越来越重，问题还在
*   两个用户提的需求互相打架，不知道该听谁的

用户说的是他能想到的解决办法，不是他的问题。他习惯用 Excel，所以他要导出；他见过别的软件有这个按钮，所以他也要。把这句话当需求，做出来的东西就永远跟在别人的想象后面。

上下两层都是**方案**，只是分别出自用户和你。把最上面那句当需求，做出来的东西就永远跟在别人的想象后面；而中间那层写清楚了，方案可以有好几个，你才有得选。

## 需求的六个特征

这六条决定了需求为什么这么难对付。

| 特征 | 对你意味着什么 |
| --- | --- |
| 源于现实 | 需求受技术和环境限制。通讯的需求没变过，但从书信变成了即时消息 |
| 因人而异 | 同一个功能，两个人要的东西可能完全不同。所以要问具体的人 |
| 不断发展 | 满足了会长出新的。今天的惊喜是明天的标配 |
| 相互关联 | 一个需求满足不了时，人会用别的方式补偿。这是替代方案的来源 |
| 有层次 | 低层的没满足，高层的就不成立。刚失业的人不会先考虑自我实现 |
| 会冲突 | 一批人要功能多，一批人要打开快。冲突不可能全解决，只能选边 |

最后一条是很多产品变臃肿的根源：两边都不想得罪，于是两边的功能都加上，最后谁都不满意。

## 哪几种分类真用得上

需求的分类方式有十几种，日常真正会改变你决定的是这三种。

按有没有说出口

显性 已经明确提出来的

潜在 他自己都还没意识到

显性需求你在竞品上都能看到，潜在需求才是差异化的来源

按会不会掏钱

有效 有意愿也有能力买单

无效 想要，但不会为它付出

「我会用的」和「我会付钱」之间隔着一整条鸿沟

按软件怎么落地

功能性

这个东西要能做什么。写需求时大部分人只写这一半

非功能性

多快、多稳、多好用。漏掉这一半，AI 生成的东西演示能过、上线就垮

最后这一组尤其要注意。你说「做一个搜索」，功能性的部分 AI 一定会做；「三千条数据下要在一秒内出结果」这种非功能性的要求，你不说它就不会想。
