# 进阶路线与书单

四个阶段各自的卡点不一样。先认清自己卡在哪一段，再决定补什么。

## 进阶路线与书单

产品能力不是读出来的，是做砸几次之后长出来的。书的作用是让你知道自己砸在哪一步，而不是替你走完这几步。

## 四个阶段补什么

| 阶段 | 这一段的目标 | 该补的东西 |
| --- | --- | --- |
| 能做出来 | 把想法变成能跑的东西，哪怕很糙 | 技术底子、AI 协作方式、一个完整走完的小项目 |
| 做得像样 | 结构清楚，交互不别扭，别人能上手 | 信息架构、交互原则、设计系统基本功 |
| 有人用 | 解决的是真问题，而且人会回来 | 需求辨真伪、用户访谈、留存与漏斗 |
| 能自己转起来 | 有收入，也知道增长从哪来 | 商业模式、定价、增长循环 |

常见的错位是在第一段就读增长的书。那些方法要有用户量才用得上，没到那一步读了也用不上，读完就忘。

读的方式比读什么更重要：**带着一个具体问题去读，读完立刻用一次。**看完 KANO 就把自己需求池里的东西分一次档——没有落到具体东西上的阅读，一周后剩不下什么。

## 书单

按上面的阶段配。每一段挑一两本读透，比列二十本更管用。

| 对应阶段 | 书 | 读它解决什么 |
| --- | --- | --- |
| 做得像样 | 《用户体验要素》 | 五层结构那套框架的原始出处，薄，一天能读完 |
| 做得像样 | 《设计心理学》 | 为什么门要推还是拉。讲的是人怎么理解物件，界面同理 |
| 做得像样 | 《写给大家看的设计书》 | 对齐、对比、亲密性、重复。四条讲完了排版的地基 |
| 有人用 | 《精益创业》 | MVP 和验证循环的出处。别只记住 MVP 那个词 |
| 有人用 | 《上瘾》 | 触发、行动、奖励、投入。讲习惯是怎么形成的 |
| 有人用 | 《俞军产品方法论》 | 中文语境里少见的、真正讲判断而不是讲流程的书 |
| 转起来 | 《增长黑客》 | AARRR 那套的展开，有用户量之后再读 |
| 转起来 | 《商业模式新生代》 | 九宫格画布，用来自查商业模式有没有漏 |

《人人都是产品经理》这类入门书适合最开始建立概念，但里面很多流程细节针对的是大团队协作，一个人做产品时用不上。

## 怎么读才有用

*   **带着一个具体问题去读。**手上正卡着某件事的时候读，能记住的比通读一遍多得多。没有问题就先别读。
*   **读完立刻用一次。**看完 KANO 就把自己需求池里的东西分一次档。没有落到具体东西上的阅读，一周后剩不下什么。
*   **方法论不用背，知道去哪查就行。**这也是这个站存在的原因：需要的时候翻一页，用完就走。
*   **做砸的项目比读完的书值钱。**一个上线后没人用的东西，教给你的东西比三本书多。前提是你复盘了它为什么没人用。
