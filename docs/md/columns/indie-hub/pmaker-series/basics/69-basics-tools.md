# 工具与模板

工具解决的是熟练度问题，不是能力问题。挑的时候只看一件事：它能不能减少你在两个环节之间搬运东西的时间。

*   **先看输出能不能被下一步直接吃掉。**画完的流程图能不能直接贴给 AI，设计稿能不能直接导出代码。搬运成本才是真正的开销。
*   **一格只留一个。**同类工具装三个的结果是三个都不熟，而且资料散在三处。
*   **能被 AI 替掉的就别学了。**过去要花几周练熟的原型工具，现在描述清楚就能出稿。把时间留给判断，不是留给操作。

## 按环节的清单

| 环节 | 要解决什么 | 这一格里选什么 |
| --- | --- | --- |
| 调研 | 看清楚别人怎么做的 | 应用商店榜单、产品目录站、社区里的真实吐槽。比任何分析报告都有用 |
| 整理 | 把零散想法攒住 | 一个笔记工具加一张需求池表格就够。重点是每条要记下来源和日期 |
| 画图 | 把结构和流程画清楚 | 白板类工具画流程和信息架构；用文本描述生成图的方式更适合跟 AI 配合 |
| 原型 | 让人能点一点 | 直接让 AI 生成可运行的页面，比传统原型工具快，而且能真的点 |
| 开发 | 把东西做出来 | 一个 AI 编程环境 + 代码托管 + 一个能一键部署的平台，三件套 |
| 数据层 | 存数据、管登录 | 用现成的后端服务，别自己搭。登录、数据库、文件存储通常一起给了 |
| 埋点 | 知道人在哪一步走了 | 轻量的分析工具就够，关键是上线前就装好 |
| 收钱 | 订阅和一次性付费 | 用成熟的支付服务，自己不要碰卡号和结算逻辑 |

这里不写具体产品名，因为这一格里的选择每年都在变，但每一格要解决的问题十年没变过。按问题去找当下最合适的那个。

## 四份模板

比工具更值钱的是模板。这四份反复用得上，可以自己攒一套。

走查清单

✓ 四种状态都做了吗

✓ 零条数据和超长内容试过吗

✓ 键盘能走完主流程吗

✓ 密钥有没有写进代码

**走查清单**上线前逐条过

CLAUDE.md

- 组件必须实现四态

- 间距只用 4 的倍数

- 权限判断一律在后端

- 改动前先更新 spec

**约束文件**反复要说的话写这儿

后两份是 AI 时代新增的。走查清单和约束文件的作用是一样的：把你脑子里的标准变成一份能被反复执行的东西。
