# 产品思维模型

这些模型本身不会给你答案。它们的价值是当检查清单用，逼你把没想到的那一面补上。

用空的典型症状：把 SWOT 四个格子填满就交差了，填完既没改变任何决定，也没人再看第二眼。判断一个模型这次用得值不值，只有一条标准——用完之后，你的决定变了吗。

下面挑三个最常用的展开，其余的在上面那张图里知道什么时候拿出来就够了。

## KANO：需求分档

把需求分成五类，决定先做哪个。它回答的是「这个功能加了，用户会不会更满意」。

另外两类是无差异型（做不做都没人在意，直接砍）和反向型（做了反而招人烦，比如强制注册）。排优先级的顺序是：先补齐基本型，再挑一个兴奋型，期望型按资源慢慢加。

## 用户体验五要素

从抽象到具体的五层。它最大的用处是提醒你：出问题时先往上一层找，别在最表层反复改。

界面怎么调都别扭，问题通常在结构层；结构怎么理都乱，问题通常在范围层——功能太多了。往下一层找，比在原地改快得多。

## AARRR

把用户从来到走的整条路拆成五段，用来定位「到底卡在哪一步」。

**获取**来了多少人

**激活**有多少人用起来了

**留存**有多少人回来

**收入**有多少人付钱

**推荐**有多少人带人来

用法不是把五个数都盯着，是找出掉得最狠的那一段集中改。多数产品的问题在激活到留存之间——人来了，试了一次，没有再回来。
