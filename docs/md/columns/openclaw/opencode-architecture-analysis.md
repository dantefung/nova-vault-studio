# OpenCode架构与扩展能力解析

## 本文阐述 OpenCode 开源 AI 编程 Agent 的七层架构，实现推理、工具调用、会话管理等能力解耦。梳理 LLM Provider、Plugin、Skill、MCP、自定义 Agent 五大扩展方向，覆盖模型接入、进程内增强、业务编排、跨进程工具、子智能体场景，提供各扩展的目录路径与操作步骤，配套选型表辅助开发者快速完成二次开发。

## 一、OpenCode 架构简介

OpenCode 是面向工程化的开源 AI 编程 Agent，采用客户端‑服务端分离、插件化、多协议接入架构。 核心目标：把大模型推理、工具调用、会话管理、业务编排解耦，支持私有化部署、自定义工具、业务 Skill 编排、外部系统对接，适配本地终端、IDE 插件、Web 多客户端。

### 分层详细说明

#### 1. 客户端接入层 Client Layer

包含 TUI 终端、VSCode IDE 插件、WebUI、Tauri 桌面等交互入口。只负责接收用户输入、展示对话与工具执行结果，本身不承载业务逻辑。全部客户端统一通过 HTTP、WebSocket 和后端网关通信，客户端与服务端完全解耦，支持多个客户端同时对接同一个服务实例。

#### 2. 服务网关层 Server Gateway (Hono)

基于 Hono 实现的 HTTP/WebSocket 网关，对外暴露 REST 接口以及流式会话接口。承担请求鉴权、路由分发、会话转发、流式输出封装能力，所有客户端流量统一收口在此层。

#### 3. 核心业务层 Core Engine（系统核心）

AgentEngine Agent 主循环：OpenCode 的核心调度组件，承载完整 Agent 执行闭环：接收用户输入、组装提示词、调用大模型推理、解析工具调用指令、调度工具执行、收集工具返回结果，循环迭代直至任务完成；同时支持子 Agent 任务委派、异常重试、任务自愈。

SessionManager 会话管理器：负责多会话管理，维护多项目上下文，提供消息压缩、会话断点恢复、工作目录隔离能力，不同会话、不同项目环境之间互相隔离。

ToolRegistry 工具注册中心：统一完成工具注册、能力发现、权限校验、执行分发。统一管理内置原生工具、插件注册工具、MCP 协议工具，向上层 Agent 屏蔽工具的底层来源差异。

SkillEngine Skill 编排引擎：扫描解析项目目录下声明式 Skill 定义文件，封装可复用的复杂业务流程，Agent 可以自动识别并触发 Skill 执行业务流水线。

CommandManager 命令管理器：处理终端斜杠命令，同时支持系统内置命令和业务自定义扩展命令。

EventBus 全局事件总线：实现全链路事件分发，覆盖会话、工具执行、模型调用等各类事件；插件 Hook 钩子机制底层依赖事件总线实现。

#### 4. 插件扩展层 Plugin System

插件加载器负责读取项目目录、用户全局目录、npm 包形式的 TypeScript 插件。提供全套 Hook 钩子，能够拦截、修改、增强系统全链路流程，无需修改源码即可完成能力扩展。

#### 5. 外部协议适配层 Protocol Adapter

MCP Client：同时支持 Stdio 本地子进程、SSE 远端 HTTP 两种传输模式，对接外部 MCP 工具服务。 LSP Client：对接语言服务器，获取代码诊断、代码符号、代码补全相关信息。 PTY 终端管理器：托管 Shell 终端会话，安全执行 shell 命令。

#### 6. 基础设施层 Infra

SQLite 负责持久化会话记录、消息、配置数据；文件系统组件完成项目文件读写访问。

#### 7. 模型适配层 LLM Provider

提供统一的 Provider 抽象接口，隔离各类大模型后端的差异。上层 Agent 无需感知底层模型实现细节，支持 OpenAI 兼容接口、Ollama、私有化推理服务以及自定义实现的模型适配器。

### 完整端到端数据流

用户输入 → 客户端 → Hono网关 → AgentEngine→ 组装Prompt，调用LLM Provider推理→ LLM返回结果，解析工具调用→ ToolRegistry分发工具├─内置工具 / Plugin工具：进程内执行└─MCP工具：转发到MCP服务（本地子进程/远端SSE）→ 工具执行结果回传给AgentEngine→ Agent循环迭代，直到任务完成→ 结果经由网关返回客户端展示

## 二、OpenCode 主要扩展点

OpenCode 扩展体系分为五大类：LLM Provider 模型接入、Plugin 钩子扩展、Skill 声明式编排、MCP 外部工具协议、自定义 Agent/Command。 每个扩展点包含：扩展点描述、定位、适用场景。

### 1. LLM Provider（模型适配器扩展点）

扩展点描述：实现 Provider 抽象接口对接不同大模型推理后端，分为配置式 OpenAI 兼容适配器、编码开发自定义 Provider 两种实现方式。定位：模型层扩展，解决大模型后端接入问题，隔离 Agent 业务逻辑与底层推理服务。适用场景

接入私有化部署大模型，例如昇腾 vLLM 等内部推理服务；

对接非标准 OpenAI 报文、带有特殊鉴权逻辑的模型服务；

实现多模型切换，单套 OpenCode 对接多套推理后端。

### 2. Plugin 钩子扩展（TS 插件系统）

扩展点描述：基于官方插件 SDK 开发 TypeScript 插件，挂载系统全链路 Hook；可以注册自定义工具，拦截会话、工具、命令、鉴权、权限等全生命周期事件。定位：进程内深度扩展，侵入能力最强，插件运行在 OpenCode 主进程内部。适用场景

请求改写，修改模型请求参数、追加内部鉴权请求头；

实现轻量自定义工具，完成工具执行前后拦截、日志审计、参数校验、结果改写；

接管登录鉴权流程，替换系统自带交互式登录逻辑；

自定义权限校验、审计日志、shell 环境变量注入；

拦截内置命令，新增轻量终端斜杠命令。

### 3. Skill 声明式业务流程扩展

扩展点描述：基于 Markdown+YAML 元数据定义 Skill 文件，声明业务目标、提示词、可用工具集合与约束条件，OpenCode 自动识别，Agent 可自动调用完成复杂业务。定位：业务流程编排扩展，无代码 / 少代码，面向业务场景封装，不改动底层源码。适用场景

封装固定业务流水线，例如昇腾模型迁移、精度对齐检查、代码评审等；

将高频重复的多轮 Agent 交互固化为可复用的业务能力；

业务域能力封装，交付业务用户直接使用。

### 4. MCP Model Context Protocol 外部工具扩展

扩展点描述：MCP 为独立进程工具协议，支持 Stdio 本地子进程、SSE 远端 HTTP 两种传输方式；OpenCode 作为 MCP 客户端，发现并调用外部 MCP 服务暴露的工具能力。定位：跨进程扩展，将工具业务逻辑与 OpenCode 主进程隔离，支持多语言开发工具。适用场景

CPU、IO 密集或者高风险逻辑，避免拖累主进程稳定性；

对接外部系统，如知识图谱、数据库、昇腾工具链、第三方业务服务；

使用 Python、Go、Java 等非 TypeScript 语言开发工具；

MCP 服务远端部署，多个 OpenCode 实例可以共享同一套工具服务。

### 5. 自定义 Agent & 自定义 Command 扩展

扩展点描述自定义 Agent：通过 yaml 配置文件定义子 Agent，配置独立的系统提示词、绑定模型、限定可用工具集合；主 Agent 可以委派子 Agent 承担专项任务。 自定义 Command：新增终端斜杠命令，可通过 Plugin 或者配置完成注册。定位：任务角色扩展，拆分专家子智能体，实现任务委派。适用场景

构建专项专家 Agent，例如算子适配 Agent、代码审计 Agent；

不同任务场景使用不同模型、不同工具集合；

新增终端快捷命令，快速触发特定业务任务。

## 三、如何进行扩展（5 种扩展实操路径）

### 路径 1：接入私有化大模型（LLM Provider 扩展）

确认待接入推理服务接口能力，确认模型支持 function‑call 工具调用。

若服务兼容 OpenAI 接口，直接修改项目根目录下opencode.json配置文件，新增模型提供者配置，填写服务地址、密钥、模型参数、上下文长度，设置默认使用模型。

若存在 SSO、自定义签名等非标鉴权，编写 TypeScript 插件，使用 auth 钩子接管鉴权流程。

重启 OpenCode 服务，查看运行日志，验证模型调用链路正常。

### 路径 2：TS Plugin 插件扩展

根据生效范围选择插件存放目录：项目级插件放置在当前项目根目录.opencode/plugins；全局插件放置在用户家目录.config/opencode/plugins；公共插件可以打包为 npm 包，在 opencode.json 中声明包名。

参照官方 SDK 规范编写 TypeScript 插件，完成钩子挂载、自定义工具注册，实现请求修改、日志、权限校验等业务逻辑。

保存插件文件，重启 OpenCode 服务。

触发对应业务操作，验证插件钩子、自定义工具是否正常生效。

### 路径 3：Skill 声明式业务流程扩展

在当前项目根目录手动创建.opencode/skill目录。

在该目录下新建后缀为.skill.md的 Skill 定义文件，一个文件对应一条业务流水线。

在文件头部 YAML 元数据填写 Skill 名称、描述、允许调用的工具白名单，文件主体编写业务提示词，定义业务执行流程。

保存文件，系统自动扫描加载，无需重启服务。

输入对应业务需求，验证 Agent 可以自动匹配并执行该 Skill 流水线。

### 路径 4：MCP 外部工具扩展

#### Stdio 本地子进程模式

开发 MCP 服务，使用标准输入输出协议实现交互，不启用 HTTP 服务，业务日志输出到外部文件。

在opencode.json配置文件中填写 MCP 服务的启动命令、环境变量。

重启 OpenCode，系统自动拉起本地 MCP 子进程，通过管道完成通信，自动识别 MCP 对外暴露的全部工具。

调用对应工具，验证跨进程调用可以正常返回结果。

#### SSE 远端网络模式

部署完成远端 MCP 服务，确认 SSE 访问地址可连通。

在opencode.json中填写远端 MCP 服务访问地址。

重启 OpenCode，建立网络连接，自动拉取远端提供的工具列表。

执行工具调用，验证远端服务交互正常。

### 路径 5：自定义 Agent 子智能体扩展

在当前项目根目录手动创建.opencode/agents目录。

在目录下新建后缀为.agent.yaml的配置文件，一份文件对应一个子 Agent。

在配置文件中填写 Agent 名称、领域专属系统提示词、绑定目标模型、配置可用工具白名单与业务约束。

保存配置文件，系统自动加载。

下发对应领域任务，验证主 Agent 可以识别并委派该子 Agent 处理任务，可搭配 Skill、MCP 工具完成完整业务。
