# 知识库首页 Quiet Library 设计方案

## 目标

将 `https://eastondev.com/blog/zh/` 的克制博客视觉语言转化为 Nova Vault Studio 的默认首页样式。只修改首页，不改文章页、侧边栏、搜索、主题切换和其他站点功能。

## 已确认选择

- 改造范围：只改首页
- 首页任务：同时提供知识分类入口和最近更新内容
- 视觉方向：A · Quiet Library
- 视觉关键词：浅色纸面、蓝色强调、圆角面板、安静阅读、真实内容
- 交互原则：轻量反馈，避免无意义动画

## 信息架构

首页从上到下由以下区域组成：

1. 保留现有 VitePress 顶部导航和操作区。
2. 首页定位区域：用简洁标题说明知识库是什么，副标题说明 AI、开发、商业、书籍和长期学习的范围。
3. “从这里开始”入口区域：优先展示指南、Wiki、专栏、书籍、教程，并提供全部内容入口。
4. “最近更新”区域：展示仓库中真实存在的近期 Markdown 内容，点击进入对应页面。
5. 保留现有 footer、评论、统计和站点基础设施。

首页不展示虚构的访问量、文章数量、用户数量或其他统计数字。没有可靠日期的内容不伪造日期。

## 视觉系统

### 颜色

- 页面背景：接近白色的浅蓝灰纸面
- 内容表面：白色
- 主文字：深蓝灰
- 次要文字：中灰蓝
- 主强调色：中等亮度蓝色
- 边框：低对比度蓝灰色
- 强调入口背景：极浅蓝色

亮色主题是默认状态。暗色主题复用现有主题机制，仅通过首页局部 token 反转，不新增主题切换控件。

### 字体

- 品牌和首页主标题：使用现有站点可用的衬线字体或现有字体体系中的 serif fallback。
- 导航、卡片、元信息：使用现有无衬线正文体系。
- 不引入新的字体依赖，除非现有主题无法表达目标视觉。

### 形状与间距

- 内容使用居中的最大宽度阅读列。
- 卡片使用小到中等圆角，不使用夸张胶囊形。
- 边框优先于重阴影，阴影只用于 hover 状态或浮层。
- 桌面端分类入口为三列网格；平板端为两列；移动端为一列或紧凑两列。
- 最近更新使用单列列表，避免卡片墙压过文本。

## 响应式行为

- 桌面端：宽屏居中阅读列，导航和操作区保持现有布局。
- 平板端：分类入口从三列收缩为两列，内容仍保持相同顺序。
- 移动端：标题缩小，卡片降为单列或两列，最近更新的标题和元信息上下排列。
- 移动端导航复用现有 VitePress 移动菜单，不创建第二套菜单。

## 交互行为

- 分类卡片是普通站内链接，链接到对应真实目录。
- 最近更新条目是普通站内链接，链接到对应真实 Markdown 页面。
- 卡片 hover 只改变边框、背景和轻微阴影，过渡约 160-200ms。
- 尊重 `prefers-reduced-motion`，减少动画时不执行装饰性过渡。
- 不使用自动轮播、滚动驱动切换、复杂视差或 IntersectionObserver 内容替换。
- 不改变现有主题切换、搜索、侧边栏和文章页面交互。

## 内容数据

首页内容优先复用现有 Markdown 和目录结构，不复制文章正文。

- 分类入口使用固定的站内目录链接，确保链接长期稳定。
- 最近更新内容使用构建时可读取的 frontmatter 标题和日期；如果现有主题没有可复用的数据读取接口，则使用少量明确维护的首页入口数据，不引入运行时扫描复杂度。
- 页面文案保持中文、直接、可理解，不使用空泛的营销口号。

## 实施边界

预计修改范围：

- `docs/index.md`：首页内容和入口结构
- `docs/.vitepress/theme/`：首页专属样式或首页组件，如现有主题结构需要
- 必要时新增一个首页数据文件，避免把内容逻辑塞进主题全局代码

明确不修改：

- `docs/.vitepress/sidebar.js`
- 文章页布局和 Markdown 内容
- 搜索实现
- 全局主题切换逻辑
- 现有 footer、评论和统计功能

## 验证标准

1. `npm run build` 成功。
2. 首页桌面端符合 Quiet Library：浅色背景、蓝色强调、圆角面板、清晰入口、最近更新列表。
3. 首页移动端没有横向溢出，入口和最近更新都能正常点击。
4. 文章页、侧边栏、搜索、亮暗主题功能保持原有行为。
5. 首页没有虚构统计数据，也没有死链接。
