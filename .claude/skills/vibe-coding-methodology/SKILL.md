# Vibe Coding 方法论

> 规划就是一切。谨慎让 AI 自主规划，否则你的代码库会变成一团无法管理的乱麻。

## Iron Law

**先结构，后代码。** 在写任何代码之前，必须完成：目标定义 → 技术栈选型 → 实施计划 → 记忆库搭建。违反此顺序会导致技术债堆积和项目失控。

## 核心理念

### 道（哲学层）

- **目的主导**：开发过程中的一切动作围绕"目的"展开
- **上下文第一性**：垃圾进，垃圾出，上下文是 Vibe Coding 的第一性要素
- **系统性思考**：从实体、链接、功能/目的三个维度分析
- **数据与函数即是编程的一切**
- **输入，处理，输出**刻画整个过程

### 法（原则层）

- **一句话目标 + 非目标**：明确边界
- **正交性**：功能不要太重复
- **能抄不写**：不重复造轮子，先问 AI 有没有合适的仓库
- **按职责拆模块**
- **接口先行，实现后补**
- **一次只改一个模块**
- **文档即上下文**：不是事后补

### 术（技巧层）

- 明确写清：**能改什么，不能改什么**
- Debug 只给：**预期 vs 实际 + 最小复现**
- 测试可交给 AI，**断言人审**
- 代码一多就**切会话**

## 工作流程

### 步骤 1：游戏设计文档 ⚠️ REQUIRED

把你的创意交给 AI，生成一份简洁的设计文档 `game-design-document.md`。

**要求**：
- 初期可以很简陋，目标是给 AI 提供结构和意图的上下文
- 不要过度设计，后续会迭代
- 自己审阅并完善，确保与你的愿景一致

### 步骤 2：技术栈与配置 ⚠️ REQUIRED

让 AI 推荐最合适的技术栈，保存为 `tech-stack.md`。

**关键动作**：
1. 要求它提出**最简单但最健壮**的技术栈
2. 使用 `/init` 命令生成规则来引导 AI
3. **必须审查生成的规则**，确保强调模块化，禁止单体巨文件
4. 添加 "Always" 规则确保 AI 在生成代码前强制阅读关键文档

**Always 规则示例**：
```
# 重要提示：
# 写任何代码前必须完整阅读 memory-bank/@architecture.md
# 写任何代码前必须完整阅读 memory-bank/@game-design-document.md
# 每完成一个重大功能后，必须更新 memory-bank/@architecture.md
```

### 步骤 3：实施计划 ⚠️ REQUIRED

将设计文档和技术栈提供给 AI，生成详细的**实施计划** `implementation-plan.md`。

**要求**：
- 每一步要小而具体
- 每一步都必须包含验证正确性的测试
- **严禁包含代码**——只写清晰、具体的指令
- 先聚焦于**基础功能**，完整功能后面再加

### 步骤 4：记忆库搭建 ⚠️ REQUIRED

创建 `memory-bank/` 目录，放入：
- `game-design-document.md`（或 `requirements.md`）
- `tech-stack.md`
- `implementation-plan.md`
- `progress.md`（记录已完成步骤）
- `architecture.md`（记录每个文件的作用）

### 步骤 5：Vibe Coding 开发 ⚠️ REQUIRED

**确保一切清晰**：
```
阅读 /memory-bank 里所有文档，implementation-plan.md 是否完全清晰？
你有哪些问题需要我澄清？
```

**执行提示词模板**：
```
阅读 /memory-bank 所有文档，然后执行实施计划的第 N 步。
我会负责跑测试。在我验证测试通过前，不要开始第 N+1 步。
验证通过后，打开 progress.md 记录你做了什么，
再把新的架构洞察添加到 architecture.md 中。
```

**关键原则**：
- **永远**先用 "Ask" 模式或 "Plan Mode"（Claude Code 中按 `shift+tab`），确认满意后再让 AI 执行
- 每完成一步，更新 `progress.md` 和 `architecture.md`

## 元方法论（高级）

构建一个能够**自我优化**的 AI 系统：

### 1. 定义核心角色

- **α-提示词（生成器）**：唯一职责是**生成**其他提示词或技能
- **Ω-提示词（优化器）**：唯一职责是**优化**其他提示词或技能

### 2. 递归生命周期

1. **创生**：使用 AI 生成 α 和 Ω 的初始版本 (v1)
2. **自省与进化**：使用 Ω(v1) 优化 α(v1)，得到 α(v2)
3. **创造**：使用进化后的 α(v2) 生成所有目标提示词和技能
4. **循环与飞跃**：将新产物反馈给系统，再次优化，持续进化

## 反模式

- ❌ 跳过规划直接写代码
- ❌ 让 AI 自主规划而不审查
- ❌ 一次性生成整个项目（单体巨文件）
- ❌ 不更新文档和进度记录
- ❌ 使用第三梯队模型处理复杂任务
- ❌ 不做测试验证就进入下一步
